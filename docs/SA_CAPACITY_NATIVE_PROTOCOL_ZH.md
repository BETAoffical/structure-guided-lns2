# 历史复核后的容量标签原生判别

## 历史复核与继续的理由

- `STRIDE_TRANSACTIONALREPAIR_V1_REPORT.md`：受控顺序和补车有局部正信号，但不是TTF证据。
- `STRIDE_NATIVEORDER_TRANSACTIONALREPAIR_V1_RESULT.md`：补车相对原生同集合重排仅3.33个百分点，区间跨零，说明必须控制随机顺序，不能把重试收益归给补车。
- `STRIDE_COMPACT_BLOCKER_RESCUE_CONTINUATION_V1_RESULT.md` 及 `STRIDE_COMPACT_BLOCKER_ESCAPE_DURABILITY_V1_RESULT.md`：短期脱困改善，没有稳定的长期完成和开销收益。不能重复启动更长窗口或更多trial。
- `SA_CERTIFICATE_REPAIR_RESULTS_ZH.md`：特定单车降低局部冲突，但12个64步延续没有完成。
- `SA_CAPACITY_FOLLOWUP_RESULTS_ZH.md`：另156个补车/替换trial不稳定，随机也可能改善。
- `SA_CAPACITY_RELEASE_RESULTS_ZH.md`：新信息是扩大集合后的必要条件标签；定向动作56/140未再检出容量不足，随机0/140。正信号限于同源8状态，其他2地图来源未通过。

本轮只回答新问题：同大小、同状态、配对随机流下，容量未被否定的候选是否比被否定和随机候选更容易被冻结PP真正修复。不再次泛泛测试“加车是否有用”。容量标签是必要条件，不是可行性保证。

## 冻结选择

保留全部10个状态。按上一轮输入候选顺序，每状态选择原集合、原始第一名单车、首个通过/未通过必要条件的定向单车、首个随机单车、首个通过/未通过的定向两车及首个随机两车。缺失类别明确保留，不替换状态；相同实际集合去重并保留角色别名。

特别记录：八个正信号状态的原始第一名单车与过滤后第一名完全相同。因此本轮不能证明过滤改变了线上top-1，只能验证必要条件标签能否区分原生结果。没有读取新的PP结果来选择候选或agent编号。

每动作4个trial，复用既有显式修复器g.probe、case/20260915/trial随机种子、来源温度与接受随机流，PP每trial5秒、作业fuse180秒、最多20独立进程。初始路径、外部路径、原生SHA、接受规则和完整路径逐条验证。不同成员集合虽种子配对，实际PP顺序并不相同。

镜像reset_paths是单步路径状态诊断，不冒充整个历史策略prefix重放；本轮不运行后续策略，不测试TTF、训练或改正式控制器。结果独立保存，运行锁/receipt/原子manifest/resume，执行前提交与备份。

## 指标与停止条件

完整报告全局剩余冲突、零冲突、回滚、PP截断、节点开销及逐trial结果。PP正常完成与MAPF零冲突严格分开；角色别名不能重复当样本。

只有至少两个状态存在同大小的通过标签候选，四trial完整、至少2/4优于原集合，且平均剩余冲突严格低于原集合、未通过标签候选和随机候选，才允许讨论下一轮有界延续。节点代价独立报告，不以并行时间宣称加速。

不通过则停止此规则的PP扩展，分析必要条件不充分、PP未找到兼容路径或接受回滚；不自动调温、补更多车、重训或跑64步。通过也只是机制准入，相关8状态不能变成独立泛化证据。
