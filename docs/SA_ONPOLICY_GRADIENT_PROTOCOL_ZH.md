# 首次on-policy更新的梯度诊断

2026-09-22。承接[首次更新结果](SA_ONPOLICY_RESOURCE_RECOVERY_RESULT_ZH.md)。只读现有96条Train轨迹，
不调用求解器、不生成标签、不更新模型、不访问留出集、不扫学习率、不测TTF。
这不是新一轮H32/一步排序，而是检验当前完整轨迹策略梯度能否提供有意义的训练方向。

## 固定问题

1. 由同条件重复回报及动作score重建的梯度，能否精确复现已保存SGD参数变化？
2. 3个有成败差异的条件彼此支持还是抵消？逐条件留一后，方向与被留出条件是否相同？
3. 4个replica全部三种2+2拆分的方向是否一致？零梯度半组必须记为不可判断，不能当作相反。
4. 早中晚阶段对实际梯度的贡献、输出层可见的候选差异及Fisher trace怎样？
5. 小步更新允许的概率变化上界是否本来就很小？这只是干预量，不等于收益。

在actor-0的输出层严格为零时，`grad_w2 log(pi)=2*(h_selected-E_pi[h])`。
该恒等式仅用于读日志诊断，必须与PyTorch autograd及实际保存的更新吻合；不是手写新优化器。
第一层及输出bias在此点的梯度应为零。非零输出模型不能复用这一简式。

保持完整轨迹的score求和及原map/condition等权；不按轨迹长度除权。
拆分时使用各自的同条件基线，不共享另一半回报。报告全部拆分，不挑最好的一半。
组/阶段方向均为事后Train诊断，不是独立成功率评价，不能据此选择对照子集或宣称泛化。

## 执行与解释

- `scripts/audit_sa_onpolicy_gradient.py prepare`封存代码、协议、模型、源审计及结果SHA。
- `analyze`最多20个独立NumPy进程读取轨迹和计算充分统计量，主进程用现有PyTorch核对梯度。
- 输出为`build/sa-onpolicy-gradient-audit-v1b`，生成文件不入Git；原模型和轨迹保持不变。
- 任何SHA、行为概率、Train边界、组完整性或梯度重建错误立即停止，不发布有效分析。
- 不把单个方向余弦当晋级门槛，也不从仅3个信息条件制造精确置信区间。

若方向不一致，应先承认当前完成回报估计噪声/覆盖不足，不直接放大学习率。
若方向稳定而更新很小，只能支持另立有界训练强度方案，不能直接宣布更大步长会成功。
归一化风险单列；没有因果消融前，不同时改表示、奖励、候选和训练方式。
