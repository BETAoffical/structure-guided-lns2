## 找到的规律

### 1. 精确条件适合识别重复，却不适合累积成功偏好

当前条件键包含：实例、选中车辆起终点、所有外部车辆路径、旧受影响冲突对数以及预算。
设外部车辆之间的冲突对数为 E，涉及选中车辆的旧冲突对数为 B，总冲突 C=E+B。
在同一个精确条件键下，外部路径固定，所以 E 固定；键中又固定 B，故 C 固定。
某次严格下降后，InitLNS的接受规则保证后续 C 不增加，因此该成功之前的精确条件不可能再次出现。
这个推论限于当前条件定义、准确冲突统计和单调接受语义，不是所有MAPF反馈方法的结论。

实测相符：两轮反馈策略共103次触发，候选池中有可复用正反馈的槽位为0；102/103次选择的是本轨迹未试过的新条件。
触发时1932个候选槽位中1818个没有观测，约94.1%。当前Beta抽样主要是负反馈加未知条件探索，不能称为已学到长期动作价值。
因此不能通过增加同一精确键的正反馈次数解决问题，更不能直接把成功计数跨不同外部约束混用。

### 2. 13号不是已证明的不可修复状态

反馈trial2在第8、9、19次修复后形成3→2→1→0；trial3在第3、9、11次修复后形成3→2→1→0。
两条成功轨迹的规则、大小和具体集合并不相同，不能将单个成功模板硬编码成新控制器。
与历史“40→39后持续停滞”的负面结果不同，这次确实获得完整可行解。但随机探索同样2/4，所以还没有结构化反馈的增量证据。

### 3. 探索的损害仍然存在

22号随机trial0中，冻结策略第14步清零而随机分支32步未清零；反馈trial2中，冻结策略第18步清零而反馈分支未清零。
反过来，两种探索也各恢复了一个原来不清零的配对trial。不能只看总数相同而忽略损害。
“多次不下降就应该换候选”仍不足以区分有益重试与错误停滞，这与历史ProductivityGuard的误触发问题一致。
当前结果不能确定损害完全来自第一次分歧、后续路径占用或PP随机性，不能据此直接部署硬禁忌/回滚所有等冲突动作。

## 第二轮：失败后的新条件检查

不重新测已有初始H1条件，也不在失败后调策略参数。
按固定顺序选择两个失败后继状态，37个新条件各4trial，共148分支：

- 13号后继剩2冲突，19候选共76分支：14次降至1，62次仍为2，没有一步清零。其中一个候选4/4降至1；它尚未经后续清零验证，不能作为新救援策略。
- 22号后继剩1冲突，18候选共72分支：仅2次清零，来自两个不同候选，各1/4；其余70次不下降。

不能将2/72解释成所有可能邻域的总体成功概率：这里只覆盖固定生成器在该状态的未测条件。
这些结果支持“选择覆盖、后继路径条件与随机repair机会共同影响尾部”，没有证明需要修改官方PP或扩大所有邻域。

## 是否重复历史错误

- 保留同触发、同候选池的uniform对照，避免把简单探索收益包装成Bandit贡献。
- 不使用永久tabu；保留候选重试机会，避免旧停滞触发器损害有益路径调整。
- 用32步清零而非单步下降作为主判断，避免重复稳定候选40→39的误解释。
- 不追加GCBS、CBS、外部车辆闭包或RL；这些方法的历史负面结果没有被本次小样本推翻。
- 第三轮不调参数，保持地图隔离；没有因为第一轮新增恢复而自动开启计时实验。
