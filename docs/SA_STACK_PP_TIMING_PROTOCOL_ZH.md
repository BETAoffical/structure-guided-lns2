# 栈邻接枚举：有限 PP 配对计时

## 边界

冻结参考 native 与 `sa-stack-neighbors-probe-v1` native；仅后者的 SIPPS 四邻接临时链表被栈枚举替代。保留方向顺序、重复邻居、随机数、模型、候选与 SA 接受逻辑。默认控制器不变。先决条件为既有 792 步完整回放一致，登记报告 SHA `1bd8c0109f8dac067900a76834393700656766b925513b7ebf6e0832ea7f6275`。

本轮不是完整 TTF：包含离线前缀校验与冻结动作回放，不以整个进程时长或累计回放时间表示求解器速度。先前邻接查询约 70.5% 的降幅不等于 PP 加速。

## 固定执行

- 复用 m01/m03/m05/m07 的低、高负载共 8 个案例，不选择性替换。
- 两次重复，每个案例每次依次运行两个独立进程；顺序按案例与重复奇偶反转，总计 32 作业，单 worker。
- 每次独立 reset，完整回放已登记前缀，重新生成并核验候选/分数/动作。每一步核验完整状态 fingerprint、PP 顺序、结果及搜索计数。
- 每个版本每次共 792 次 PP。两重复形成 1,584 个配对调用；全部版本共 3,168 次修复。
- 首/中/末状态按 `0, floor((n-1)/2), n-1` 固定抽取，共 48 个配对样本，仅作阶段诊断。既然必须完整回放，主分析使用全部 PP，避免极少采样调用造成偏差。
- 主指标为 `native_replan_seconds` 累计值。另报 `env.step_experimental_pp` 外层调用时长，二者嵌套，不相加。reset、候选生成、Python 结果转换和回放校验不计入主指标。
- 不改变单次 PP 的 300 秒上限；环境预算 3,000 秒仅避免回放校验消耗求解预算。独立作业硬超时 300 秒，异常或不一致立即停组，不自动重试。
- 支持完成当前作业后安全停止。原子结果和 SHA manifest 支持续跑已完整成功的作业，遗留开始标记/失败结果必须人工检查。不得为了改善结果追加第三次重复。

## 预设门槛

主 PP 累计时间至少下降 5%；8 个案例至少 6 个下降；按地图配对重采样 5,000 次（seed 20260913）的降幅 95% 区间下界不小于 0；所有语义核验通过。四张历史地图只提供开发证据，不声明独立泛化。

通过仅允许另行设计端到端确认，不在本命令中自动启动 TTF、修改默认 native 或重训。未通过保留局部优化证据，本轮停止扩测，不调整门槛。

## 命令与保存

`scripts/time_sa_stack_pp.py register|verify|collect|resume|stop|analyze`。

先本地 Git 标签及 ZIP 备份，提交代码与本协议，再登记输入 SHA 并运行测试。所有原始计时、注册和 manifest 保存于忽略目录 `build/sa-stack-pp-timing-v1`。本轮不推送。
