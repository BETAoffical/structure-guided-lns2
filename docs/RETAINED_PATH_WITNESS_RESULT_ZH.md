# 保留路径见证审计：任务可解，但未找到廉价外车协调证据

## 本轮问题与结论

上一轮三个困难状态的 2,708 个单外车软 CAT 释放分支均回滚。本轮不再搜索，而是检查已有路径：相同任务是否有合法解，能否把少量已有成功路径移植到失败状态，以及历史局部成功是否真的改变了外部车辆。

结论是：三个任务均有同任务、同 solver seed、相同初始完整 fingerprint 的 Official 首次可行路径；但在这一个固定参考解构成的路径库中，没有找到最多 16 辆实际改路的小规模拼接见证。历史中的一个两车局部成功仍成立，但没有外车改路，也没有证明长尾恢复。

本轮只有离线存在性诊断，不是新修复器成功率、计时实验或上线门槛。Official、V2、Dual16、native 和模型均未修改。

## 方法与冻结

- 运行前提交并推送 `531fc90a0085e97125582639a3d6f772c9bb7344`。
- 安全标签 `pre-retained-path-witness-20260910` 指向 `40599c4ffb164ed0f5a0ebec8a740ae49da9af1e`。
- 参考固定为每个任务 Official 的 120 秒 fixed-budget episode 中保存的 `first_feasible.json`，不是第二阶段优化后的路径，也没有按拼接结果更换参考。
- 完整验证任务、地图、起终点、agent ID、solver seed、native、初始状态与路径文件身份。
- 设旧路径为 p、参考路径为 q。如果 q_i 与 p_j 冲突，采用 q_i 就必须连带采用 q_j。由每个原冲突端点分别计算传递闭包。
- 参考路径之间无冲突；逐项重算拼接后的全部顶点、交换和终点持续占用冲突。实际改路数排除 p_i 与 q_i 完全相同的车辆。
- 使用 20 个进程完成 1,401 条依赖行和 77 个根闭包；新增求解搜索次数为 0。三份最终拼接路径另交冻结 native 的 `reset_paths` 校验，没有执行 PP 修复。

**不能解释成“至少要改动四百辆车才能求解”。** 这里每辆车只能选旧路径或这一个参考解的路径，闭包的必要性仅在该固定二选一路径库内成立。其他尚未找到的局部路径可能只需要少量车辆。大量依赖也可能来自两套完整时序差异，不等于物理瓶颈规模。

**不能把最后零冲突算成我们的新算法成功。** 参考完整解已由 Official 求得，本轮只是借用它检验路径兼容性，没有在线找到这些路径。

## 历史成功重新归属

读取并核验了同状态的全部 12 个旧局部方法作业，包含失败与未知，不只保留成功。

1. `case-3723c8bd272e` 的车对 `(19,364)`：旧 Python 定向路径重选保存了两个合法见证，均只改变这两辆车，且两车都在原 16 车邻域内。全局冲突均为 40→39，只消除 `(19,364)`；不是外车释放成功，也不是完整可行解。此前 native 定向机制未复现该参考机会，不能混称 native 修复成功。
2. 同状态的 `(62,157)`：普通、随机、定向未找到；旧两车联合参考搜索记录固定外部路径下不可行。结论只针对那个硬外部约束子问题，不是整个 MAPF 任务不可解。
3. `case-7ee343a50388` 的 `(35,201)`：没有保存成功路径；随机与 CBS 分支为预算未知，不能写成无解。`full-f062ea7307d7d84b` 不在那组旧局部两车研究中，不能当作已测试失败。

另复核两条容易误读的历史记录：

- case-7ee 第 992 步结束了连续 602 次不变状态，实际改变 `[4,35,162]` 的路径，但冲突仍为 1→1，冲突边没有消失，整条轨迹最终也没有可行。这只是换路，不是脱困。
- 另一项已完成的四车首步延续试验，在 case-3723 消除的是 `(222,245)`，8/8 从 40 降到 39，随后 63 步仍为 39，0/8 可行。这不是对 `(19,364)` 见证的延续测试；只能提示不能用一步下降代替长期恢复证据。

## 下一步边界

到这里应结束“单外车软释放”和“借用一个已有完整解做廉价局部拼接”两条分支，不自动增加外车数量、闭包上限、CBS 预算或随机 trials，不重训排序器，不进入 RL 或正式 TTF。

仍未解决的问题是：在当前困难路径状态中，是否存在能由有界方法找到的少量车辆联合重选机会。任务本身可解与这种局部机会存在不是一回事。

继续实施前，应先提出与已有负面方法不同的联合路径协调机制，说明它放开了哪个已确认的限制，以及预期能在哪个同状态见证上新增恢复。若拿不出这样的可检验差别，就先收束本轮失败证据，不重复已有搜索。任何未来成功仍须区分局部冲突下降、持续进展和最终成功率/TTF，不能跳过延续验证。
