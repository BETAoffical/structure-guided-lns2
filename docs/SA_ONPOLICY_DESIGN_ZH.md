# 新模型设计：用自身连续决策结果学习，不再混合旧续跑标签

2026-09-22。状态：**设计与数据合同检查完成，尚未实现采集器/优化器，未训练、未调用求解器、未计时。**
这是一个待实施的小规模on-policy RL原型，不是新一轮监督GBDT，也不是已有收益或正式准入。
保留Dual16+SA、V2、Official及全部历史失败结果，不修改PP/SIPPS、SA或候选生成。

## 1. 新假设与历史排重

假设：在同一候选池和基本输入下，让策略直接从自身完整轨迹的完成结果更新，
是否比“预测换一个首动作、然后由旧策略续跑的价值”更适合持续接管？
这是可检验的新训练方式，不是已经找到长尾原因；它不能解决候选不足、标签稀疏或PP路径协调的全部问题。

| 已有尝试 | 已有结论 | 本轮不可重复的部分 |
|---|---|---|
| [H32持续接管](SA_PAIRED_CLOSED_LOOP_RESULT_ZH.md) | 新模型15/32，冻结20/32 | 不能凭离线分数直接接管 |
| [两旧策略续跑混合](SA_POLICY_ALIGNED_UPDATE_RESULT_ZH.md) | 新模型0/8，冻结2/8；样本内拟合已很好 | 不再平均两个旧策略的标签再拟合 |
| [晚期独立trial](SA_LATE_STATE_SIGNAL_RESULT_ZH.md) | 25/48对24/48，随机期望24.75/48 | 不再声称补晚期状态本身就是答案 |
| [同来源聚合](SA_MATCHED_AGGREGATION_RESULT_ZH.md) | 局部提升，旧四候选退化 | 不再扫样本权重寻找有利结果 |
| 容量、线性、时空、历史、干预频率 | 见[证据总账](RESEARCH_EVIDENCE_STATUS_ZH.md) | 不以更大网络、加入温度或少干预换名重来 |

代码复核发现：`features_for()`的127维动态输入已经含`sa.log_temperature`、`sa.log_decision`，
后来的预算对齐模型已有两个剩余预算特征。不能宣称本设计首次考虑SA/预算。
本轮固定129维，不同时加入新历史窗口、地图类别、OD、密度或新图网络。
历史顺序增量仍未证明；复用已有信息能隔离训练方式，但也可能受相同表示瓶颈限制。

## 2. 候选与模型

- 使用当前Dual16完整显式候选池，不只抽取历史四候选，不新增邻域成员或改变代表选择。
- 每步由冻结Dual16得到anchor。以`q(a)=0.9*I(a=anchor)+0.1/K`定义固定探索对照。
- 共享小网络`129 -> 32(tanh) -> 1`为每个候选输出`r=2*tanh(output)`。
- 策略为`pi(a|s) proportional to q(a)*exp(r(s,a))`，不是两两胜率累加，也不预测剩余轮数。
- 最后一层初始化为零，初始策略严格等于不训练的探索对照，**不等于确定性Dual16**。
- 归一化只用Train初始状态的动作前输入确定并冻结；后期越界只报告，不临时改尺度。
- 训练与评价都按相同分布采样，不在评价时突然改为argmax；随机流与PP、SA分离。
- 残差有界限制单步偏离，但不保证长轨迹安全、不保证成功率、不构成回退机制。

这不是声称MLP优于GBDT。模型小、固定是为了检验更新合同，旧MLP/GNN负面结论仍保留。
下一阶段若实现训练，使用已有PyTorch的Categorical/autograd，不自行实现自动微分，不安装新依赖。
现有原生环境在WSL，现有图训练环境在Windows；CPU采集与训练通过冻结快照交换。
实际启动前必须核验环境、导出器和跨平台预测一致性，当前尚未完成这些接口。

## 3. 训练目标与完整轨迹合同

每个batch从reset开始，由同一策略版本连续行动到首次可行或固定工作预算结束。
成功终止得1，决策/节点预算用尽但未完成得0；不加一步下降、节点节省或剩余轮数奖励，discount=1。
节点预算在两次完整修复之间检查，不能把它描述成SIPPS内部硬中断；最终修复可能越界，必须记录。
墙钟保护、PP不完整、外部超时、用户中止是未知，不填0，不静默删除；整批暂停更新并审计。

每个任务、初始solver seed收集4个独立replica。每条轨迹的baseline取其余三个replica完成率。
baseline不能使用该轨迹自己的结果或某个候选的事后oracle。不同replica的策略、PP、SA流独立；
不同对照方法可配对同一个replica流，但不能把这些对照混进学习batch。

更新方向使用`(return-baseline) * sum_t grad(log pi(a_t|s_t))`，先对episode等权，再对任务和地图等权。
**不除以每条轨迹步数**，不把长轨迹当更多独立样本；零冲突任务保留，动作和梯度项为零。
重新计算带梯度的log probability，并与采集记录核对。每批只做一次SGD更新，之后必须重新采样。
旧H32/反事实数据只能用于输入检查和背景分析，不能伪装成当前策略数据反复训练。
当前版本、候选身份、全部行为概率、选中动作及归一化/schema/native身份必须登记。

这是标准episodic policy-gradient思路，不是本项目发明；其数据必须来自当前策略，loss下降不等于性能提高。
依据：[策略梯度推导](https://spinningup.openai.com/en/latest/spinningup/rl_intro3.html)、
[VPG说明](https://spinningup.openai.com/en/latest/algorithms/vpg.html)。这里只借鉴完整轨迹估计，未实现其critic/GAE。

## 4. 有界试验草案，不在本轮启动

复用预算对齐实验既定6张Train、2张已查看开发留出图，两个任务、solver seeds227/229。
24个Train条件、8个留出条件，不按冲突结果筛选。该留出集不是独立确认集，不再赋予其正式验证身份。
完整MAPF文件及模型身份尚需新执行清单冻结，不能仅因历史plan哈希正确就认为已可运行。

| 项目 | 固定草案 |
|---|---|
| 优化器 | SGD，learning rate0.001，gradient norm clip1，一批一次更新 |
| 最大更新 | 2次；最后快照评价，不看留出结果挑checkpoint |
| 每批训练 | 24条件乘4replica，共96条；两批最多192条 |
| 评价 | 8条件乘2replica乘4方法，共64条 |
| 方法 | Official+SA、Dual16+SA、不训练的固定探索、训练后的策略 |
| 工作预算 | 每条最多256次修复、2500万修复generated nodes；不声称TTF |
| 安全限制 | PP20秒、episode300秒、进程fuse360秒；触发保留未知 |
| 并行 | 最多20个独立进程，每batch策略冻结；不边收集边改权重 |

合计最多256条episode、65,536次修复，另有初始化和准入检查。
四个方法必须在该预算下重新配对运行，不拿历史128步或512步结果直接作为本轮对照。
这是修复次数上界，不是耗时预测；本轮实际均为0。小型模型拟合通常不是主要费用，原生采集才是。
若一批所有条件的replica回报都相同，记录“本批没有更新信号”并停止，不自动加入密集奖励。
不能由这个小预算原型失败断言所有on-policy学习无效，也不因失败自动增加更新数、换seed或调参数。

## 5. 不要求每图全胜，但必须区分探索与学习

- 首先与不训练的同分布探索对照比较，再与Dual16+SA、Official+SA比较。
- 报告各方法成功、预算用尽、保护截断数量；未知单列，并给出成功差的上下界。
- 共同成功集合报告总修复、节点、SOC、makespan；失败不能填成零工作，节点不称TTF。
- 原型只允许“有进一步独立确认价值”的开发结论，不自动替换生产模型。
- 已知完整结果下，新策略相对固定探索和Dual16+SA均净增加完成，且共同成功节点不增加超过10%，
  才考虑独立地图确认。10%是提前声明的工程取舍，不是统计定理；无共同成功或存在删失则证据不足。
- 不要求每张图都更好，也不在两图小样本上要求bootstrap下界为正。报告原始配对与区间，允许不确定结论。
- 若只有探索对照提高，成果属于探索而不是训练；若只在Train提高，记录过拟合；若更高完成但更多工作，公开取舍。
- 正式成功率/TTF收益必须另做独立地图、单worker配对确认，不能从并行工作预算试验推导。

## 6. 本轮交付与尚缺内容

`experiments/sa_onpolicy_contract.py`只实现概率分布与训练批合同，不创建网络、不更新权重、不调用native。
`gradient_coefficients()`仅校验声明的元数据和概率一致性，不能代替路径合法性、实际行为概率重算、随机流独立性或特征泄漏审计。
只读入口：`python scripts/check_sa_onpolicy_contract.py --check`。
它核对5个设计输入、既有地图划分和预算算术，不验证所有历史trace；输出固定为`design_checked_not_execution_ready`。

下一步若决定实施，顺序固定为：补完整episode采集/快照推理接口；微型地图验证真实随机流与恢复；
冻结任务/schema/模型/native/代码及执行授权；运行最多两次有界更新；最后一次开发留出评价。
当前没有collect/train入口，配置明确禁止采集和训练。不能把本文件当作已经开跑的RL或性能结果。
