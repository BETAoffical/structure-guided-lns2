# 压缩集合的原生PP结果：12车保留局部效果，11车退化

## 结论

原16车历史动作复现成功，完整修复后fingerprint和PP顺序与原trace一致。随后24次新修复全部完成，无非法动作、重放不一致、超时或回滚。

预登记结果为`no_go`：12车仅1/8次达到不超过34对冲突，11车0/8，均未达到6/8门槛。不降低门槛、不追加种子、不扩采或自动进行闭环。

同时，不能把结果说成压缩完全无效。三个集合都8/8严格降低冲突；12车相对16车七次相同、一次少一对冲突，生成节点也更少。它是一个有局部信号、未通过更强见证复现门槛的事后机制结果。

## 11车为什么退化

12车与11车仅差agent235。但“删掉一个重规划对象”会把该车辆的旧路径变成整个PP期间的固定外部约束，同时改变搜索调用和后续随机消耗；不能理解成从16车成功结果中机械删掉一条已知路径。

对每个实际12车结果再作只读路径检查：保持其他新路径不变，仅将235恢复为旧路径，冲突数依次为：

`[35,35,37,36,35,35,35,35]`

而真正运行11车PP得到：

`[38,38,37,38,38,37,38,38]`

除trial2外，真正重规划都比这种事后路径拼接留下更多冲突。新搜索改变了其他车辆的路线选择，不是单纯恢复235旧路径的结果。

七个trial中，11车相对12车结果保留/新增了围绕335的四条冲突边：`(11,335)、(65,335)、(115,335)、(335,426)`。在trial0、1、4、6、7中，12车顺序里335位于235之前；12车PP能先移除235的旧路径约束，再联合安排两者，而11车始终把235旧路径当作外部占用。固定12车其他新路径、仅恢复235旧路径，会出现`(235,335)`，同时移除`(103,235)`。

这些路径证据说明235相关占用与335的路线选择有联系。它们不能证明所有差异都只由一个格子或某个单一随机事件引起；本轮没有逐次低层搜索消融。

## 对前一轮路径消融的修正

前一轮“11条已知新路径可以维持34对冲突”是正确的有限路径组合事实，但不能推出“只选这11辆，PP就能找到同样效果”。本轮实际检验了这一步，结果不支持该推论。

因此至少要区分：

- 在某组已知新路径中，需要保留哪些路径变化；
- 为使PP找到兼容路径，哪些车辆必须作为可调整对象；
- 得到的一步进展能否在闭环中减少长尾和TTF。

12车保留了235，并在本轮保持接近16车的一步效果，值得保存为机制线索。但集合来自成功见证的事后消融，尚无输入可见的通用生成规则，更没有独立新状态或闭环收益。

## 下一步边界

本轮按预登记停止。不部署固定11/12车策略，不重新训练、不修改Official/V2/Dual16，不追加同一状态的trials或TTF实验。

若后续继续，应先研究从当前路径占用识别“必须允许移动”的协同车辆，而不是直接预测最终应该变化的路径集合。任何新规则都需要在未用于挑选该规则的状态中验证；不得硬编码235/335，不把成功后的路径作为在线输入，不重新采用已失败的全量blocker扩张。当前仍没有可上线的长尾修复方案。
