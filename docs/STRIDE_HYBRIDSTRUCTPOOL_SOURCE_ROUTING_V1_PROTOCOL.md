# STRIDE HybridStructPool source-routing v1 protocol

This development experiment isolates the runtime value and cost of the two
frozen HybridStructPool challenger sources. It does not retrain a selector,
change V2 features, prefer small neighborhoods, or alter the complete offline
HybridStructPool audit contract.

The five strictly paired arms are frozen V2, V2 plus the complete StructShell,
V2 plus CausalClosure, the exact full V8 runtime, and a routed StructShell arm.
The first four use the existing high-stress gate. The routed arm removes total
agent count as a sufficient stress condition and requires at least 16 conflict
pairs plus either 32 active conflict agents or a conflict component of size 16.

Before any timed episode, the 78-state zero-solver audit must prove that every
source mask preserves the complete V2 pool and includes exactly the registered
source memberships. It may not call PP or a solver.

The eight development keys are run in rotating, strict five-controller serial
order. All arms use the frozen V2 124-feature rows, Copeland selector, native
PP, episode-stream repair seeds, and reset-inclusive raw-TTF clock. Candidate
generation, StructShell generation, CausalClosure generation, feature,
inference, selected provenance, selected size, PP and raw TTF are recorded.

A challenger is eligible only with 8/8 success, raw TTF strictly below V2,
paired faster fraction at least 0.5, no Maze or Room regression above 5%, no
repair-count increase, and complete integrity. Among eligible arms, raw TTF is
primary; arms within 1% use worst-group regression and then selection time as
tie breakers.

Passing remains outcome-enriched development evidence. It authorizes only a
separately preregistered result-blind 60-key confirmation. Failure stops Hybrid
runtime tuning and keeps V2 as the runtime default.
