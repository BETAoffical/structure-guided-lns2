# 脱困候选来源核验：没有选到seed，还是生成后丢弃？

## 本轮范围

沿用上一轮固定六条轨迹，检查其中存在长停滞退出事件的三个案例：两个最终成功，一个最终失败。不重新选择有利案例，不尝试新的修复动作，不训练、不修改控制器，也不进行TTF计时比较。

三个进程各重放一次已登记前缀，共472次历史修复，完整fingerprint与实际PP顺序均核对。停滞段的路径状态保持不变，只根据各历史decision的完整fingerprint、seed agents和proposal随机种子重建生成器请求，不再次运行停滞段的PP。共重建1603个proposal批次、258624个原始proposal请求；未对任何新候选执行PP。

注意：这不是完全不调用求解器的只读解码，包含reset和历史前缀重放，但源文件只读，生产代码及正式结果不变。前缀重放不算新增研究样本。

## 结果

| 案例 | 退出步骤/集合 | 来源seed此前覆盖 | 此前原始proposal命中该集合 | 此前生成后被筛掉 | 历史后续 |
|---|---|---|---:|---:|---|
| V2 长尾后成功 | 829，Collision-8 | agent254：806/806轮 | 0 | 0 | 1对仍1对，随后第834步可行 |
| V2 最终失败 | 992，Random-4 | agent35：602/602轮 | 0 | 0 | 路径改变，最终仍1对 |
| Dual16 长尾后成功 | 254，Random-16 | agent115：192/192轮 | 0 | 0 | 42对降至34对，随后可行 |

每个具体集合第一次在本次核查停滞窗口的原始proposal中出现，恰好就是历史上被选中并退出停滞的那一步。每个集合当轮均只有一个原始生成请求支持；两个成功案例占据所在规则/大小族的第一个代表位置，失败对照占第二个代表位置。

“此前”仅指已经冻结的最长路径不变段，不是整条episode或全部历史。未重复成功见证的PP修复，表中效果读取历史trace，不是新的稳定性试验。

## 代码流程解释

1. 选择最多四个冲突seed：优先高冲突度和高delay，不足时确定性补齐。本轮三个见证对应seed每轮均已覆盖，不支持把原因归于漏选seed。
2. 每个seed使用Target、Collision、Random及4/8/16大小，每组合八个proposal随机种子。随机种子含task、solver seed、完整状态fingerprint和decision index，所以路径不变不等于每轮产生同一批候选。
3. Collision先包含或游走当前冲突分量；分量不足时，通过路径表上的时空随机游走加入车辆。Random包含指定seed后，使用当前实现的冲突度相关累计权重抽样补足。因此，它们不是穷举全部车辆组合。
4. 每个规则/大小族选两个代表。第一个优先出现次数，平局按candidate ID；第二个优先与已有代表的Jaccard距离，再按出现次数与ID。这里没有另一个GBDT，也没有读取真实修复效果。
5. 冻结GBDT才对保留的具体集合评分。两个成功退出集合出现当轮已经被选中，不能说GBDT在这些更早的相同路径窗口中忽略了它们，因为它们此前根本未进入原始proposal。

实现对应`experiments/repair_collection.py`、`experiments/neighborhood_candidates.py`、`lns2_selector/runtime/online_selection.py`及冻结native对应的`InitLNS.cpp`。本轮未更改这些实现；不把当前接口扩展混称为未经修改的上游源码。

## 能证明什么，不能证明什么

**能排除的窄解释：**对这三个具体见证，在核查窗口内不是seed未覆盖，不是生成后代表筛选丢弃，也不是出现后GBDT没选中。

**仍不能证明：**现有候选池没有其他好动作、GBDT整体没有选择问题、扩大随机proposal会提速、这三个完整集合的再次生成概率低于应有水平。组合空间很大，一个特定集合很晚出现并不自动构成算法缺陷；其他等效有效集合的数量和效果未知。

V2成功8车集合中六辆当时冲突度为0；Dual16成功16车集合中也有六辆冲突度为0。失败对照的4车集合也有三辆冲突度为0。因此“包含当前无冲突车辆”不是成功判据，也不说明这些附加车辆全部必要。具体路径占用是否使它们成为关键协同对象，仍需单独验证。

## 下一步边界

不修改seed优先级、不取消代表筛选、不增加八次proposal试次数，不以本轮结果重训或启用RL。单纯恢复特定成功集合也是事后见证，不能作为通用控制器。

若继续，唯一值得优先考虑的机制问题是：成功集合中哪些车辆及其时空占用真正影响修复，能否从当前输入构造小而有用的协同集合。先区分必需的路径协调对象和随机附带车辆，并保留失败对照；只有存在可由输入解释的规律，才设计有界生成器及新的配对修复验证。不得重新采用已有未通过的全量blocker闭包，或硬编码这些成功集合。
