# 九个SA拒绝事件：单决定分支探针

## 问题与边界

判断当前SA实际拒绝的9次较差尝试，拒绝决定在有限后续搜索中是否有保护作用。
使用已审计的全部9个事件、5条旧轨迹、4张地图，不按结果删换，不宣称独立泛化。
不修改正式模型/native/控制器，不训练，不计时TTF，不扫描温度。

## 执行

- `keep_rejection`：完整重放prefix，再复现原接受随机数，确认当前尝试被拒绝。
- `accept_once`：同一prefix、模型候选、PP顺序与温度，仅本次uniform改为0。9个事件的原接受概率均严格为正，因此只改变该次接受决定。
- 两支都核对PP尝试成员、顺序、尝试/插入数量、碰撞计数和低层节点与旧记录一致。拒绝支完整状态必须与原记录一致。
- 原记录未保存被拒绝的完整新路径；接受支保存新路径见证并做完整路径/冲突验证，不从旧记录离线伪造。
- 后续恢复原冻结模型及 `1000*0.99^decision`，继续原decision编号与接受seed，不重新升温。两支访问状态不同后，候选自然可以不同。
- 每支最多64次后续修复；后续generated节点软上限500万，在两步之间检查并报告单步越界量。
- 后续安全墙钟120秒，单次PP最多30秒；这些是多进程下的资源保护，不是比较指标。
- prefix与目标重放使用每次PP300秒保护，环境3000秒，总进程fuse900秒，包含重放与事后验证。
- 资源截断记为有限预算未知；64步未成功仅表示该窗口内未可行，不称无解。
- 最多20worker，共18分支作业，实际最多18并发。另先执行第一个拒绝事件的两条2步smoke，不混入正式诊断结果。

## 验收与分析

- 两条smoke通过且成对根状态、PP尝试一致才运行18分支。
- 逐结果原子保存、run lock、防止重复采集；已有错误不能自动重试。stop禁止尚未开始的作业，已运行作业完成本次有界分支后退出；resume复用已完成结果。
- 所有分支完整性检查通过；不允许因失败删除事件。
- 首先比较可行性、观察窗口是否完整，然后比较后续冲突和generated节点；不把多worker墙钟当作TTF，不合并重叠事件为独立地图样本。
- 拒绝新增成功而接受不成功：保留拒绝的保护信号；接受新增成功而拒绝不成功：保留错失机会信号。
- 双方成功时比较累计工作，完整窗口双方不成功只报告有限状态差异；资源截断不强行判胜。
- 混合结果不派生阈值、不追加温度档位或RL。只有得到清晰机制证据后才另行讨论新对照。

## 交付

`scripts/probe_sa_rejection_branches.py prepare|verify|smoke|collect|resume|stop`

输出 `build/sa-rejection-branch-probe-v1`，代码/协议先本地提交并备份；保留原9事件来源SHA、原模型和native身份。
