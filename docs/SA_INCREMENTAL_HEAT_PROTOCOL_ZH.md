# SA 增量路径热度独立工程验证

## 改动范围

只替换独立 selector 的 TopologyAnalysisCache 私有绑定；选择器 code object、native、模型、候选、评分、fingerprint 和 PP 不变。

每次从缓存实际保存的 paths 与当前状态比较，计算精确 changed agents，不依赖上一次请求的邻域。不接受外部提示，agent 身份或地图变化报错。复用已有 `_update_heat`，继续运行 native 状态/冲突分析，并保留每20次更新的完整 shadow 校验。

## 验证与资源

- 单测覆盖 Python/native、非连续ID、重复ID、接受路径、未变化路径、回滚旧路径、路径增长/等待、跨状态变化、调用方突变、错误变化提示和热度损坏。
- 同一8条历史轨迹共792个修复前状态，新旧拓扑、heat、特征、候选、分数和动作必须一致，重放后的完整fingerprint与历史一致。
- 上轮24个点用于定位，本轮对全部792次选择做一次配对组件计时，因为只测稀疏点可能遗漏每20步的shadow成本。无额外重复访问，无自由rollout或新任务。
- 新旧调用顺序按案例及决策索引交替；包含变化集合识别、shadow和全部选择器工作。输入deepcopy、配对检查和保存位于组件计时外。
- 固定单worker，每案例600秒进程fuse，重放单PP安全上限300秒。不是新TTF比较，不使用重放总耗时证明加速。
- 每案例原子保存、运行锁、完成当前案例后暂停、resume。任何错误停止，已中断但未写出结果的作业不自动重跑。

## 预设判断

所有等价性通过后，只有总选择时间减少至少5%，且至少6/8案例选择时间减少，才保留为下一次独立TTF确认候选；否则不晋级。另报告初始化、普通增量、shadow和无路径变化分组，不因某分组有收益而删除其余开销。

这是已有4张地图的开发工程证据，不是独立泛化或TTF收益。未通过时先区分变化识别开销、增量热度维护及shadow成本，不自动改shadow周期或删校验来追求正结果。

只在本地提交备份。输出 `build/sa-incremental-heat-audit-v1`；冻结原始数据及native不改动。
