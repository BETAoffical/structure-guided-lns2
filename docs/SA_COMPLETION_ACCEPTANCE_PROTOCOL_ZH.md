# 冻结A的接受器消融

## 问题和边界

扩样计时已有A 69/72、父模型66/72的正向结果。后续288条只读诊断没有支持旧式固定邻域循环。
本轮只问：对已经在SA轨迹上训练的冻结A，允许接受恶化是否提高完整任务成功率、减少真实TTF？
这是条件于当前模型的接受器干预，不是所有SA的结论，也不证明重新训练一个无SA模型会怎样。

不改模型、特征、候选、PP/SIPPS、native、温度日程或随机流；不训练，不扩采监督标签。
使用原生已有的`annealed`与`complete_greedy`，两者都完整执行同一PP。
后者拒绝冲突增加，仍接受相等冲突；不能冒充官方带提前退出的标准PP。
保留模型输入中的原温度日程，视为虚拟时钟；complete_greedy只在接受谓词中忽略温度。
否则同时改变模型输入就不再是接受器单因素对照。历史特征随实际轨迹自然变化。

## 固定数据与资源

- 来源`build/sa-expanded-four-arm-ttf-v1`，12张地图、每张d20/d25两个任务全部保留。
- 统一选来源第一个solver seed 281、replica0，24组条件，两个接受器共48次运行。
- 选择不读取成功、失败、TTF或冲突结果；不能只选三个失败，也不替换地图。
- 使用来源相同选择/PP/接受随机流键；历史SA结果只做首步一致性校验。
- 两臂都重新串行计时，不能用历史SA秒数直接对比今天greedy秒数。
- 每个episode从reset前开始计时，120秒规划预算、240秒进程fuse，无决策数或节点上限。
- 每张图的两个负载顺序相反；各负载中SA先/后各6图。计时单worker，准备审计20workers。
- 支持完成当前episode后安全暂停、身份一致后resume；不覆盖部分结果，不自动重试失败进程。
- 48次规划预算极端合计96分钟，fuse合计192分钟，另有准备/审计；不是性能预测。

## 验证、度量和决策

1. 冻结模型、native及源输入SHA；修改前远端备份标签。计时前提交代码与本协议。
2. 两臂首步候选、特征、概率、选择及PP尝试工作量必须与已保存SA首步一致。
   同一接受结果还须路径一致；拒绝必须完整回滚。测试等价/恶化、零预算、非法模式。
3. 沿用已验证的延后审计计时器，不把逐步hash、JSON压缩或科学审计放入TTF。
4. 运行后重算每步模型概率、选中动作、接受规则、路径身份、终局质量和计时统计。
5. 首要报告成功数、增益/损失条件；原始TTF仅在共同成功上配对，不把超时填0或伪装120秒TTF。
   给出两档负载、逐地图、胜负数、5000次地图级bootstrap；完整报告SOC/makespan和建模任务完成时间。
6. 不要求每一张图都赢，不据小差异自动晋级。若同成功数而TTF方向/区间不明确，结论是不确定。
   若速度与成功率反向，明确记录取舍；不以失败末态冲突少替代成功。
7. SA净完成有益或明显加速：保留SA。无明确优势：保留当前冻结版本，不能宣称等效或立即扫新温度。
   greedy有可靠净收益：只允许提出独立确认，不立即修改默认控制器。任何实验错误先停整组排查。

本批地图已查看，不是独立确认，不回流训练。旧预算冷却、回温、探索实验继续保留负面结论。
原模型/原native不变，不重新验证工程加速，不重跑Official/父模型等非本问题所需的对照。

入口：`python scripts/run_sa_completion_acceptance.py prepare|verify|preflight|collect|audit|report`。
`all`仅在准备及preflight通过后执行串行采集与审计；`stop`在当前episode完成后停止，`resume`显式续跑。
输出独立写入`build/sa-completion-acceptance-v1`。默认控制器保持不变。
