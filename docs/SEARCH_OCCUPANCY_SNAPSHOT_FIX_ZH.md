# 搜索占用记录：v2 日志快照修复

## 原因与影响

独立复核发现 v1 记录器保存了可变的 `fixed` 列表引用。PP 后续追加车辆后，早期搜索记录中的列表也变成了最终列表。

这不是求解器改变固定车辆：每次原生调用已经结束，实际占用映射也在追加前完成。v1 的冻结/off/on 路径、节点数和 PP 决策一致性仍有效，但原始 `capture.fixed` 不能直接用来证明每次搜索的输入。

v1 全部文件保留，不能将其记录完整性解释为通过独立审计。开发阶段 14 次记录截断的 NO_GO 也保持不变。

## 修复与重新验证

- 不修改已登记的 v1 文件，新增 `SnapshotObservingProbe`，在调用前复制列表，调用后只替换日志中的对应字段。
- 复用原有 collector、同一 native、同一搜索预算、8 个见证和 48 个开发条件。
- 每次搜索记录上限仍为 65,536，不提高上限、不修改选择或修复。
- 输出写入 `build/initlns-search-occupancy-observer-v2`，独立 plan、registration 和 SHA。
- 先运行 8 个见证，仍需全部路径/节点/PP 等价、零截断及零无法映射事件、至少 6/8 捕获目标；通过后才运行 48 个开发条件。
- 增加可变输入列表回归测试；独立审计按逐条搜索记录重建 PP 前缀，并验证保存的固定车辆列表。
- 截断记录只能复核已保存部分；其统计是下界，不得补造缺失记录或放宽原完整性门槛。

这组重做是修正证据记录，不是额外的机制参数试验，不产生 TTF 结论。
