## 本轮完成什么

- 六张原Train地图，每图一个预先分配的decision32、64或96状态，没有按结果替换。
- 每状态四个历史显式候选、16个trial，共384条新分支；前八次发现，后八次独立评价。
- 第一批全部审计后才固定选择并登记SHA，之后才启动第二批。确认结果没有参与改选。
- 每次只强制根动作，后续一律冻结Dual16+SA。继承原episode的128步、2500万修复节点预算，不从根重新给完整预算。
- 原动作control为6/6通过。新分支384/384通过全轨迹审计，199条可行、185条到达决策预算；零资源删失、非法动作、重放不一致或未解释错误。
- 新分支实际修复15,044次，prefix另24,576次，control的prefix与单步另390次。最多20个独立进程。
- 真实模型拟合0次，未运行TTF、RL或新控制器闭环，没有修改冻结模型、候选生成、PP/SIPPS、SA或native。

384条分支不是384个独立状态；本轮只有6个状态、6张已查看的开发图。
199/384是整个候选网格的完成数，不能当作某个新算法的端到端成功率。
达到工作预算仍未完成不是无解证明；多进程诊断耗时也不是正式TTF。

## 为什么仍不宜直接训练下一版

已观察到的事实：

1. **不是单纯模型太小。** [上一轮](SA_POLICY_ALIGNED_UPDATE_RESULT_ZH.md)训练集已命中全部经验最佳，开发闭环仍0/8。本轮根状态上，上轮模型也没有超过anchor。
2. **中后期不是毫无机会，但覆盖和可靠性仍薄。** 六根中三根两批完全平局；唯一重复正信号来自m02。16trial增加了重复检查机会，并没有自动令所有排序稳定。
3. **单次干预与持续接管仍是两个问题。** 本轮标签的续跑器是Dual16+SA，不能用它证明更新模型自身连续运行的价值。m02的根动作改进没有解决整个策略的闭环问题。
4. **没有发现能解释本轮结果的实现不一致。** 六根重放、在线/离线特征、冻结模型评分、动作、温度/随机流、路径状态及节点记账均通过；这不等于全项目没有bug。

六根、每候选每批八trial的统计能力有限。噪声、状态覆盖、表示和连续控制各自贡献尚未分离，
不能从弱结果断言整个学习方向不可能，也不能断言多采同类数据必然解决。

## 历史排重与下一步边界

重新核对以下已有结果，而非将本轮解释成全新发现：

- [H32标签合同审计](SA_COMPLETION_CONTRACT_RESULT_ZH.md)：已见样本内赢家乐观、部分trial排序不稳定。
- [31状态扩采](SA_UNBALANCED_COVERAGE_RESULT_ZH.md)：离线有信号，但增加同配方训练数据未证明改善。
- [同动作不同续跑器](SA_CONTINUATION_VALUE_RESULT_ZH.md)：固定首动作也会因后续新模型接管而退化；仅改续跑标签尚无稳定修复证据。
- [成对一致性审计](SA_PAIRWISE_CONSISTENCY_RESULT_ZH.md)：总分聚合的确可能不一致，但直接anchor比较、矛盾否决不等于可靠改进。
- [预算对齐更新](SA_POLICY_ALIGNED_UPDATE_RESULT_ZH.md)：完成过一次训练与闭环，不是只因准入门槛未训练；更少节点没有带来更多完成。

本轮新增的是**更晚状态、继承剩余预算、先冻结选择再运行全新trial**；不是重新证明一步下降有用。
但它只得到弱正信号，因此到此停止本批扩采和同配方重训，不继续更换窗口、抽样种子或树参数追结果。

保留Dual16+SA与原正式结论；这轮新旧GBDT都不替换它。m02作为可复现的开发案例保留，m01反例同样保留，不能按这两个图事后设计并宣称有效门控。
若继续研究新模型，下一份方案必须明确改变并检验“候选监督如何转化为持续策略”的学习合同，
把完整闭环的成功与搜索工作作为必要对照，不能再把一次根动作加参考续跑的离线收益当作部署收益。
这也不等于重做上一轮的“两种旧策略续跑混合标签”：那一方案已经训练并失败，不能换名重复。
这需要独立设计，不自动启动RL、正式TTF、更多同类标签或第二轮拟合。
