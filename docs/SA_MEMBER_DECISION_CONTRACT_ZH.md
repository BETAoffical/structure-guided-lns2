# 新模型决策范围审计：成员修正还不能直接接入 Dual16

## 本轮回答的问题

上一轮提出“冻结旧全局排序，再学习同来源成员修正”。本轮先检查它是否能在真实候选池中执行、现有标签是否覆盖那个决策，以及是否只是重做旧门控。没有拟合、求解、补采或计时，没有修改 Dual16、PP/SIPPS、SA、native 或生产模型。

这里的“旧策略”明确指冻结 **Dual16+SA 的原选择**，不是16状态/47状态H32研究模型，也不是仅在二候选组内取得最高pool分数的候选。

结论：**不直接训练或部署成员修正器。当前补采有价值，但与这个拟议部署位置不充分匹配。** 这不是再次检查模型是否达到5%门槛，也不是否定所有新模型。

## 输入和检查规则

- 复用47根、8张已查看的station-centric地图，读取原控制事件的完整候选池和真实anchor。
- 检查94个训练组的成员、实际大小、来源、8-trial完整性、源状态/地图/指纹及输入SHA。
- “可替代成员”必须与anchor的完整`selection_families`签名、实际agent数量相同，且agent集合不同。来源有交集不等于来源相同；请求16但实际15不算同大小。
- 范围判定只读动作前成员和来源，不用模型分数、完成结果或未来轨迹。没有按效果好坏筛选适用状态。
- 标签覆盖要求anchor和替代集合在同一个已采集比较组中。不同collection的trial编号相同不能伪造成配对标签。
- 原16根另外保存的anchor诊断也检查了；没有为这个严格范围提供额外比较。不把缺标签当失败、平局或零收益。

### 为什么不是程序丢了候选

`lns2_selector/runtime/structshell_dual16.py`登记的运行时只增加component16和hotspot16，最多两个结构候选。`generate_structpool_candidate_subset()`对每个family/size生成一个draft，再合并相同agent集合。它没有给每个结构族生成多个不同成员版本。

因此，同来源变体缺失符合当前候选生成合同；本轮没有发现候选被错误删除的证据。它也不证明跨来源替代没有价值，只说明不能一边声称保持原规则/大小，一边实际切换到另一来源。

### 为什么47个匹配组不能都用于该部署位置

以前的匹配组按稳定哈希在可用的纯Target/Collision/Random size16对中选取，故意不依赖原选择及结果。它正确回答“同来源内部是否有可学习差异”，并不保证该来源就是旧控制器本步选中的来源。

所以需要区分：

1. 同来源二候选里选谁更好。
2. 是否应该放弃原Dual16动作，改用这个二候选组。
3. 新选择器连续使用是否提高完整完成率。

本次匹配标签主要覆盖第1项。它不能自动回答第2、3项。最新聚合的局部正信号仍保留，旧结果及其解释没有改写。

这不意味着旧训练集完全没有结构化邻域标签：旧四候选组包含原anchor，也包含跨来源比较。缺少的是围绕该anchor的同来源、同实际大小成员版本。这个范围错位针对拟议的新控制方式，不是已经证明的此前所有闭环退化原因。

上述历史实验来自不同协议和地图，不将其成绩合并或推断所有门控、结构变体均无效。

## 设计决定和后续边界

**停止自动衔接到“成员修正模型重训”。** 不是永久放弃学习，而是不把离线二候选任务直接包装成能修复Dual16长尾的控制器。

若保留正式候选生成不变，只能研究11根所代表的较窄适用范围；现有直接标签仅3根/2图，不能用它们拟合、选择阈值并宣称泛化。为保留原策略，不能在没有候选时偷偷跨来源选取，也不能事后根据标签决定触发。

若目标仍是处理当前经常选中的结构化集合，则研究对象必须先变成**有机制依据的结构化成员变体**，之后才谈评分器。该路线改变候选生成，不再是“只换模型”；它还没有被本轮证明有效，也不自动授权新采集。

后续方案必须先写清以下四项，否则不进入下一轮训练：

1. **生成差异**：具体改变哪个component/hotspot成员选择步骤；与已有StructPool、SlotPool、阻挡闭包和变大小方案的差异是什么。不能泛泛扩大整个候选池。
2. **动作前依据**：为什么这次可以替换原集合，输入从何取得；不得读修复后结果或成功见证。已有127维H32模型并非完整历史模型。
3. **标签与使用方式一致**：一次替换后交回旧策略的标签只支持这种干预；若计划反复介入，必须验证重复介入，不能沿用根动作优势当连续控制证据。
4. **验证对象**：只对冻结的单一新假设开展有界验证，随后以净完成数和工作量评价，不要求所有地图获胜；新的独立地图确认不能被本批反复查看的8图替代。

本轮不据此恢复一步最优目标、不直接改SA、不启动RL，也不重新运行已经完成的模型容量、标签稳定性或全套TTF测试。如果找不到区别于历史的具体生成依据，保留当前局部成果，停止这条自动训练循环。
