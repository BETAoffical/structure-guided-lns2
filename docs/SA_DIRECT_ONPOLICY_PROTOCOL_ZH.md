# 单模型：完整修复轨迹的 on-policy 更新

2026-10-04。原单模型、代码和结果已增量备份到 `../backups/20261004-before-direct-onpolicy/`；先前完整 HEAD/Git/native 备份继续保留。

继承 `h128-s4110` 的结构、输入、归一化和候选生成，不使用 Dual 评分、推荐或运行时残差。训练只使用上一轮的 8 张训练地图，共 16 个初始条件，每条件 4 个独立搜索随机流。每轮 64 条轨迹、最多 20 worker；两轮采集各自当前模型的数据，各做一次完整轨迹 REINFORCE 更新。

训练在修复迭代边界检查 2,500 万低层生成节点预算，不设决策次数停止上限；完整最后一次修复允许超过节点参考预算。单次 PP 120 秒、episode 900 秒仅为保险，保险到期视为未知。记录所有结果，不将未知填为失败；若批次含未知或缺失结果，该批不作更新，保留现场与原因。没有根据测试结果补换训练或测试条件。

完整轨迹奖励沿用既有 `completion_work` 定义：失败为 0，成功为 `1 + 0.1 × (1 − min(generated / B, 1))`。以成功为主，小幅奖励较少搜索量的成功轨迹。搜索量是训练的工作指标，不能将其等同于 TTF。使用同一条件下另外三条轨迹的平均奖励作基线；梯度按地图、条件和完整轨迹等权，不按轨迹长度重新加权，不使用剩余修复轮数或单步冲突下降作为标签。

冻结归一化，全网络更新。按 L2 步长 0.1、0.05、0.025、0.0125 顺序尝试，选择首个满足既有 KL 限制的步长（平均状态 KL ≤ 0.002、平均轨迹 KL ≤ 0.1、最大状态 KL ≤ 0.02）；这些检查只使用本轮训练轨迹，不优化测试表现。若梯度为零或全部拒绝，则记录未更新，仍保留模型。最终使用第二轮后的模型，不按测试结果选择 checkpoint。
