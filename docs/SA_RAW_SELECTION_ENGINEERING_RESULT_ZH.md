# Raw 选择器无效历史计算：等价工程优化结果

预登记提交 `7a38ca3`，分支 `codex/sa-raw-selection-engineering`。
协议：[本轮范围](SA_RAW_SELECTION_ENGINEERING_PROTOCOL_ZH.md)；来源：[串行 TTF 结果](SA_RAW_SERIAL_TTF_RESULT_ZH.md)。

**本轮找到并消除了实际未使用的计算。完整轨迹特征、概率和动作保持一致，组件时间明显下降。未测新的端到端 TTF，未改变默认控制器或重新训练模型。**

## 1. 为什么这不是重复旧工程实验

历史已经实现 grouped/batched proposal、原生特征、prepared/静态缓存、原生评分及单次完整 fingerprint。
本轮保持这些实现不变，不改 PP/SIPPS，也不采用此前被用户拒绝的 PP 内部加速。

最近 TTF 中，新 raw 模型对 Dual16+SA 的共同成功节点减少 16.92%，但 TTF 慢 6.59%；选择开销平均多约 4.21 秒，是有数据支持的具体新问题。
这次只检查新增 raw 选择路径，而不是再次扫描或重训旧 V2。

## 2. 找到的冗余与模型边界

旧 `features_for()` 先对每个候选计算 `History.features()`，包括整批外部车辆路径的 JSON SHA、历史重复集合和上下文统计，再调用 `profile_features(..., 'dynamic')`。
`dynamic` 会删除所有 `history.*` 列。因此这些历史计算不参与当前冻结模型的概率，也不影响抽样选择。

这不是本轮改变输入或补回训练漏项。早期 `SA_ONPOLICY_DESIGN_ZH.md` 已明确冻结为 127 维动态/阶段特征加 2 维资源参考，共 129 维，不新增历史窗口。
实际模型与逐步轨迹也确认没有 `history.*`。仍保留当前冲突/路径/邻域结构、低层累计统计、温度、决策数及资源参考。

此前“动态/历史条件化”的宽泛表述需要收紧：当前 raw 模型是动态状态、搜索阶段和资源进度条件化，不是显式使用候选最近重复次数、外部路径历史或序列记忆的模型。
这些未使用字段被删除计算，不证明历史信息无用，也不证明历史缺失就是长尾原因。历史信息学习是否有效的旧负面结果仍保留，本轮不重新打开训练方向。

36 个固定状态的 cProfile 定位结果：

| 部分 | 累计剖析时间/s | 相对被测 choose 时间 |
|---|---:|---:|
| 候选生成后的 choose | 2.7277 | 100% |
| History.features，702 次 | 1.8752 | 68.75% |
| 其中外部路径 context，702 次 | 1.6972 | 62.22% |
| raw 模型概率前向，36 次 | 0.0477 | 1.75% |

context 是 History.features 的子项，不能相加。cProfile 会改变调用开销，这张表仅定位热点，不是 TTF 时间占比。

## 3. 改动是什么

新增 `experiments/sa_raw_selection_fast.py::FastPolicy`，是独立、显式启用的快路径：

- 跳过最终必被 dynamic 过滤掉的历史字段计算，直接产生同值的温度/决策阶段输入。
- 保留候选成员合法性、历史连续性及完整外层状态检查；History.observe 仍按原逻辑更新。
- 保留模型、候选池、原始顺序、分数、去重、SA、PP seed 与抽样随机流。
- 私有函数绑定复用冻结 selection/choose 的同一 code object，不改全局函数，不复制一套策略判断逻辑。
- 拒绝不兼容的历史特征模型；原 129 列 schema 及模型 SHA 由冻结输入校验继续保护。
- 没有修改旧 Policy、旧特征函数、正式计时 CLI、原生库或默认控制器。

本轮不优化 History.observe、通用逐步验证或 Official 封装开销，避免把几个独立变更混在一起。

## 5. 串行组件基准

固定六图、两密度、seed251、replica0 的 12 条新模型轨迹，各取早中晚三个状态。
每状态原/快实现各测三次并交替顺序；每次独立 engine、状态副本，预先准备前一状态，避免重复当前对象产生额外缓存收益。

## 6. 可支持的结论与下一步

本轮证明了当前模型运行时有一项可消除的未使用计算，在已登记轨迹上动作保持一致，而且组件收益跨本六图均出现。
没有证明学习策略选择得更好，也没有新的成功率、makespan、SOC 或 TTF 成绩。此前 192 次计时报告及成功数不得重写。

下一步只需冻结这一快路径，比较同一个 raw_updated 模型的原/快运行时，串行配对测实际 TTF 和交付；保留 Dual16+SA 同期对照可判断是否消除了原来的速度差。
不同时增加输入、改候选、修改退火、删验证或重训；预算边界下快实现可能多做步骤，应单独记录，不能要求超时轨迹等长或把新增成功当作选择规则改进。
先采用六图两密度的固定小规模案例，不重跑整个 192 次四臂实验来重复已经回答的父模型学习增量。
本轮停在等价与组件收益确认，没有自动进入下一组 TTF。
