# 容量证书引导的外部协调候选：两层验证结果

## 结论

**通过进入下一轮原生 PP 机制验证的局部门槛，但没有证明修复成功、TTF改善或跨地图有效。**

本轮把“知道邻域缺少外部协调”推进到“能从输入中找到解除特定容量缺额的少量外部车辆”。在八个同源干预后停滞状态，定向候选显著不同于固定随机对照；另两张地图的两个状态没有通过扩大集合检查，结果保留，不追加抽样或扩宽候选。

未修改模型、候选生成的正式默认实现、PP+SIPPS、退火接受；未训练、未运行原生修复或计时。该模块目前仅是诊断工具。

## 如何选外部车辆

从上一轮容量证书涉及的车辆出发，计算全部目标条件化可达时间层。从可达位置尝试一步移动，记录阻挡该移动的外部顶点占用和反向交换边占用。

候选按关键时刻前后8步的阻挡次数、全时域次数、agent ID排序，最多8个。另选同数量、哈希固定的其他外部车辆作为对照。每状态测试单车8个、排名前4车的两车组合6个、对应随机14个，以及原集合基线，共29个。

排名仅使用输入路径和可达层，没有使用本轮放松结果或历史PP成功标签。它只是有限候选生成规则，不是完备最小割，也不保证全部必要外部车辆都在前8个。

## 两层检查不能混为一谈

1. **路径放松**：暂时忽略候选外部车辆，检查原证书车辆在关键时刻能否分配不同格子。
2. **完整成员检查**：把这些车辆真正加入待修复集合，也要求它们到达各自目标；重新检查扩大集合全部时间层的容量必要条件。

第二层通过的准确名称是 `not_proved`，即没有检测到该类必要性矛盾，不是“找到可行解”。每个时刻都能匹配，不保证能串成合法路径，也不排除交换冲突或其他约束。

### 八个干预后状态

同一张地图、同一原始来源的八条干预分支，各389辆车、入口5对冲突、原集合16辆。

每个状态的结果均为：

- 定向单车：4/8解除原缺额，其中2/8扩大集合未再检测到不足。
- 定向两车：6/6解除原缺额，其中5/6扩大集合未再检测到不足。
- 两种随机对照均没有解除原缺额。

这些相关状态不能写成八张独立地图或八个独立任务。相同计数也不是八次独立成功验证。

以 `post-add_certified-0` 为可追溯示例：

| 外部候选 | 原缺额是否解除 | 加入该车并要求到达目标后 |
|---|---|---|
| 329 | 是 | 未再检测到容量不足 |
| 57 | 是 | 第93步仍不足，证书组包含57 |
| 220 | 是 | 未再检测到容量不足 |
| 375 | 是 | 第93步仍不足，证书组包含375 |
| 57和329 | 是 | 未再检测到容量不足 |

这些ID只用于复核，不硬编码为控制器动作。“拿走57能腾出格子”不等于“要求57同时到达目标后，整个集合就能协调”。

## 门槛与历史经验

预先固定的下一轮准入要求是：至少两个状态有定向候选通过第二层必要条件检查，并且按状态、单车/两车配对组等权平均的通过比例高于随机。

实际为8个相关状态有此候选，组均值为 **43.333% 对 0%**，达到局部机制准入条件。按全部动作汇总则是56/140对0/140，即40%对0%；两种口径不能混用。

这不是降低正式TTF门槛，也不是控制器晋级。没有恢复静态上下文迁移主张。

与历史“补入全部阻挡车”不同，本轮先区分放松原矛盾和加入新成员后的新矛盾；与反复回温不同，本轮调整的是必要的外部占用约束，不是在不可行集合内继续改变接受概率。历史全体补车成本增大、随机补车也有效等负面结果仍保留。
