# 冻结退火机制的新地图确认协议

## 决策问题

确认完整 PP + SA 对冻结 Dual16 的开发性 39.1% 平均 TTF 改善能否在新地图任务上重现。
主比较只有 Dual16 + SA 对 Dual16；Official、Official + SA 为通用收益与竞争力对照。
不是完整 CPLNS 复现，不重训、调温度、改变候选、尝试其它门控或自动替换默认模型。

## 固定数据与边界

master seed 为 2026091207；派生八个地图生成 seed，每个生成一张新的 48 x 72 station_centric 仓库。
复用已登记仓库生成器参数，每图独立生成 15% 和 25% free-cell 密度的 balanced OD 任务。
比例为 storage->station 35%、station->storage 35%、left->right 15%、right->left 15%。
两个密度任务不是 agent 前缀，也不是同步任务流或 lifelong MAPF。
每任务 solver seeds 101、103，共 32 个案例，四臂共 128 个 episode。

生成前登记本地保留数据 manifest 中的 map/task seeds 和可访问地图文件 SHA；新数据不得重复。
缺失历史地图文件必须列出，不能把本地 inventory 写成已核实所有被删除的历史数据。
新地图文件 SHA 也要求彼此不同。文件级不同不保证每种拓扑特征都不同。

32/32 reset 正确为硬要求；零冲突、高冲突均保留，不要求每地图达到某个冲突比例。
25% 密度只是预先指定的较高负载，不保证一定出现困难或超时。
生成失败、seed 重复、非法路径或不完整初始化必须停止，不重抽 seed 或删除任务。
若任务仍全部很易解，只能确认该分布的 TTF，不能声称成功率和严重长尾已修复。

## 冻结实现与执行

使用上一轮同一 native、模型、TimedPool 和 worker；新入口仅负责独立输出目录、生成、登记和判定。
计时单 worker，60 秒预算，无修复次数上限，180 秒外部 fuse。
四种方法 Williams 顺序轮换，每个方法每个位置出现八次。
温度仍为 1000 * 0.99^decision，完整 PP 与接受逻辑不变。
PP 使用剩余墙钟预算，不设置另一个短 PP 上限。
TTF 从常驻环境 reset 前到首次可行 native 返回，不含最后审计落盘和冷启动。
成功前的状态处理和选择开销仍计入；不能与包含最后交付的旧时间直接混算。

非计时生成、reset 准入最多 20 进程；全部准备任务结束后才进入串行计时。
先运行原生配对 parity 和三步 smoke，随后提交源码、配置、数据哈希与排程登记。
复用逐 episode 原子结果、完整重建验证、运行锁、resume 和当前 episode 后安全暂停。
新旧输出目录严格分离，不能续跑进旧 pilot，也不能覆盖旧证据。
不重跑上一轮长实验，不改已有正式默认控制器。

## 预定解释

主终点为 60 秒时间窗内平均 TTF：成功取实际时间（上限60秒），未解取60秒。
原始共同成功 TTF 与非共同成功明细另报，失败不能当零秒。
同时报告成功数、样本最大值、各密度与各地图结果、实际 PP 次数、节点与选择开销。

主比较的平均改善至少 5%、地图级 5,000 次 paired bootstrap 时间差区间上界小于0、
且观察到的成功数不下降时，记为本生成器新地图上的平均 TTF 确认通过。
不要求每张地图、每个 seed 都赢，也不以节点数增加一票否决。
成功数下降而均时改善记为速度/可靠性取舍；区间跨零记为不确定，不等同无效。
成功数相同不能证明统计非劣；全成功时退化的 bootstrap 成功差区间不作为可靠性证明。

主比较之外均为次要描述，不根据哪个对比最好来改主问题。
即使主比较通过，也不等于超过 Official，不证明静态上下文迁移或跨地图族泛化。
禁止按新结果挑出“适合SA”的任务作为确认性结论，禁止在本轮追加温度或救援链。

## 预算与停止

128 个 episode 搜索预算累计上限128分钟；180秒 fuse 极端累计上限384分钟，另加调度与准备。
这些是上限而非性能预测。准备阶段测量不用于给方法排性能名次。
`python scripts/run_sa_independent_confirmation.py stop` 在当前 episode 后安全暂停；
`resume` 校验全部身份和既有结果后继续；异常保留记录并暂停，不静默重试。
