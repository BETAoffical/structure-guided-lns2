# 冻结 A 与原模型的真实 TTF 对照

状态：96 次计时和96条完整轨迹审计均已完成，正式报告已生成并通过seal校验。

## 结论与范围

本轮冻结纯成功率续训模型 A，与其父模型 raw-1 比较，不训练、不更换 PP/SA、不改变候选或特征。
两者使用同一套共享特征加速运行时和轻量计时循环。没有重新测试旧工程加速，也没有并行计时。
协议见 [预登记计时方案](SA_TERMINAL_EFFICIENCY_TTF_PROTOCOL_ZH.md)，训练来源见 [完整任务成本对照](SA_TERMINAL_EFFICIENCY_RESULT_ZH.md)。

核心结果是：A 多成功两个条件，没有丢失原模型成功；共同成功条件总体 TTF 仅快 1.41%，
较高负载平均快 8.25%，较低负载平均慢 11.18%。这是有限的可靠性与高负载信号，不是全面加速。
最困难地图的四个高负载条件仍然两者全部失败，长尾没有被彻底修复。

六张地图均为已经查看过的同族仓库开发图，不是新的独立跨布局确认。
本轮只比较 A 和 raw-1，不将历史 Official、Official+SA 或 Dual16+SA 的异期数字混作同期对照。
原模型仍保留，A 不自动取代默认控制器；B 没有参加本轮计时。

## 新增成功、退化和未解长尾

A新增成功均在M01/d25：

| solver/replica | 原模型 | A |
|---|---|---|
| 251/0 | 120秒未解，剩5对冲突，493次修复 | 118.5219 s，552次修复 |
| 257/1 | 120秒未解，剩2对冲突，484次修复 | 52.1464 s，249次修复 |

第一例距预算仅约1.48秒，必须保留截止时间敏感性，不能称为大幅稳定挽回。
剩2或5对冲突也不保证延长一点时间就会成功；本轮没有延长预算来证实它。

有代表性的速度取舍：

- M03/d20/257/1：原模型10.8250 s、53次修复，A 52.1665 s、262次修复。
- M03/d25/251/0：原模型64.6041 s、291次修复，A 23.6071 s、75次修复。
- M04/d25/251/1：原模型55.5295 s、208次修复，A 94.6213 s、356次修复。

因此变慢并非全是记录开销或毫秒级噪声，真实搜索轨迹也改变了。
共同成功平均修复次数107.786 -> 108.952（+1.08%），节点8,442,186 -> 8,353,073（-1.06%）。
选择耗时4.4999 -> 4.4773 s，native PP耗时14.6900 -> 14.3775 s，均没有足以解释全面加速的大变化。

M05/d25全部四个条件双失败。按251/0、251/1、257/0、257/1顺序，
原模型剩余冲突为71/31/82/64，A为53/51/90/118。
减少修复次数或某一个条件剩余冲突较少都不能替代可行性；也不能从一次预算失败证明固定候选必然无解。

## 为什么与节点预算结果不同

上一轮25M节点预算下为parent41/48、A42/48；本轮取消节点限制，仅保留120秒预算，变为42/48与44/48。
模型和随机流没有更换，但两种预算允许的搜索长度不同。
A在M01/251/0和M04/251/1继续搜索后成功；parent在M01/251/1继续后成功。
这不是重训后又变模型，也不应把两个不同终止条件的成功数混成一次实验。

只读回看训练信用：A的96条训练轨迹中仅16条有非零优势，其中d20为4条、d25为12条。
d20有47/48成功、d25有33/48成功；纯成功目标对同条件全部成功或全部失败时不提供相对差异信号。
这与高压力条件获得更多训练信用一致，可能参与解释负载取舍；尚不是完整因果归因。
上一轮B把非零信用扩大到88条仍没有足够增量，因此不能简单靠加一点成本权重或继续增加更新解决问题。

## 判定与后续

按冻结协议，总体TTF至少降低5%的速度信号条件未满足。净成功增加则保留可靠性取舍，不能将本轮一概判为没有价值。
A在本批全部保留parent成功并净增两个，且高负载共同成功均值更快，值得作为冻结候选保留；
整体和分层时间区间仍跨零，较低负载和M04存在明显代价，默认模型不自动替换。

下一项优先工作应是冻结A与parent，在少量新地图上一次性检验高负载可靠性，并保留较低负载对照。
不在这六张已经多次查看的图上继续扫奖励权重、训练轮数或事后负载路由。
若另行研究如何保护较低负载，应先单独定义新目标与验证集，不回到一步便宜等于完成更快的假设。
本轮未启动任何后续实验。
