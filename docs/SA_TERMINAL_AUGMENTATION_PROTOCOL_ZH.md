# M04 终末邻域补充：有界机制对照

本轮不训练、不修改控制器、不测正式 TTF。它不是一个全新的机制：历史补外车和路径兼容性曾有局部收益，但没有恢复完整任务。本轮只检查上一轮 94–249 与 94–388 冲突交换对应的具体候选缺口。

## 固定输入与动作

- 完整 500-agent M04 Train 任务，trial 0 的 decision 241、249 两个相关状态。
- 原动作集合分别为 `[94,244,249,443]` 和 `[56,60,80,84,93,101,198,266,273,306,312,322,350,388,397,497]`。
- 定向组只加入缺失的 `{94,249,388}` 成员，原集合全部保留，得到 size 5、18。
- 随机组从原集合外的所有 agent 按 namespace、root fingerprint、agent ID 的稳定哈希排序，补同样数量；运行前登记，不看新 outcome，不排除潜在有效阻挡者。
- 每组沿用该根旧候选实验的四个 PP seed。集合不同不保证共有成员相对 PP 顺序不变；这是集合级干预，不是严格的“只换一条路径”实验。
- 原组八个 trial 按 SHA 和全路径科学字段验证后复用；另在两个根各执行原 action 控制，要求原生科学结果逐项复现。
- 16 个新分支，2 个原动作控制，单次共享完整 prefix 重放至 249；不重放第三个根。最多 20 workers，实际每根 8 分支，无人为增加作业。

## 预算与正确性

沿用冻结 native PP+SIPPS、原温度与 acceptance uniform；单 PP 20 秒保护、子进程 90 秒 fuse、含重放组 1860 秒 fuse。预算耗尽为未知，保留记录并停止检查，不自动重试。不存在 episode 决策数上限，249 是复现目标而非求解截断。

完整重放模型、历史、状态和原候选池；所有新 action 在独立 fork 中执行。验证实际修复成员、外部路径不变、全路径顶点/交换冲突及终点持续占用、节点增量与 SA 接受/回滚。复用结果、当前源码、配置、模型、native 及旧登记全部进入输入 SHA。输出原子写入，支持检查后 resume 和 `stop`。

## 解释与停止边界

主要结果是完整任务零冲突，而非旧冲突消失。分别报告两根三组的四个 trial、残余边、节点、SOC/makespan、实际 PP 顺序和完整成功见证。不把 24 个分支当成 24 个独立任务。

- 定向恢复：存在该集合的机制见证，随后才可设计不读取未来结果的在线构造；不能立即推广。
- 随机同样恢复：不能宣称资源反馈增量价值。
- 全部失败：只说明当前集合与四个 PP 顺序未恢复，不能证明无解或模型无法提前避开状态。
- 全部失败后，最多考虑一个固定外部路径的联合可行性参考检查。须先明确支持的 agent 数、资源预算和证明范围；不把两车松弛当成三车可行、不自动启动另一轮 CBS/PBS 扫描。

当前三车假设来自此前 outcome，是事后机制诊断，不能用作独立验证或正式训练标签。结果和报告保存在 `build/sa-terminal-augmentation-v1`，旧科学文件不变。本轮只本地提交及备份，不推送。
