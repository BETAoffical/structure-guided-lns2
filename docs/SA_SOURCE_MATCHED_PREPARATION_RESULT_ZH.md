# 候选来源匹配检查与下一轮准备结果

## 本次完成了什么

本轮继续查找新选择器的可检验问题，没有运行求解器或重新训练。核查了47个既有根状态的完整候选池、原标注候选、8折旧GBDT留图预测，并追溯三个事后案例的48条原始分支。

随后完成了[同来源同大小协议](SA_SOURCE_MATCHED_PROTOCOL_ZH.md)的盲抽样、输入登记和dry-run。**当前只有准备结果，尚未获得新标签，`collection_ready=false`。**

## 新发现：当前标注没有覆盖组内比较

| 检查 | 结果 |
|---|---:|
| 已标注候选中，实际size16且完整来源签名相同的候选对 | 0 |
| 完整池中，满足上述条件的候选对 | 137 |
| 完整池中，同一纯Target/Collision/Random规则且实际size16的候选对 | 137 |
| 能提供这种对照的根状态 | 47/47 |

这里的“来源相同”不是只要有一个family重叠，而是规范化的`selection_families`签名完全一致；新清单进一步只使用单一family。

因此旧标注直接比较过不同size、不同来源以及不同集合，但没有直接评价“同一规则、同样大小生成的两个车组”。它是一个具体的标签覆盖缺口。

**不能据此证明模型只看来源，或证明模型不可能从跨状态变化中学习成员信息。** 匹配来源和大小后，seed agent、原始分数、路径、成员重叠等仍可能不同；本轮也没有识别coverage的因果效应。

## 与历史尝试的区别

- 原paired pilot按小、中、大邻域分层抽取候选，确保大小覆盖；新准备固定同一来源与实际大小，检查成员差异。
- History bridge使用anchor和模型赢家；factorial复用这些标签，没有补齐同来源组内对照。
- History sampling correction侧重重复记录、候选是否尝试过及4/8/16覆盖，不等于这个匹配设计。
- 已做的同根配对trial、冻结续跑及反事实标签不是新贡献。本次只补一个尚未直接验证的数据条件，不重做模型容量、历史窗口或置信度阈值搜索。

## 固定清单与预算

清单由哈希盲选，不使用旧标签、模型分数、coverage数值或三个事后案例的结果。

- 8张已查看仓库地图，每图2个不同来源episode，共16个根。
- 每根一对同规则、实际size16的不同集合，加旧首选参照；去重后共47个候选评估。
- 规则分布：Target 7根、Random 6根、Collision 3根。未为了均衡规则而事后换根。
- 每候选8个全新trial：共376条分支，包含128个主匹配pair-trial比较。
- 最多12,032次H32修复；独立reset逐trial重放prefix时，另外最多10,048次历史修复重放。
- 每trial安全预算180秒，串行预算和为67,680秒；除以20个worker为3,384秒（56.4分钟）。这是理想满并行的预算换算，不是实际耗时预测，也不是保证的墙钟上限。

16根仍只有8张地图，不把376trial当376个独立场景。此清单用于机制标签检查，不能据此宣称新地图或连续控制提升。
