# SA 工作量与冷却进度只读审计

## 范围与历史差异

已有按修复次数分组的冷却审计发现：部分早期失败仍大量接受恶化，极晚期低温则几乎不接受恶化。这不证明提高或降低温度能改善完成率。本次不重复温度扫描、末态重热、外部车辆扩充或梯度两半检查。

本次只检查一个接口：在每步搜索开销变化时，固定节点预算内实际执行的决策次数和温度是否明显不同。复用 `build/sa-second-onpolicy-batch-v1` 全部192条完整 Train 轨迹，不新增求解、标签、模型更新或 TTF。冻结 actor-1 和未训练探索 actor-0 各96条，来自6张地图、24个任务/solver条件，各4次重复。未训练探索不是纯均匀随机，它仍有冻结 Dual16 锚点先验。

输入正式 report SHA 固定为 `869ae98b2fbbd3b7d9f1aa014f46576a11b8e9599fd118d91b206d4cbea628c1`。正式控制器、native、训练数据不变。已有模型输入已经包含温度、decision和剩余预算，不把本次诊断称为新增模型信息。

## 固定统计口径

- repair generated nodes 为当前计数减 reset 后初始计数，预算2500万，无决策次数上限。
- 刻度固定为25%、50%、75%、90%、100%。记录首次跨过刻度的实际完整动作温度及前后节点区间、超出量，不虚构刻度上的精确状态或下一步温度。
- 刻度前已清零的 episode 单独记 already_feasible，温度缺失而不是0；清零与跨越同时发生另记 success_on_crossing。
- 动作分箱按动作开始前已消耗节点；一个昂贵动作可以跨多个刻度，报告其跨越区间。节点预算是完整动作边界停止，不声称是硬节点截断。
- 统计恶化尝试、接受、拒绝、回滚、完成情况、所选邻域大小和搜索节点。低冲突沿用1至10对。未完整规划不得当作 SA 拒绝。
- PP attempted 是局部计数；全局尝试冲突为修复前全局冲突加局部新旧差，不能直接把 pp_attempt 当全局。
- 两臂按同 task、solver seed、replica、初始 fingerprint和随机流配对。只在双方确实到达刻度时比较温度，始终给出幸存者分母，不作因果收益估计。
- 全体、地图、任务类型分层；失败子集只作描述，不能用事后分层选择新温度。

## 完整性与停止边界

校验来源登记、已完成标记、审计、192个结果及其轨迹SHA；逐步检查状态连续性、候选身份、接受概率和回滚。登记本脚本、测试、协议及关键解析依赖。只读解析最多20进程。发现不一致即停止，保留输出，不改原始结果。

新登记名使用 `audit_registration.json`，避免被历史采集器的 collection 重复源扫描误认为新采集。支持逐 episode 原子保存与 `--resume`，拒绝改变输入后续跑。

```text
python scripts/audit_sa_work_clock.py prepare
python scripts/audit_sa_work_clock.py analyze --workers 20
python scripts/audit_sa_work_clock.py verify
```

输出在 `build/sa-work-clock-audit-v1`。本轮最多形成组件接口描述；没有新冷却方案的实验，不据此宣称成功率/TTF改善，不自动进入改温度、训练或新反事实采集。若只是复现已知相关性，明确停止该分支。
