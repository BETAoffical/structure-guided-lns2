# CPLNS 同任务重新初始化：有界机制诊断

## 为什么进行，以及不能回答什么

前轮无分配观测及独立静止路径计数回归已通过。正式 V2、Dual16 和官方 native 不改。
这里复用修正后的作者单求解器，不重新实现退火。它不是完整 CPLNS 多求解器协作，也不是官方 LNS2。

现有五个困难状态来自 Dual16 的历史轨迹。作者 CLI 没有任意路径导入接口，因此本轮仅保留其地图、
agent ID、起终点，重新运行作者初始化。不能称为同停滞状态续跑，也不能判断旧失败状态已被修复。
先检查新初始化是否有足够修复机会，避免对全是直接可行的任务进行无意义的四路实验。

## 固定方案

- 分支 `codex/cplns-real-task-mechanism`；恢复标签 `post-cplns-noalloc-count-20260911`。
- 固定五个 discovery 案例 02、04、09、13、22，不读取 validation、test、OOD。
- solver seeds 为 0、2、3、5；无退火/无重启、仅退火、仅重启、退火加重启四组。
- 直接复用作者参数：温度 1000、每轮冷却 0.99；重启阈值关闭为 2、开启为 0.4。
  不把该阈值误称为冲突上升阈值，不改变作者的连续失败计数定义。
- 最多 80 作业，每作业求解预算 30 秒、外部 fuse 60 秒，20 个进程。
  求解器墙钟预算之和上限 2400 秒，不是实测 CPU 时间，也不是性能预测。
- 先运行 20 个无退火/无重启作业：至少 10 个产生初始冲突、覆盖至少三张地图，才补齐其他 60 作业。
  准入失败后停止，不改密度、不替换任务、不追加 seeds。
- 复用前 128 次决策和最终状态的固定无分配观测。使用 screen=1 减少作者海量逐 agent stdout；
  四组必须完整初始路径、SOC、冲突一致，差异则禁止配对结论。
- 过程路径、冲突、SOC、接受与回滚必须独立验证。过程异常、缺失完整初始状态或文件身份错误停止。
- 同一批最多 20 作业；在输出目录创建 `STOP_AFTER_BATCH` 可完成当前批后暂停。
  resume 只复用身份/输出 SHA 完整且正常的作业，孤立文件或失败不得自动覆盖重跑。

## 分析边界

报告初始冲突、前 128 次决策的接受/拒绝、路径不变、接受更差后同一重启段突破历史最低冲突的次数、
观测范围内与最终可行情况。每个实际保存状态均重新计算冲突和 SOC；截断后没有导出的中间步骤不做推测。
重启清除归因标记，不能把新初始化带来的改善归因于上一次退火接受。
接受更差后出现新低也只表示时间上的先后，不证明那次更差动作是改善的原因。

最终可行数属于并行资源限制下的开发诊断；不计算 TTF 加速比，不作为晋级门槛。
这里未使用旧模型，不能将四个作者参考配置的差别直接推广到 Dual16。
初始配对和完整性通过只是准入，不等于退火有效。无有效差异则保留负面结果，不追加温度搜索。

## 入口

```bash
python3 scripts/diagnose_cplns_real_tasks.py prepare
python3 scripts/diagnose_cplns_real_tasks.py verify
python3 scripts/diagnose_cplns_real_tasks.py run
```

所有输出留在 `build/cplns-real-task-mechanism-v1`。代码/协议在作业执行前本地提交，冻结模型及正式结果不变。
