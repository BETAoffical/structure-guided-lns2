# PBS 隔离修复与机制比较协议

本轮只做非 TTF 诊断，不修改正式 native、模型、Dual16 或退火。恢复点为 `pre-pbs-repair-fixes-20260914` (`d0476dc`)。
所有 C++ 变更受默认关闭的 `LNS2_PBS_DIAGNOSTIC` 编译选项控制；独立 native 和原始记录存入新 build 目录。

## 顺序与停止规则

1. 有符号 CAT 查询修复：五个最小查询全部通过；六个旧准入输入在独立 ASan 构建中不再崩溃，路径、外部约束与失败回滚正确。发现新错误则先定位修复，不记作算法失败。
2. 补充 PBS 合作式单车 deadline、终止原因及高层计数；只有独立诊断 API 启用。零预算、中途耗尽和失败都验证回滚。现有随机平局及官方默认路径不改。
3. 原四个历史状态、原 agent 集合、四个固定 trial，比较 PP 与 PBS，最多 20 个独立进程。每步 5 秒修复预算、每进程 30 秒硬 fuse，无回合续跑，超时标记未知。度量严格冲突下降、可行、节点和原因，不将多进程耗时称为 TTF。
4. 同集合上界诊断：外部车辆之间的冲突不可被本集合消除；单步全局可行性不可把这些冲突误记成修复器失败。
5. 最多一次搜索结构迭代：仅在高层节点上限确实先终止且无收益时测试固定 4 倍节点上限；若未触顶而主要耗在 PBS 根路径生成，则只测试重用输入路径为 root。两项不同时叠加，不改 agent 集合、模型或接受规则，不追加参数扫描。
6. 若存在重复严格下降机会，再在三个已有 SA 残余平台状态中做同集合四 trial 诊断；不声称独立验证，不扩新地图、不训练、不跑 TTF。若无收益停止本轮扩展并分析根节点、约束、候选覆盖和资源限制。

节点扩展实施记录：Random 四 trial 在原节点上限先终止；按同一 4 倍规则扩展后四次均下降一个冲突。
三个 SA 平台在基础 PBS 下同样全部先触顶，因此将这一个已选定的规则原样验证于它们，共 12 个新增作业。
这不是追加第五档上限或重选 seed；保持 5 秒预算，若无收益不继续扩大预算，不在同轮再叠加 warm root。

## 解释边界

- PBS 接受严格下降，PP 默认可接受非增，主要比较严格下降和全局/受影响冲突数；不把内部 replan_success 直接作为可比成功率。
- PBS 加搜索预算保护后的结果须记录独立 native SHA，不能混入冻结原算法正式统计。
- 历史四状态为事后选定开发材料；两个算法使用相同数值 seed 不代表相同随机路径或 PP 顺序。
- 既有 GCBS 的局部下降多但开销过大、路径重选及宽泛回退失败结论仍有效；不因本轮局部机会自动部署通用 PBS 回退。
- 每阶段保存原始结果并本地提交备份；只有正确性测试全部通过才允许下阶段机制比较。默认 baseline 再构建需通过现有 CTest/parity。
