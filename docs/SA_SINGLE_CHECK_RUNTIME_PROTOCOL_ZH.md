# SA 单次完整状态检查：工程确认协议

## 边界

保留冻结 Dual16+SA、原模型、候选池、PP顺序、退火温度、接受随机数和 native。
只把候选生成器的 `verify_full_state=True` 改为 `False`；保留其版本号检查、无版本接口时的完整检查回退、原 selector 最终完整指纹检查。
独立类不注册为默认策略，不修改历史运行脚本，不使用全局 monkeypatch。
运行器使用冻结 worker 的同一 bytecode，私有 globals 只替换 selector 和计时结束后的结果保存回调。
不改原有截止/异常处理语义：异常停止并保留，不回退、不自动重试。

## 先验证

- 安全标签 `pre-sa-single-check-runtime-20260912` 保留上一版。
- 固定历史地图 m01/m03/m05/m07、两个密度、seed103，共8案例，不按成功或耗时筛选。
- 这批案例未进入上一轮组件微基准，但历史结果已查看，仅作为开发工程证据。
- 8个独立诊断进程重放全部显式动作 prefix；每一步比较两个 selector 与保存轨迹的完整候选、分数和选择，以及路径/冲突/低层计数 fingerprint。
- 诊断环境预算3000秒、每次参考修复上限300秒、进程fuse1800秒。这些不属于TTF结果。
- AST检查除重复校验开关外 selector 操作一致；测试版本号、完整指纹回退、最终校验、空候选、冻结 worker 注入隔离及停止机制。

## 小规模配对计时

通过全部前置检查后，每个案例两种运行时，各重复两次，共32个episode。第二轮反转第一轮的AB顺序；case ID不含运行时或重复号，保持随机动作流相同。
严格单worker，60秒规划预算，无修复轮数上限，180秒独立solver fuse。原始结果保存后，另起进程完整审计（1800秒fuse），审计不与下一条计时重叠。
TTF从reset之前至首次可行native返回，模型/环境构造另报，审计和写出不计TTF。失败保留并按60秒作capped汇总，另列共同成功原始时间。
支持 `stop` 完成当前episode及审计后停止；`resume` 只对缺失审计补审计，已有无输出失败尝试不自动重跑。

## 解释

比较同一案例同一重复的初始FP、候选、分数、动作、PP顺序和完整路径轨迹。只有预算截止造成的尾部差异可以单独解释，不能掩盖非截止分歧。
报告选择时间、PP时间、总TTF、成功数、逐案例/地图差异，以及5000次地图级配对bootstrap（seed20260912）的秒差区间。两次重复不算新独立样本，只有4张地图、8个配对案例。
只有动作等价且实测端到端变快才称本轮有端到端工程加速；组件变快但TTF不变只记组件收益。不得将上轮约4.8%的投影当实测值。
不重跑128条正式实验，不修改SA主结论，不自动替换默认控制器。
