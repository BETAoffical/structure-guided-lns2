# STRIDE 平台—逃逸见证审计 V1

## 结论

现有长尾不是单一的“候选池缺少正确邻域”，也不是 PP 每轮机械地执行同一顺序。主要机制是：结构候选先取得真实局部进展，随后把系统带入一个对当前邻域 **PP 可修复概率很低** 的残余状态；状态不变使缺少修复概率信息的排序器继续选择同一高分邻域，而 PP 以不同 seed 和顺序重复尝试，直到极少数顺序成功或候选池后来产生另一集合。

因此，下一步不应再次学习不稳定的长时域赢家，也不能只扩大候选池。应先把“候选条件下的 PP 可修复分布”确立为机制目标，同时保留一步质量约束，防止重演 V3 偏爱安全小邻域的问题。

## 审计边界

- 使用冻结的 45 个 `first_repeat_stall` 案例、已有逐轮轨迹和 16-seed Repairability 因果审计。
- 使用 16 个进程并行重建轨迹；没有运行新的 PP、训练模型或修改控制器。
- 逃逸动作、外部阻塞者和平台长度都是事后证据，不能作为在线特征。
- 本报告不能声明已经避免长尾或改善 TTF。

完整性检查全部通过：45/45 案例、全部轨迹和因果状态哈希一致，且没有按结果删除案例。

## 平台是怎样形成的

45 个案例中：

- 43 个平台紧接一次严格冲突下降之后出现；首个结构动作本身在 39/45 个案例中严格降低冲突。
- 平台内 98.40% 的动作同时保持 agent 路径和冲突边集合不变。
- PP seed 和 repair order 的唯一比例均为 100%。这不是重复执行同一次 PP，而是在同一残余状态、同一邻域上尝试不同随机顺序。
- 43 个最终严格下降的案例中，36 个使用与平台主导候选完全相同的 candidate 和 agent set，只是 repair order 改变；7 个通过换集合退出；另有 2 个在轨迹结束时仍未退出。

这说明平台更接近“低成功概率的重复抽样”：邻域不一定逻辑上无解，但大多数 PP 顺序都无法改变状态。不能把这一类现象简单解释成“必要 agent 一定缺失”。

## 可修复概率与真实长尾

冻结的 16-seed `baseline_replan_success_rate` 与真实平台长度的 Spearman 相关为：

- 全部 45 个案例：-0.6656；
- 17 个 adverse 案例：-0.6997；
- 排除两个右删失案例后：-0.6213。

|---|---:|---:|---:|---:|---:|---:|---:|
| 0 | 5 | 70.40 | 10.0 | 196 | 5 | 2 | 2 |
| (0, 0.25) | 9 | 11.22 | 7.0 | 49 | 3 | 1 | 0 |
| [0.25, 0.5) | 19 | 4.00 | 3.0 | 8 | 1 | 0 | 0 |

这比外部阻塞者数量、缺失 persistent-core agent 数或重复候选占比更直接地对应长尾。它仍只是关联证据，但已经指出了比“未来 128 步赢家”更稳定、更贴近根因的学习目标。

## 候选池究竟缺不缺

7 个换集合才退出的平台中：

- 6 个退出集合加入了因果审计中观测到的外部阻塞者；
- 只有 1 个完整退出集合在冻结的触发决策候选池中已经存在；
- 其余 6 个与当时最相似候选的平均最高 Jaccard 合并后，总体最高相似度均值为 0.568。

所以候选生成确有缺口，但它只解释少数“换集合退出”案例。在触发点不存在不等于生成器永远无法生成：这些生成器含随机性，退出集合可能在后续轮次才出现。

更重要的反证是：因果审计标记为 `set_defect` 的 21 个状态中，20 个最终退出，18 个仍由原 agent set 退出，仅 2 个换集合，1 个右删失。这里的 `set_defect` 只表示“加入阻塞者的干预在 16-seed 配对测试中稳定优于基线”，不表示原集合不可修复。

## 已知 Maze 回归

- `v2-full`：没有长度至少 3 的平坦段。
- StructPool：8 个平坦段，最长 140 轮，冲突数 18；最终仍由同一 candidate 退出。
- SlotPool：2 个平坦段，最长 49 轮，冲突数 1；最终换 candidate 退出。

因此，StructPool/SlotPool 的问题不是“所有结构邻域都差”，而是结构选择把某些残余状态的单次 PP 成功概率压得极低，确定性排序又不会因为状态未变而改变判断，形成重尾等待时间。V2 在这个冻结回归中没有相同行为，但这还不能证明 V2 在所有状态都具有更高 PP 可修复概率。

## 对此前路线的修正

1. 长时域 MultiValue、Cost-to-Go 和 H=3/H=4 目标失败，是因为候选未来赢家受 teacher、seed 和后续策略强烈影响；继续扩大模型不会修复标签漂移。
2. 一步冲突下降仍然必要，但不能单独作为排序依据；它识别“眼前有效”，没有衡量进入残余状态后下一次 PP 是否几乎不可修复。
3. 单纯增加 closure agent 或增大邻域也不够。多数平台最后由原集合退出，而过度扩张会增加 PP 成本并重演“大邻域越多越慢”。
4. 运行时先试 PP、失败再换候选不可接受；repairability 必须离线学习并在执行前预测。
5. 不能直接最大化 PP 成功率，否则会重演 V3 选择安全小邻域、总体修复轮数增加的问题。

## 下一步：候选质量约束下的 Repairability 排序

### 1. 冻结目标

对状态—候选联合预测：

- `P(PP 产生真实路径变化)`；
- `P(PP 产生严格冲突下降)`；
- 条件于成功时的冲突下降量；
- 原冲突边残留、新冲突边产生和外部阻塞失败分布。

标签由严格配对的多 seed PP 离线产生，不运行到未来多轮，也不把实际平台长度作为训练输入。

### 2. 候选池先做机会审计

- 始终保留完整 V2 候选和锚点。
- 保留原自然拓扑候选，不沿用 StructPool 单一人工首选尺寸；对同一结构种子输出少量、预注册的尺寸/closure 变体。
- 只加入能解释 persistent conflict 或外部 blocker closure 的 agent，不按结果无限扩张。
- 用同一状态、同一 seed 比较全部候选，报告在“一步质量不低于 V2”约束下，是否存在 repairability 明显更高的候选。
- 先证明候选池存在这种候选，再训练排序器；否则先修候选生成。

### 3. 排序采用受约束 Pareto 规则

候选必须先满足一步进展质量下限，再比较 repairability；不能把两个目标压成一个任意权重分数：

1. 不降低相对 V2 的成功率和一步修复质量；
2. 排除预测 PP 成功概率接近零且替代候选明显更可修复的动作；
3. 在剩余非支配候选中比较预期冲突下降；
4. 证据不足时精确选择 V2 锚点。

### 4. 验证顺序

1. 8+8 seed 半组稳定性与 whole-map held-out 校准；
2. 候选池机会率和排序 regret 分开报告；
3. 冻结首次动作后做 bounded forced-continuation，检验是否从入口减少平台形成，而不是触发后回退；
4. 最后才做完整 paired raw TTF、成功率、P95 和最大修复轮数评估。

任何阶段都不得用离线 Oracle、单步胜率或本报告相关性替代端到端晋级结论。
