# 同来源、同大小的候选区分：准备协议

## 研究问题

继续研究首次可行解的可靠邻域选择，不回到“一步冲突下降最大”的目标。

前轮发现新模型经常选择比同状态旧首选内部冲突覆盖更少的同大小集合，但低覆盖集合也存在长期正例。本轮先检查数据能否区分**来源规则偏好**和**同一规则生成的不同 agent 集合的价值差异**。

来源签名定义为候选 `selection_families` 的排序集合，大小使用实际 agent 数量，不使用请求大小。签名一致并不意味着 seed agent、proposal次数、源分数或成员路径一致；本实验只固定来源规则和大小，不能宣称控制了全部变量。

## 本次执行边界

- 只运行 `prepare / verify / dry-run`，登记原输入、候选清单和预算；没有 `collect` 入口。
- 复用47个已查看开发状态及已有留图预测；不重新拟合、不运行求解器、不修改控制器或候选池。
- 三个历史分半同向案例仅用于解释原分支。案例选择使用旧标签，明确为事后分析，不进入模型盲抽样函数。
- 仅核查旧预测对这些已有标签的区分情况，不扫描特征、margin、coverage阈值或新模型参数。
- 保留历史全部记录，不重新枚举旧512分支的trial划分、修改窗口或改写确认结论。

## 待采集对照的固定设计

1. 从现有8张地图各取2个不同来源episode的状态；按固定seed的稳定哈希选择，不按冲突、成功率、特征、模型分数或本轮案例筛选。
2. 每个状态从保存的完整候选池中找出两个**实际size16、同一纯来源规则**的不同集合。规则限于Target、Collision、Random，混合来源签名不进入主配对。
3. 可用规则及规则内候选均按哈希选择。旧Dual16首选作为第三个参照；若已经包含在配对中则去重。
4. 该配对不是模型提出的新动作，所有集合都在历史完整池中。不能将此实验写成新候选生成器。
5. 后续若执行，每候选8个全新PP/SA trial，首动作后由冻结Dual16+SA续跑，固定H32且包含首动作；温度沿根状态的绝对decision继续，不从温度起点重置。旧8个trial不拼入新结果。
6. 同根同trial各候选使用配对PP/SA随机流，候选选择不消耗该流。独立reset和完整prefix replay，候选池与根指纹必须一致。
7. 最多20个进程；单trial含reset、prefix与rollout的安全预算180秒，单次PP安全限5秒。超时记为未知，不能写为MAPF无解，也不能自动换seed。
8. 不用本轮多进程时长比较TTF。预算单独计算prefix重放，不只报告32步rollout成本。

本阶段的数据是**已看过状态上的新随机重复与新候选对照**，不是新地图验证。即使有收益，也仍然是一次动作后冻结参考策略续跑，不能推导为学习器连续控制有收益。

## 后续分析边界

- 主标签仍是H32完成情况。报告每对的完成差、同trial胜负平、censor数量和地图分布，不能只挑两个候选中样本均值较高的作为“真实赢家”。
- 对完整8-trial配对，交叉选优使用固定的全部35种4/4无序划分，平局按候选ID。比较另一半的收益与两个候选的均匀随机期望；35种划分不是35组独立样本。
- 地图等权，地图内根状态等权。报告地图级区间及正负结果，不要求每张地图全胜，也不为追求正结果搜索阈值。
- 若同规则同大小差异仍以平局或不稳定反转为主，不训练新的细粒度排序器，也不自动加trial。若出现可重复的配对差异，下一步才检验动作前表示能否预测其方向。
- 旧anchor只作共同参照，不能用“匹配候选中挑最优”与它比较后声称已获得可部署改进。
- 本轮不添加coverage硬约束，不用新数据修订原bootstrap闭环的负面结果。
