# 无模型均匀探索与官方对照结果

日期：2026-09-12。预注册提交 `6717be5`，分支 `codex/uniform-runtime-official-probe`。

## 结论

完成 16 个等价作业及 32 个新增官方/原版 PP 对照作业，合计 48 个非计时作业。没有改动生产控制器、模型或原生求解器。

**工程等价验证通过，性能准入未通过。**无模型均匀选择能复现此前的全部 445 次修复，但相对官方并未获得预设的底层工作量优势。不能把上轮均匀探索的 16/16 成功写成优于官方，因为官方本轮同样为 16/16。

## 无模型实现验证

保留原有 seed、Target/Collision/Random proposal、代表候选、Dual16 结构候选、去重及随机选择规则；只跳过模型加载、候选特征向量和模型打分。结构候选仍需冲突拓扑分析，不能说候选生成变成零开销。

- 16/16 完整轨迹一致，共 445 次修复。
- 除不再保存模型 score 外，完整候选及来源字段一致。
- 选中 agent 集合、PP 随机 seed、PP 顺序、接受判断、路径 fingerprint、冲突序列、节点数和最终路径均一致。
- 运行时 guard 禁止调用模型加载、候选打分和 `realized_rows`。全部作业通过。
- 这证明无模型调用路径的语义等价，不是正式墙钟加速测量，也没有将其设为默认控制器。

## 三方法结果

复用上一轮 8 张 station_centric 仓库地图、8 个任务、两个初始化 seed 19/23，共 16 个状态；239–299 agents，初始冲突对数 9–41。没有生成新数据或重抽任务，仍是开发性诊断。

| 方法 | 成功 | 决策轮数 | 实际进入 PP 的轮数 | generated nodes |
|---|---:|---:|---:|---:|
| Official Adaptive | 16/16 | 737 | 599 | 7,918,470 |
| 无模型均匀选择 + 原版 PP | 16/16 | 486 | 486 | 7,777,519 |
| 无模型均匀选择 + 完整 PP | 16/16 | 445 | 445 | 8,024,255 |

这里 Official 是相同规范化初始路径下的官方 InitLNS Adaptive，保留原 RNG 调用方式，不额外插入 proposal 或动作级 reseed。它不是上一轮名为 `standard` 的冻结 Dual16 选择器。

完整 PP 和原版 PP 都不接受冲突增加，本轮没有退火。完整 PP 取消较差修复的提前中止，但仍在完整尝试后按冲突数决定接受或回滚。

相对 Official：

- uniform-standard：实际 PP 轮数减少 **18.86%**，节点仅减少 **1.78%**，未达到 5%；只有 **3/8** 张地图节点总数不增加，未达到 4/8。
- uniform-complete：实际 PP 轮数减少 **25.71%**，节点反而增加 **1.34%**；地图覆盖 **4/8** 通过，但节点门槛失败。
- 两种方法均没有新增成功或损失成功，没有资源截断或实验错误。

完整 PP 相对均匀原版 PP：PP 轮数减少 **8.44%**，节点增加 **3.17%**，成功数相同。因此本轮不支持“取消提前中止就能提高整体成功率/降低工作量”。这不是证明完整 PP 永远无用，只是否定本轮的普遍优势解释。

## 为什么轮数减少不等于加速

官方 737 轮中有 **138 轮没有运行 PP**。这些轮次均为 `pp_failure_reason=not_run`、尝试 agent 数 0、节点增量 0，并非 PP 运行了但没有计数。

代码原因见 [InitLNS.cpp](../third_party/mapf_lns2/src/InitLNS.cpp)：收集邻域关联冲突后，若 `neighbor.old_colliding_pairs.empty()`，更新启发式权重并直接返回。本轮这些轮次选的是 Random 邻域，集合没有涉及当前冲突。我们读取并核对了代码，没有修改这个官方行为。

这些空轮并非完全免费，但不能按一次完整 PP 的代价计算。若仅比较 737 和 445，会把“轮数少 39.62%”误当成昂贵修复少 39.62%；实际 PP 次数仅减少 25.71%。

| 方法 | 平均每次实际 PP 生成节点 | 邻域大小分布（实际 PP） |
|---|---:|---|
| Official | 13,219 | 8车591次，7车6次，5车2次 |
| uniform-standard | 16,003 | 16车166次，8车161次，4车157次，其他2次 |
| uniform-complete | 18,032 | 16车153次，8车160次，4车130次，其他2次 |

均匀策略每次 PP 的平均工作量更大。此外，它仍要生成多个候选，而官方只选一个邻域。节点不计候选生成和 Python 处理成本，所以不能以此表直接推导 TTF。

## 对当前研究意味着什么

1. [上一轮](SA_INDEPENDENT_LANES_RESULTS_ZH.md) 中模型 + 退火 15/16、均匀贪心 16/16，说明均匀探索补上了那批模型失败；加入官方后，发现官方本身也能全部完成。这是“修复模型策略缺口”与“超过官方算法”的区别。
2. 无模型路径确实存在；但这只是均匀策略的执行简化，不是证明学习方法有效，也不是完整 V2 模型无需打分。
3. 原版 PP 与完整 PP 的轨迹随后会不同，包括节点计数变化带来的后续 proposal seed 变化。因此本轮比较的是完整策略行为，不能把所有差异都归结为固定邻域下多规划了几辆车。
4. 失败是**性能准入门槛未通过**，不是出现非法路径、错误回滚或计数损坏。
5. 节点门槛只是事先规定的保守资源筛选，不是 TTF 的数学等价指标。本轮既未证明真实加速，也未证明一定更慢；不为得到正结果临时改换门槛。

## 后续边界

停止这批数据上的均匀探索直接计时扩展，不再追加温度、随机比例或末态救援实验。保留无模型实现作为强基线的诊断入口，正式 V2/Dual16 默认不变。

后续新机制必须明确如何减少真实底层工作或候选处理开销，并与官方比较；不能继续以“更少决策轮数”作为充分理由。已有候选剪枝、反馈与容量等失败记录仍有效，不因本轮工程等价通过而重开。任何独立计时研究都要另立协议，不能将本轮未通过包装成通过。
