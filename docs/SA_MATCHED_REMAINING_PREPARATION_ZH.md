# 剩余31个根的同来源配对准备

## 目的和边界

上一轮发现同来源、同实际大小的匹配标签覆盖不足，且观察到的差异集中。
本轮只准备现有47个开发根中未匹配的31个根，不再在旧16对上换模型或调参。
所有地图已经参与开发，不作为独立确认集。旧16个根的标签、模型和结论不变。

只提供 `prepare / verify / dry-run`；没有 `collect` 或训练入口。
检查保存的 trace 与 root 一致不等于已用 native 成功重放。
准备产物的 `collection_ready` 保持 false，不能直接交给旧采集器。

## 冻结的选择与预算

- 排除集合严格等于旧16根，取47根的完整补集，不按标签、预测或难度增删。
- 复用旧采样 seed `202609181` 和 family/member 哈希顺序。
- 每根选择同一纯来源 Target/Collision/Random、实际大小16的两个不同集合。
- 不额外运行 anchor；若 anchor 本身是两成员之一，保留一次，不改变其真实身份。
- 每候选8个 trial，H32，仍由冻结 Dual16+SA 继续，而非训练一步下降模型。
- trial seed `202609182` 沿用匹配实验。注册八条完整 PP/SA 序列哈希，候选间共享对应trial随机流。
- 不跨旧采集组拼接同编号trial。检查新旧完整序列无重合，不宣称哈希证明统计独立。
- 精确496个新作业，各自reset并完整重放prefix，不能将缓存状态复制冒充独立reset。
- 每作业180秒，包含reset、prefix和rollout；PP安全限仍为5秒。耗尽为未知，不是失败标签。

调度在执行前固定：prefix小于32步用最多20进程，32步及以上用4进程，两个阶段串行。
这是对既有长prefix在20进程下超时、4进程下恢复经验的保守资源安排，不是速度收益结论；
32步分界尚未做吞吐量验证，也不保证没有删失。不得自动更换候选、增加预算或重复较差结果。

报告给出准确prefix次数、最多H32修复次数和批次预算。
预算累计不是运行时间预测或TTF，不含进程调度和收尾。磁盘估计只参考历史结果文件字节，
不是硬上限，不用历史完成标签影响本轮选择。

## 输入和后续采集约束

登记上一轮590个输入，以及本轮新增的原始轨迹、地图任务文件、配置和实现SHA。
源root与索引的地图、任务、决策步、路径指纹、anchor、实际集合必须一致；
保存的prefix必须从0连续到目标事件，目标完整pool/action事件必须等于root登记内容。
本轮不调用求解器，不修改原生库，不更新原控制器或特征。

下一步需要独立的双候选采集适配器，不能直接修改冻结旧采集器的376作业/anchor合同。
它应复用原独立作业、PP/SA continuation、回放及receipt校验，同时支持：

1. 此处冻结的两阶段worker排程、独立作业原子写入、运行锁和安全排空停止。
2. 每作业执行前核对native，reset与prefix状态/历史指纹，以及重新生成的完整候选pool。
3. 无效动作、指纹变化及未解释错误停止；普通预算未知保留，不填成false或自动重跑。
4. 保存两个候选真实ID及原anchor身份，但不伪造缺失anchor的结果；单独统计配对差异。
5. 新旧标签按采集组隔离，根总权重不因新增组翻倍；留图时排除该图所有组。

数据完成后先核对差异是否扩展到更多根/地图，再决定固定模型验证。
不新增事后成功门槛，不承诺补采一定能使模型有效，也不将离线标签当成TTF改进。

```powershell
python scripts/prepare_sa_matched_remaining.py dry-run
```
