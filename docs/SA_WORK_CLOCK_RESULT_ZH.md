# SA 工作量与冷却进度审计结果

## 本次完成什么

按照[只读协议](SA_WORK_CLOCK_PROTOCOL_ZH.md)，复用第二批 on-policy Train 的全部192条轨迹：6张地图、24个 task/solver 条件、每条件4次重复，两种策略各96条。没有新增求解或标签、没有训练、没有计时实验；不是192张独立地图。

- 192/192输入、26,041次已保存修复全部可解析并通过状态连续性、候选身份、SA接受规则及最终状态检查。
- 158条可行、34条耗尽25M repair generated nodes；没有本次新增成功、PP不完整或合法空操作。
- 节点统计扣除了 reset 初始规划；停止发生在完整动作边界。最大预算超出154,368节点，占25M的0.6175%，不是额外迭代上限。
- 全程只读，正式 Dual16、两个研究 actor、PP、SA、native及原实验数据不变。不读 Validation/Test/OOD。

## 主要结果

actor-0是带 Dual16 锚点先验的未训练探索策略，不是纯均匀随机。actor-1是已有研究模型，不是本次新训练的模型。

| 项目 | actor-0探索 | actor-1 |
|---|---:|---:|
| 原批次完成数 | 78/96 | 80/96 |
| 失败数 | 18 | 16 |
| 失败轨迹修复次数范围 | 221–395 | 209–341 |
| 失败轨迹修复次数中位数 | 250.5 | 261.5 |
| 最后执行动作温度范围 | 19.066–109.583 | 32.807–123.629 |
| 失败轨迹恶化接受/尝试 | 1,711/1,763（97.05%） | 1,531/1,570（97.52%） |
| 失败轨迹最后10%预算恶化接受/尝试 | 205/220（93.18%） | 173/187（92.51%） |
| 失败轨迹在1–10对冲突时恶化接受/尝试 | 325/335 | 182/189 |

这里的97%左右是事件加权比例，不是独立任务成功率。最后10%按动作开始时的工作进度归箱，不能把跨界动作的搜索成本切成精确时间段。

**这批失败不支持“退火已经冻住，必须继续升温”的解释。** 到节点预算结束，大多数冲突增加尝试仍然被接受。这与旧300秒实验中超过1000步后几乎不接受恶化的极晚期现象不同，不能互相替代。

当前冷却公式是 `T = 1000 * 0.99**decision`，但本批终止依据为25M节点。昂贵的修复使节点预算结束时仍只运行几百步。因此有一个需要分离的组件问题：选择器改变动作及单步成本，也间接改变了同一工作进度处的温度；并不是所有长尾都处在同一种退火状态。

这属于协议与组件耦合，不是发现SA公式写错。也不能反过来宣称“温度一定过高”“把温度降低就能清零”。失败轨迹是事后条件子集，接受坏动作之后的另一条轨迹没有被观测。

## 中断原因及验证

初次在Windows只读解析时，第331步重算温度为 `35.91281197926689`，原Linux轨迹为 `35.9128119792669`，仅相差一个浮点末位（约7.1e-15）。现有冷却审计要求逐位相等，因此停止并保留 `windows-attempt-failure.json`，没有生成失败的研究结论。

在原WSL `/usr/bin/python3` 环境重算与轨迹逐位一致。保留此前60条已通过结果，20进程解析剩余132条，未重跑任何求解；未放宽检查，也未更改原始轨迹。Windows可做结果SHA与汇总验证，但完整温度重算应在原Linux环境运行。

新增16项Windows测试及60项相关WSL测试通过。输入与完整报告校验通过。这是相关回归，不是全仓库测试或新的CTest/parity运行；C++未修改。

## 决定及下一步

本轮决定为 `work_exposure_descriptive_no_causal_gain`，没有新方法晋级。原80/96对78/96仍只属于已有Train证据。

历史核对表明：末态重热、额外20%预算、定向补车、同根CBS/PBS、单步/H32目标、课程重训和梯度两半检查均已有结论。本轮不据此重复这些工作。

若继续，只值得考虑一个**另立协议的预算对齐冷却对照**：固定actor-1及探索对照、候选、PP、随机流和25M预算，不训练；比较现有按decision冷却与一个事先冻结的按工作比例冷却方案，覆盖原六图完整任务及新随机流，保留成功与失败而不只重跑M04。温度端点及日程必须先独立论证、检查历史，不能从本报告挑最佳温度或循环扫描。

该对照仍须同时报告全任务完成数、成功增损、搜索工作量和路径质量；不以每步成本、局部冲突下降或接受率作为晋级指标。没有新终局收益则停止此日程，不自动再调温度。只有得到可重复的完整任务收益，才值得在相应SA语义下重新训练选择器。

这只是下一项可能的有界实验，本轮未启动。现有模型已经含温度和剩余预算特征，不把调整日程包装为首次引入历史信息或新的迁移成果。
