# 单外车软占用机会审计 v1

## 问题与历史边界

此前某个事后案例中，保持11车集合、PP顺序和所有外部真实路径不变，只在搜索的软CAT中不参考235号车，即得到更低冲突。此结果不是全局可行性或TTF改善。

后续实际碰撞反馈、全部搜索区间、入队/出队搜索前沿的频率排序均未通过门槛。前沿裁剪减少了记录量，却不能把历史见证排到前列。继续换频率规则无法回答更基本的问题：其他失败状态是否存在此类机会？

本轮对有限动作空间做穷举，避免先设计新的选择器。冻结 Official、V2、Dual16、模型、native、冲突账本与接受/回滚规则。不训练、不进行正式TTF、不运行闭环。

## 冻结来源与动作

- 来源为已查看的 reservation-feedback 开发证据中的7个 failed-tail 状态，兼容两种历史角色名称。
- 每张地图按 `SHA256("single-release-opportunity-v1/" + case_id)` 最小值选一个，共3个状态。不得查看新结果后换状态。
- 固定 case-3723c8bd272e、full-f062ea7307d7d84b、case-7ee343a50388；地图分别为 station_centric 0000、0002、0006，不是三种地图族。
- 原有选中集合/顺序分别为16、16、15车；外车分别416、467、471辆。
- 固定 PP seeds 20260912、20260913。每辆外车逐一在每个seed下测试，共2708个分支，6个普通基线。
- 单次搜索可忽略一辆外车的软占用，但从首辆新路径插入开始，该外车必须始终进入真实冲突计数；外车路径完全不变。
- 不增加外车到邻域，不改变优先顺序，不做多外车联合释放或成功后继续修复。

## 预检、进程与存储

先复现6个普通基线的完整路径、逐车搜索路径、成本、generated、expanded、冲突数及回滚。每个条件做 A-B-A 及 B重复，验证持久worker缓存不改变科学结果。另复现历史235号见证trial 0/1，不能据此作新效果证据。

20个独立进程，每分支重置PP RNG；绝不在线程间共享全局rand。分支搜索30秒，单车最多5秒；单分支进程监护90秒。单次收集60分钟后停止派发并完成当前作业。预算不足为unknown，不视为无收益，不自动增加预算或重试。

`STOP_AFTER_JOB` 请求安全暂停。整组锁、原子结果、逐作业进度、身份/SHA检查及resume。外部fuse或未解释错误暂停整组，先检查再恢复；正常内部unknown保存后继续。运行时为并行诊断成本，不是控制器TTF。

每条raw只保存实际尝试的选中车路径及搜索记录，通过冻结原状态重建完整路径。真实冲突账本、最终路径、外车不变、native reset_paths验证全部保留。每条raw和摘要均绑定plan及SHA。只压缩新输出，不改变历史文件。

## 预注册判定

每个状态分别报告两个seed下所有有效、回滚、unknown分支，改善外车ID、最佳剩余冲突、SOC/makespan及节点开销。

稳健机会必须是同一辆外车在两个seed都严格优于对应普通基线。对该固定外车计算两个seed相对冲突降幅均值，至少5%；至少2/3状态达到此标准。2708分支全部完整可判定、6基线及2见证校验通过、独立账本校验零错误才通过完整门槛。

- 通过：只证明这些已查看失败状态中存在可重复的单外车机会。下一轮才可设计输入可见的选择器；不能直接部署或称为速度改善。
- 完整但不足：暂停单外车机制部署。区分完全无收益、只在一个seed有收益、两个seed需要不同外车、收益不足5%。不临时新增trial/状态/阈值。
- 缺失或unknown：有限预算下证据不完整；仍可报告已见机会，不能声称不存在机会。

事后从数百外车中选择的最好结果是oracle，非可用策略。3个状态、3张同族地图不能提供一般泛化证据。只测试失败状态，不能证明不会损害快速正常任务。局部冲突下降也不保证减少长尾或提高整例成功率。

## 命令与交付

`scripts/diagnose_single_release_opportunity.py` 提供 prepare、dry-run、preflight、collect、analyze。prepare仅冻结协议，不启动搜索；正式diagnose前提交推送登记、代码、测试、配置及本文件。输出在忽略目录 `build/initlns-single-release-opportunity-v1`。

交付逐外车/seed结果、独立路径账本校验、中文报告、失败分类与下一步go/no-go。保留所有历史否定结果；不恢复静态迁移、RL或正式TTF主张。
