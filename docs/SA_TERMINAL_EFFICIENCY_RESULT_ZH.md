# 完整任务成本训练对照结果

## 结论

本轮已完成两种固定目标的模型更新，以及全部训练与比较轨迹审计。
纯成功率续训 A 有有限的开发正信号；加入完整成功轨迹搜索成本的 B 没有达到本轮预登记信号条件。
不能据此宣称任一模型已经缩短真实 TTF，也不替换当前 raw-1、Dual16 或官方控制器。

| 模型 | 48 个比较位置的成功数 | 相对 parent 的新增/丢失成功 | 共同成功的搜索节点变化 |
|---|---:|---:|---:|
| 原模型 parent/raw-1 | 41 | 基准 | 基准 |
| A：只按最终成功续训 | 42 | 2 / 1 | -0.98%，40 个共同成功位置 |
| B：成功加完整搜索成本奖励 | 41 | 0 / 0 | -2.82%，41 个共同成功位置 |

这里的变化是低层 generated nodes，不是运行时间。节点减少不能自动抵消候选选择、推理以及额外修复的开销。
每一行使用自己的共同成功集合，不能横向混用两个集合的均值。

## 实验实际改变了什么

预登记提交为 `6738dbb`，起点为 `d234691`。协议见 [完整任务成本训练对照](SA_TERMINAL_EFFICIENCY_PROTOCOL_ZH.md)。

- 两个模型从同一个冻结 raw-1 分叉，使用同一批新采集的 96 条完整 parent 轨迹，各更新一次。
- 保持 129 维输入、32 单元隐藏层、归一化、候选生成、PP+SIPPS、SA 和 native 不变。
- 保持按地图等权、leave-one-replica-out 基线、原有 KL 限制和回溯步幅，不扫描参数。
- A 的整条轨迹回报为 `R = success`。
- B 为 `R = success * [1 + 0.1 * (1 - min(G / 25000000, 1))]`。
- `G` 是初始化后直到首次可行的全部修复搜索节点，包含无效及被拒绝修复，不是某一次动作成本。
- 预算内未成功得 0；成功得 1 到 1.1。原子修复越过节点边界后成功仍得 1。
- 保护性中断属于未知，不补成失败标签。本轮没有触发这类中断。

这不是重新使用一步下降、一步便宜、剩余轮数预测或短 Horizon oracle 标签。
B 的有界辅助项也不是数学上的成功率优先保证，仍须检查成功率和成本之间的取舍。

## 训练是否真正获得了新信息

| 诊断 | A | B |
|---|---:|---:|
| 非零信用轨迹 | 16/96 | 88/96 |
| 提供非零信用的训练地图 | 3/6 | 6/6 |
| 接受的参数更新步幅 | 0.25 | 0.25 |
| 平均状态 KL | 0.000644 | 0.000871 |
| 历史状态相同随机抽样下改变的动作 | 435/12,775 | 515/12,775 |

24 个训练条件中，18 个全部成功、两个全部失败、四个同时包含成功与失败。
A 只有混合条件提供梯度；B 还利用了成功轨迹之间的总成本差异。
但是全部失败条件仍没有相对信用，这条更新不能自动告诉模型如何解决从未成功过的难例。

两个更新的隐藏层权重均有 4,064/4,128 个元素改变，隐藏层偏置和输出权重也改变。
因此本轮不是又一次只更新零初始化输出头，但参数变化本身不代表泛化改善。

只读梯度诊断显示：A/B 更新方向余弦约 0.99784，夹角约 3.76 度；
辅助成本梯度分量的范数约为成功梯度的 6.66%。
更多轨迹提供非零信用，并不等于新增了很强的有效训练信号。
这个诊断不授权增加辅助权重；B 已经相对 A 丢失净成功，不能仅为放大信号而继续调系数。

## 整体配对结果

所有成本和质量统计只使用对应两方法共同成功的位置，失败不填为零。
负值表示 challenger 更低；修复次数、SOC 和 makespan 均独立报告。

| 对照 | 共同成功数 | generated nodes 均值：基准 -> 对照 | 节点变化 | 修复次数变化 | SOC 变化 | makespan 变化 |
|---|---:|---:|---:|---:|---:|---:|
| A 对 parent | 40 | 7,428,990.60 -> 7,356,280.05 | -0.98% | -0.28% | -0.14% | -0.82% |
| B 对 parent | 41 | 7,769,336.39 -> 7,550,628.59 | -2.82% | +2.02% | -0.08% | +1.10% |
| B 对 A | 40 | 7,356,280.05 -> 7,312,990.93 | -0.59% | +2.36% | +0.02% | +1.86% |

共同成功位置的节点更少/更多/相同分别为：A 对 parent 17/20/3，B 对 parent 20/18/3，B 对 A 18/15/7。
B 没有在多数指标上优于 A；省下少量低层工作同时多做修复，也未改善最慢车辆路径。
本轮不测墙钟，因此不能计算或宣称整批任务的交付加执行时间改善。

5,000 次地图级配对 bootstrap：

- A 对 parent 成功率差区间为 [-6.25, 12.50] 个百分点。
- A 对 parent 平均节点差区间为 [-751,461, 674,867]。
- B 对 parent 平均节点差区间为 [-950,493, 435,742]。
- B 对 A 平均节点差区间为 [-870,824, 724,495]。

三个节点差区间都跨零。B 和 parent 在完全相同的位置成功，因此成功率差的经验 bootstrap 为 [0,0]；
这是当前样本差值完全相同形成的退化区间，不是总体等效性证明。

## 判定与下一步

预登记开发信号要求：成功数不降低，且净成功增加或共同成功搜索节点减少至少 5%。

- A 满足净成功增加，保留为有限开发候选；置信区间很宽，不视为可靠晋级。
- B 未增加成功且节点仅少 2.82%，未达到本轮条件。保留弱成本信号，不将其夸大为有效新目标。
- B 对 A 只有约 0.59% 节点改善，却少一个成功，更不支持优先采用 B。
- 正式 decision 为 `development_signal_not_ttf`，默认策略不变，未启动计时。

下一项有价值的工作是冻结 A 与 parent，进行一次有预算的串行 TTF 对照，保留两档负载并完整记录成功率和路径质量。
不重复已经完成的工程加速测试，不先扫奖励系数或追加更新轮数，不把反复使用的开发图写成独立泛化。
若要得到独立结论，必须另外冻结新案例；本轮不自动启动该工作。

本轮仍未解决的核心问题是高耦合难例中的长期失败，以及成功率、低层工作量、控制开销和路径质量之间的取舍。
这不是要求方法每例全胜，而是避免把有限净成功或节点节省直接当作真实速度和全面可靠性改善。
