# H32选择器：独立episode覆盖的最后一轮有界检验

2026-09-17。用户允许继续多做非计时工作及小规模新标签采集。本轮新立协议，不修改上一轮的失败门槛。
旧512分支、两种模型的负面结论以及正式Dual16+SA均冻结；不运行TTF、RL或上线新控制器。

## 历史依据与不重复的边界

参考`SA_PAIRED_COMPLETION_PILOT_RESULT_ZH.md`、`SA_COMPLETION_CONTRACT_RESULT_ZH.md`及
`RESEARCH_DECISION_REVIEW_ZH.md`。上一轮只有16状态、8地图；每折14个训练状态，且仅8状态出现完成率差异。
全部35种trial划分交叉选优40.16%，仍低于随机40.82%；没有已证实的可靠选优收益。
路径分叉真实存在，但只有8.72%的配对分支在H32二元完成上不同。没有发现可以通过修正PP或指纹解决的错误。

这不能证明失败只是数据少，更不支持无限扩采。本轮只检验一个问题：
在同一批新状态上，旧14状态训练与42状态训练的两种固定模型是否有可复现差别？
新增的是来自不同episode的决策状态，不是对旧root追加trial；H、trial、特征、树参数全部不变。
这是对上一轮停止后的一次明确、有上限的样本覆盖检验，不声称提出新的模型机制。
若仍失败，停止本套H32二元完成、127维表格特征与GBDT组合的自动扩采/调参，不再追加第二批。

## 抽样和预算

- 固定seed 20260921，原8张已查看warehouse地图，每图4状态，共32。
- 排除旧H1采样、旧8根桥接和旧16根pilot涉及的全部episode。来源轨迹曾被整体查看，仍非独立确认。
- 只检查原决策前milestones 4/16/32/64/128；先取一个continuing、一个early，另两个按哈希补充。
- 每次先按episode哈希取一条，再在该episode的合格occurrence中按哈希取一项，避免长轨迹因有更多时间点获得更多抽中机会。
- 同一episode只取一个状态，不看后续成功、难度结局、模型/候选完成结果。候选仍为原动作加3个大小分组哈希挑战者。
- 任一地图不足4项或缺早/中后阶段就停止，不重抽seed、不用另一地图填补。
- 最多32×4×8=1024条新H32分支、32768次分支修复，另计reset、prefix及32个原动作对照。
- 使用旧冻结native与分支函数；同时最多20个分支进程。PP 5秒、分支120秒/2500万节点、进程fuse180秒、root fuse900秒。
- 这些是安全预算，不是TTF。先2root验证再同配置resume；中断半根需审计，禁止自动换困难来源。
- 不完整trial保留未知，禁止标成失败或删去；发生删失时本轮不训练新增模型。
- 所有全0/全1或完全平局状态保留，不因标签无区分度而删掉。每状态训练权重总和1。

## 先冻结对照，再采标签

在新标签生成前，用旧16状态完成8折留一地图的两种固定模型拟合并登记pickle SHA及训练ID。
每折只用旧7图14状态。它们对新32状态的预测不读新标签，也不称为已上线模型。
新增数据后，每折训练包含旧7图14状态加新7图28状态，共42个状态；整个待测地图及其所有新旧标签均排除。
两个模型始终为pairwise完成差和直接完成率回归，同127维特征、等状态权重及现有固定HGB参数。
没有static上下文、历史额外特征、一步下降目标、Cost-to-Go或剩余轮数预测。

只在新32状态上比较旧训练/新增训练，两套方法共享同一评价集；不能把旧16状态成绩和新32状态成绩直接相减。
基线为冻结动作、随机精确期望、样本内经验oracle。oracle有选优偏差，不作为可达到的真实上限。
同时报告全部35种对半trial的交叉选优及有区分状态的集合重合；35种划分不是35批独立样本。
源地图只有8张，更多状态不等于更多独立地图；地图bootstrap也不能创造新的结构泛化证据。

## 固定判定

对两种新增训练模型分别报告，不根据结果追加架构或选阈值。有限覆盖正信号需同时：

1. 相对冻结动作完成率提高至少5个百分点，5000次地图bootstrap区间下界不低于0，至少5/8地图严格改善。
2. 相对随机期望严格改善且地图bootstrap下界不低于0。
3. 相对同设计、旧数据训练的模型严格改善且地图bootstrap下界不低于0。

未通过不是证明所有学习无效；它意味着增加这一批独立episode没有让本数据/标签/表示组合获得可靠信号。
不因接近门槛放行；正负结果都禁止直接替换正式控制器。即便有信号，因两种固定设计均被比较、地图已查看，仍只是开发证据。
若只是直接模型有信号，不归功于pairwise设计。若新旧模型都不优于随机，不转向更多树、更长H、更多trial或救援机制。

## 执行与交付

入口`scripts/run_sa_state_coverage.py`：prepare、dry-run、collect、analyze、fit-evaluate、verify、request-stop。
准备阶段在Windows现有sklearn1.5.0训练旧数据对照；采集和路径核验使用冻结WSL native；新增模型训练回到Windows。
输出`build/sa-state-coverage-v1`，只存本地；源码、模型对照和结果分阶段备份。原正式结果/native/model SHA不变。
准备不足会停止，运行错误会暂停定位；科学门槛失败不会触发无预算下一轮。
