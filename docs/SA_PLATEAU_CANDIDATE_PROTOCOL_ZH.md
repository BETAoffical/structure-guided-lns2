# SA末期候选检查：固定三个状态

本轮仅回答：当前已有候选是否存在被最高分遗漏的一步修复机会。不更改Dual16、模型、候选、SA或原PP，不做TTF，不增加整场预算。

## 历史边界

稳定4车候选曾使40降到39，但八次64步延续全部停在39；因此一步下降不是脱困。
五路选择/接受实验支持选择覆盖局限，但不同初始轨迹的成功不能证明末态换一个邻域就能恢复。
本次是300秒诊断中三个map0006持续平台的直接同状态检查，不重跑上述实验，不据此上线随机探索。

## 冻结对象

- 来源：`build/sa-pressure-300s-diagnostic-v1`，报告SHA为`b5d18477c724fc7b867fa45995cd691e2f9c5f24dfff53388bd041e6eb492945`。
- 三个来源：b445d1b1b944/seed62、b87d6a85480a/seed61、b87d6a85480a/seed62。
- 每个取第一条记录完成时间达到120秒的决策之前状态，不根据候选修复结果挑状态。
- 保留当时全部候选、成员、最高分、温度与接受draw。四个新PP-order种子按状态/trial确定，候选之间配对；固定draw以隔离PP随机顺序。
- 每状态另有一个原动作、原seed、原draw控制分支，要求完整科学状态和PP尝试复现。
- 三个状态仅来自一张已查看地图，不能作三个独立地图或总体泛化证据。

## 执行与预算

完整prefix重放逐步验证fingerprint和PP尝试，重新生成池并逐项校验成员、分数与选择。
仅在单线程Linux父进程中fork，继承完全相同的native状态；每个子进程独立执行一次修复，无状态回写。
这避免为每个候选重复重放数百次动作；不使用reset_paths冒充完整重放。
最多20个进程，每次PP限30秒，子进程硬上限90秒；超时为未知，不能认定不可行。
父进程全局环境上限仅防止历史300秒预算妨碍重放，不是新计时预算。
每个分支原子保存，支持resume，`STOP_AFTER_JOB.json`阻止启动新分支，等待已运行分支结束。
准备阶段输出准确候选、分支、重放步数。预计约10至25分钟，主要取决于重放与校验，不是求解速度预测。

## 解释

报告候选覆盖、非冲突填充车辆、末期选择重复率、四trial剩余冲突、一步可行及删失。
有替代候选清零是局部选择缺口的直接证据；只有下降则仍需另立有预算的延续验证。
全部候选无收益只是否定这些状态/随机流的一步机会，不能证明所有路径和顺序都无解。
报告保留原动作重放、进程隔离和科学字段检查结果，不自动训练、修改或晋级。
