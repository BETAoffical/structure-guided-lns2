# 双轨按已消耗节点调度：只读准入核算

2026-09-14。只读取已有独立双轨16案例，不启动solver、训练或计时。

## 与停止方法的区别

[原独立双轨](SA_INDEPENDENT_LANES_RESULTS_ZH.md)全部16案例可行，但一比一修复调用分配多消耗14.83%节点。其后续边界明确留下了按已消耗节点分配的假设。本轮不改变邻域排序、SA、贪心、PP或任何单轨动作；不是HistoryRank、停滞救援、温度调参或重训的重启。

本轮只回答：固定调用次数交替的成本失衡，是否可被一个不看未来的节点调度规则缓解？它不能证明解决当前120/300秒残余难例，因为来源是旧239--299车、初始9--41冲突的开发任务，native和运行时也不同。

## 唯一新规则

- 两个独立轨道仍是`rank_sa`和`uniform_greedy`，各自保留本地decision和原随机流。
- 每次选择累计已执行generated节点较少的轨道；相同时先选已执行次数较少者，再相同时先选模型SA。
- 只在一次完整修复后计费，不预读下一次修复的节点数、冲突数或是否成功。节点零增量不能产生无限循环，仍受总调用上限约束。
- 共256次调用，沿用旧预算。任一轨道实际执行到可行即停止，未完成预算不能虚构成功。
- 全部已执行工作都计费，包括最后未获胜的轨道。单步可能很贵，因此不声称严格等节点配额，也不将256次调用称为固定总节点预算。
- 源前缀不足时结果未知，不跳到另一条轨道，不补标签，不运行新分支。

## 数据与校验

固定`build/sa-independent-lanes-v1`两轮、八地图、seeds19/23，不挑案例。校验plan、两轮报告、analysis SHA和48个单轨/原双轨文件SHA；复核初始配对、冲突链、generated累加及原双轨的已执行科学字段与单轨前缀一致。

先用相同离线调度器的一比一模式复现旧双轨337次调用、9213999节点、16成功，再计算唯一新规则。不能降低文件身份门槛来通过复现。已有源路径合法性验收按冻结文件SHA复用，不重新做全路径物理审计。

## 固定判定

分别报告两轮与总计，不扫描比例或更换开始轨道。沿用旧开发机制数值标准：

- 成功数不低于两个单轨，且没有原单轨成功案例损失；至少恢复一个模型SA失败案例。
- 总调用至少比均匀贪心少5%，总generated不超过均匀贪心的110%。
- 两轮成本标准都满足；源完整且没有预算未知。

通过只记为`eligible_for_separate_native_protocol`，不自动开新求解；失败停止此无参数节点均衡规则，不在原案例扫描比例、温度或启动顺序。原一比一双轨FAIL不改变。

这是在已经看过的数据上提出的新调度核算，属于事后开发分析，不是新独立确认。即使通过，也需要独立真实执行协议来验证轨道暂停、墙钟截止、初始化/双环境开销。节点数不是TTF；历史均匀轨道仍计算模型分数供审计，不能据此得出无模型部署速度。
