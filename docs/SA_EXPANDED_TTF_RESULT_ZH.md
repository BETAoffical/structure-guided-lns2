# 冻结模型四方法扩样：12张新仓库地图TTF结果

## 结论

2026-09-29完成：72/72初始规划准入、288/288四方法预检、288/288串行计时、288/288计时外审计，零实验错误。
本轮没有训练、修改模型或PP/SIPPS，没有更改候选、SA或工程运行时，没有重跑不利结果。

**本批A相对父模型出现了明确的正向TTF证据，主要来自较高密度任务；不等于所有任务更快，也不等于长尾已解决。**
A成功69/72，父模型66/72。在65个共同成功条件上，平均TTF由20.9861降至17.9123秒，下降14.65%，
地图级配对差值95%区间为[-5.389,-0.741]秒。A更快33个、更慢32个，优势来自改善幅度而非逐例压倒性胜率。

A相对Official和Official+SA的共同成功TTF分别下降27.03%、22.21%；成功数分别为69对65、69对69。
但A的makespan仍更大，按每步1秒的整批完成模型，相对Official+SA均值反而增加3.11%，区间跨零。
因此成果应限定为**本批新同族仓库任务中的首次可行规划效率**，不能写成实车执行更快或跨布局通用提升。

此前12图确认中A比父模型少成功1个、TTF差值区间跨零，旧结论保留。本批不能倒推旧实验其实通过，
也不把已查看的多批数据直接合并成新的独立确认。现在不再为本批数据重训或加入事后负载路由。

## 长尾、失败与开销解释

19个未解episode全部用完120秒规划预算：12个在PP内到期，7个在外层到期；没有进程保险终止、崩溃或身份错误。
最大软预算越界约0.083秒。最大实际决策2861次，123个episode超过256次决策，52个超过2500万generated nodes；
因此历史归一化常量没有变成运行上限。

在A对父模型的65个共同成功条件上，平均选择开销由4.275降至3.676秒，native PP耗时由14.045降至11.753秒，
决策数由112.4降至98.14。由于运行时代码冻结，这是访问轨迹/修复工作量变化，不是本轮又换了一个更快PP。

所列分项不是完整加和拆解，原生调用包装等其他开销仍包含在真实TTF中，没有事后扣除。

Official+SA相对Official在本批净多成功4个，d20平均TTF变慢19.39%，d25共同成功平均快16.07%。
这支持退火收益随负载变化，不能说“SA每次都快”。这也只是登记的整套实验SA与标准接受机制的比较，
不是新模型自身的有/无SA消融，更不是完整复现CPLNS并行与重启的因果结论。
