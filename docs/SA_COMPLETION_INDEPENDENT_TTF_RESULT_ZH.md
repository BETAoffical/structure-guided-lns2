# 冻结父模型、更新A与Official+SA：12张新仓库地图确认

## 结论

任务准备故障已修复，48/48初始规划、144/144三方法准入、144/144计时和144/144离线审计全部完成，零实验错误。

本轮支持父模型和A在同族新地图上的首次可行规划速度优势，但不支持将A升级替换父模型：
父模型成功45/48，A为44/48，Official+SA为42/48。
A相对父模型在44个共同成功条件上的平均TTF下降3.00%，地图bootstrap区间跨零，而且少成功一个条件。
两种学习策略的makespan均比Official+SA更大，不能把规划速度优势写成整批机器人更早完成任务。

本轮没有训练、调参或改动native、PP、候选、选择器、退火。父模型为raw-1，A为completion-only更新；
它们不是本轮新训练的模型，也不能把父模型标签替换成Dual16或V2。
基线为同机制Official Adaptive + SA，不是未加SA的Official。

## 数据与口径

- 12张新生成的station-centric仓库地图，24个独立静态OD任务，solver seeds 271/277，共48个条件。
- 每条件串行运行parent、A、Official+SA，六种执行顺序均衡轮换，总计144个episode。
- 每episode规划预算120秒，外部保险240秒；没有决策次数或节点数上限。
- TTF从reset前到首次返回无冲突状态；交付时间另外包含最终路径检查和保存。
- 科学轨迹审计、完整轨迹压缩在交付之后，不计入TTF；模型加载与进程启动另记。
- 成功率分母始终48。时间和路径质量在共同成功条件上配对，不给失败填零或120秒惩罚。
- 置信区间为5,000次地图级配对bootstrap，差值方向为“目标方法减基线”。
- 新地图与历史map/task seed及地图SHA隔离；仅支持同族新地图，不是跨布局或真实机器人实测。

没有进程保险超时、崩溃或丢失记录。最大软预算越界约0.069秒。

## 解释和下一步

1. 准备故障已经解决，不能再把端点采样失败解释成模型或求解器失败。
2. 学习选择有实际规划价值：例如A对官方SA的共同成功集，native PP平均耗时由21.26降至13.07秒，
   虽增加约4.03秒选择开销，最终TTF仍下降。这是记录到的开销分解，不是更换PP或审计口径产生的收益。
3. A的增量证据不足：相对父模型只减少约0.72秒平均TTF，区间跨零，并损失一个成功条件。
   目前保留父模型为默认对照，A作为负载相关候选，不自动晋级或继续无边界重训。
4. SOC接近而makespan变大，说明总路径消耗与最慢机器人路径不能混为一谈。
   首次可行选择与SA接受没有直接优化最大路径长度，这与现象一致，但还不是具体失败的因果证明。
5. 后续应优先审查A独有失败的M01-d25-s271，以及少数makespan显著增加条件的冻结轨迹，
   再决定是否需要改变训练目标；本轮没有据此追加实验、选择门控或重新训练。
6. 本轮为新同族仓库地图确认，仅一个120秒预算、两个solver seed；不恢复静态上下文迁移或跨布局普适主张。
