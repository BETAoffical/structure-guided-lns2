# 完整邻域内的路径恢复：预登记协议

## 范围与备份

恢复点为 `pre-full-neighborhood-recovery-20260910`，指向 `cbeab1d168afbc7d4edc328213491fb1a91f0730`。
实验分支 `codex/initlns-full-neighborhood-recovery`；冻结 Official/V2/Dual16、模型和正式 native 不覆盖。
只使用已允许作为开发证据的压力轨迹，不读取封存 Test/OOD 标签，不训练模型。

本次批准的是有条件的完整流程：机制门槛通过后才继续原生事务集成、完整测试和有限串行计时。
授权计时不等于跳过门槛。未通过时分析失败并完成独立验证，不增加 trials、预算或更换主方法。

## 数据

保留六个旧锚点。从相同四张地图的其他任务选择最多十八个状态，总计最多二十四个。
按失败长尾、成功停滞、快速对照及地图/控制器分组轮转，组内按固定哈希排序。
同任务不重复抽取其他 episode；相同路径/冲突结构的状态去重，不把克隆状态计为独立证据。
不足二十四个不同状态则报告证据不足，不补抽使结果更有利的案例。

从原压力任务剩余四张地图，各按固定哈希选择一个 balanced 和一个 bottleneck 任务，
保留为最多八个闭环任务。选择只使用地图、任务语义和哈希，不使用新方法结果。
这些仍是开发性闭环任务，不是从未被研究过的独立跨布局确认集。

## 原始邻域与恢复动作

每个状态冻结历史实际邻域和完整 PP 顺序，使用两个预登记 seed：20260912、20260913。
所有普通及替代搜索使用原核心 SIPP 的软 CAT，不把外部路径改成硬障碍来冒充 InitLNS PP。

普通 PP 按原有冲突对接受上限运行；允许中间状态存在冲突。
仅回滚或接受后路径完全不变时触发恢复；等冲突数但路径改变不触发。
对失败插入提取已规划内部阻挡车。接受但不变时只研究首个冲突插入。
最多检查两个内部阻挡关系，后车暂时忽略其中一辆内部车形成参考路径，
由参考路径与该车路径之间的冲突形成时空约束；不读取事后成功见证。
只能回退一层，复用该车之前的有效路径前缀，按原顺序重算该车及后续车辆。
约束车辆的成本不得超过普通尝试的成本；外部路径完全不变。
只有替代分支完成且全局冲突严格下降，才接纳恢复结果，否则保留普通分支结果。

固定四种方法：普通 PP、最多四次随机 seed 重试、最早四个不同事件、最多四个不同阻挡资源。
主方法预先指定为 `directed_resources`；资源键为阻挡车、顶点/边类型与位置/有向边，
每个资源只取最早事件，避免同一格子的相邻时刻耗尽全部尝试。
其他方法是对照，不允许主方法失败后改选其中的胜者作为本次成功。

## 预算与隔离

- 最多 48 个普通 PP parity 作业和 192 个机制作业，最多 20 个独立进程。
- 可用内存低于 3 GiB 时停止新增 worker；记录实际并发和每个 worker 峰值 RSS。
- 机制作业搜索预算 30 秒，单次搜索最多 5 秒，进程保护上限 60 秒。超时为未知，不当作无解。
- 每个方法从独立进程中的相同快照开始，随机重试与正式控制器不共享进程随机流。
- 这里的额外 Python 编排不是线上事务集成；即使机制通过，也不能立即称为可部署修复器。
- `STOP` 文件或中断信号停止派发，并完成活动作业后暂停；结果原子写入，续跑检查全部身份。
- 单轮采集会话最多两小时，整个开发执行计划建议上限十小时，预留收尾时间。
- 不把并行诊断的耗时解释为真实 TTF。不会为了达到并发数运行重复 collector。

## 门槛

先要求全部状态的两 seed 普通 PP 与冻结 native 在最终路径、回滚、尝试冲突数、车辆数及逐车诊断上一致。
这不是对未提交中间路径的逐格等价证明，不能扩大表述。

机制门槛同时要求：

1. 二十四个不同状态、全部配对作业完整，没有非法路径、身份错误、未知预算结果或配对普通基线差异。
2. 主方法至少三个不同状态在两个 seed 下均新增恢复，涉及至少两张地图。
3. 至少一个新增恢复来自失败长尾来源。
4. 稳定恢复状态数不低于随机重试，且至少两个状态仅主方法恢复、随机重试未恢复。
5. 所有提交的路径均保持外车不变，Python 与冻结 native 校验一致。

通过只允许进入原生事务与运行时测试，不允许默认替换或声明 TTF 提升。
失败后输出内部反馈不足、外部阻挡、成本约束不可行、替代仍冲突、预算未知等分类。
完整失败类别不等于联合无解证明，也不自动授权加入外部车辆。

## 条件性闭环安排

只有机制和原生事务测试通过并完成远端预登记，才运行八任务 x 两 seed x 四方法，共六十四个 episode。
方法为 Official、V2、Official+恢复、V2+恢复；必须单 worker，方法顺序均衡轮换。
规划预算 120 秒，外部保护 180 秒，不限制修复次数；主时钟从 reset 前开始至有效路径交付。
额外恢复和校验开销计入真实 TTF；冷启动和模型加载另列。
成功数不降低才比较共同成功的原始 TTF；失败单列，P90/P95、小样本和地图级区间如实报告。
部署或扩大验证不能只依据局部恢复率；本轮没有无条件的计时入口。
