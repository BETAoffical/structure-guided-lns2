# 退火降温与停滞的已有轨迹审计

只读分析，不启动solver、不生成新修复标签、不修改温度、候选、模型或PP。
本轮先检验是否存在“低温拒绝大量变差尝试”的暴露证据，不从观察轨迹推断被拒绝分支的未来价值。

## 数据边界

- 原120秒完整高压力组：96条Dual16+SA轨迹，包含成功、超时和可能的零冲突任务。
- 原300秒失败并集组：11条Dual16+SA轨迹，单独报告；与120秒组有重叠前缀，绝不合并成107个独立样本。
- 复核注册输入、报告/manifest/逐episode文件SHA，以及初态、末态fingerprint。
- 结合历史9次拒绝的18个反事实分支报告及最新三状态候选审计解释，不重跑它们。

## 固定分析

- 按决策次数0--99、100--499、500--999、1000以上分组。
- 按当前冲突1--5、6--20、21以上分组；按连续未改善历史最低冲突的步数0--31、32以上分组。
- 分别报告完整PP、变差尝试、接受/拒绝、概率低于0.01、严格下降、历史最低改善和等冲突步数。
- 记录接受变差后的4/16/64步是否降到变差前水平以下；后续不足且未结束的记为右删失。这是现有策略上的描述，不是接受的因果收益。
- 单独统计物理路径状态不变、历史物理状态重复，以及相同物理状态与候选组合重复。
- 物理身份由地图、agent ID与完整路径、冲突边组成，排除iteration、低层计数和runtime；仅供分析，绝不替换正式fingerprint或proposal随机种子。
- 物理身份使用路径哈希增量更新，并测试其与全量重建等价；不把同候选ID直接判为同状态。
- 成功/失败分别统计，但明确这是结果条件化的描述，存在长度偏差，不能证明降温导致失败。

## 判定与停止

大量低概率拒绝仅支持“接受层可能限制探索”，不证明提高温度会成功。
若主要是无变差尝试或物理状态不变，则不推荐单靠调温。
若两者并存，报告机制混合；不事后挑温度、改门槛或启动新变体。
历史拒绝曾保护成功轨迹，不能直接改成无条件接受或反复回温。
只有充分理由才另立一个固定小变体和闭环协议；本轮默认停在报告，不自动计时。

## 执行

`python scripts/audit_sa_cooling_traces.py prepare`登记后，使用`run`分析；已有输出须显式`--resume`，错误不自动重试。
只读作业使用最多20进程，逐episode原子保存、运行锁、进度与300秒作业安全上限；不加载或调用native求解器。
输出到忽略目录`build/sa-cooling-trace-audit-v1`，旧正式数据保持不变。
