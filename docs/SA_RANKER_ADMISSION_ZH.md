# SA适配排序器：重启准入与目标边界

2026-09-14。状态：`not_admitted_for_collection_or_training`。

本轮完成协议设计前的历史与逻辑复核，不运行求解器、不采集、不训练、不计时。复核后的决定不是自动安排下一轮H4/H32采集：仅有“使用退火数据”还不足以重启已停止的长期排序与反馈方法家族。

## 1. 当前到底缺什么

当前Dual16+SA有三个不同环节：

1. 生成实际agent邻域，包含原V2候选及Dual16结构候选。
2. 冻结GBDT根据当前状态和实际集合排序，选一个邻域执行PP修复。
3. 完整修复后，按冲突变化和温度决定接受还是回滚。

`SingleFullCheckPool.select()`调用`realized_rows()`和`score_online_candidates()`；当前排序输入没有显式温度、历史最佳差距或重复尝试反馈。温度作用于后续接受，不是另一套候选排序模型。冻结模型身份继续以原portable artifact SHA为准。

因此存在合理但未证实的假设：原排序器可能不适配非单调搜索的状态分布或动作价值。不能从“没有温度特征”直接推出其全部长尾由此造成，更不能据此断定加特征、重训或RL一定有效。

## 2. 为什么只换成退火数据仍可能走回老路

令当前冲突数为C，某次完整PP尝试的冲突增量为d，温度为T。当前SA接受概率为：

```text
p(d,T) = 1                         if d <= 0
         exp(-d/T)                 if d > 0 and T > 0
         0                        if d > 0 and T = 0
```

拒绝时旧路径保留。忽略耗时，并条件于这一完整尝试，接受后冲突的期望为`C + p(d,T) * d`。

- 只产生上升的动作，对一步冲突目标有非负代价；有正接受概率时为正。
- 只产生相同冲突数的动作，一步代价为零，即使其路径空间位置完全不同。
- 因而一步目标无法表达“先上升，之后更容易清零”的价值。

这只是一步目标的信息边界，不是现有模型必然选择错误的证明。真实候选有PP-order分布，也可能同时包含下降与上升结果；应对整个分布求期望，不能用一个trial替代。可行率、耗时及后续状态也不能从上述单个式子推出。

由此排除三个直接方案：把SA接受动作当正标签；把温度加入原一步排序后就宣称解决长期问题；把曾失败候选永久禁用。接受不等于有益，重复不等于无效。

## 3. 与已失败工作的逐项对照

| 提议 | 最近似的最终证据 | 本次判断 |
|---|---|---|
| 记住成功集合，重复时优先选它 | SA准备度：正反馈可用决策206/11562与93/11019，原排序已选202/206与90/93；复用后下降未刷新历史最低值 | 不能把精确反馈复用当作主要遗漏机会 |
| 失败次数、新颖度、换下一名 | HistoryRank及Feedback Exploration；反馈未优于随机，干预有恢复也有损害 | 不改名重做阈值或规则搜索 |
| SA访问状态上继续训练一步GBDT | 旧policy-visited聚合未晋级；新SA候选标签仅3状态、1地图 | 可以提出分布适配假设，但不能直接称为长尾修复方案 |
| 将H4改为H8/H32并多跑trial | 旧H4有oracle机会但split-half稳定性不足；Compact-Blocker短期收益未持续 | 改长度、数据源或预算本身不消除旧失败原因 |
| 冷却后重新加热 | 有限回温：主要12配对分支完成数均1/12，局部冲突改善未转为新增完成 | 不追加温度/触发参数网格 |
| 增加树、图模型或RL | 容量、图表示、长期标签门控未过 | 先有适当监督信号，不能用更复杂模型替代问题定义 |

上述均是开发证据边界。不能把三状态结果外推为所有SA候选无效，也不能把停止某一实现写成理论上不可能改进。

## 4. 如以后重启，必须分开的两个问题

### A. 分布适配：SA状态上的一步排序是否失准？

输入仍是当前动态状态与实际邻域；同状态全部候选经独立PP-order trials得到标签。它最多回答一步排序是否改善，不能单独证明减少长尾。已执行动作轨迹只能描述访问分布，不能填补未选动作真值。

若只研究这一问题，应明确把成果限定为SA分布上的一步排序；不能一边使用一步标签，一边以“学习脱困”解释模型。现阶段不批准为这一有限目标新增一整套采集。

### B. 序列价值：是否能识别值得接受短期代价的候选？

这是与成功率和TTF直接相关、但尚未满足准入的问题。需先给出一个具体的前置可见信息或表示假设，解释它为何能够区分有益探索与只返回旧水平的循环；不是只列温度、停滞计数几个字段。

后续观测可以作为标签，不能作为在线特征；到达可行解的概率或有界持续收益必须明确预算、截断、随机性与估计误差。不能把remaining repair rounds、Cost-to-Go或重命名的旧H4目标直接引入。预算结束仍有冲突是该预算内未成功，不是整个MAPF不可解。

当前没有证明新表示解决了旧标签稳定性问题。因此不指定一个看似精确的H值、样本数和通过率来掩盖这个缺口，不实现collector，也不预授权“失败再换一个目标”。

## 5. 重启时的固定数据与实现合同

以下是必要条件，不代表采集已经获准：

- 冻结PP、候选生成、排序基线、SA温度日程和native；不能同时改接受与排序后混称模型贡献。
- 记录具体访问发生位置`episode + decision`及完整prefix。相同路径状态在不同历史或温度下不能只保留第一次出现，否则可能再次把历史特征变成常量。
- 历史特征只能查询决策前记录，缺少历史记为未知；完整不下降、被拒绝和截断分别记账。
- 重放同时核验物理状态、计数、候选ID/agent集合/来源和历史累积；仅路径fingerprint一致不足以证明历史输入一致。
- SA温度沿原episode绝对decision继续，不能在每个反事实分支重新从高温启动。
- 候选trial使用同一预登记随机化方案，PP和接受随机流分开；相同seed是配对随机化，不保证不同agent集合得到相同相对规划顺序。
- 不把一个候选的结果强行拼接到另一个候选或旧H4轨迹后。分支后续必须来自对应实际状态和冻结策略。
- 来源包含自然成功与困难任务；不只挑事后失败，不用历史120秒/300秒重叠来源扩大独立样本数。开发诊断与未来未见地图确认分开。
- 地图是分组验证单位。相同状态的候选、trial和同一地图的任务不能横跨训练与验证；trial不是独立地图样本。
- 最多20进程用于非计时标签工作，按内存/完整PP开销降低并发；任何真实TTF确认仍单worker。并行耗时不得充当单worker性能。

可复用已有prefix、候选、路径校验、原子结果与运行锁实现，不另建一套执行框架。`audit_sa_training_readiness.py`是只读工具，不应通过添加隐含solver调用变成collector。

## 6. 决策与下一步

1. **保留Dual16+SA及已有正结果。** 本次不改变任何默认策略、模型、PP或正式结论。
2. **暂不直接重训，也不新跑长期反事实。** 原因是目标与方法差异未过准入，而不是算力不够或要求每个案例都更好。
3. **重启前只需一个可检验的新假设，不需要更大的实验计划。** 必须说明：新增何种决策前信息，旧方法为什么没覆盖，正负结果会怎样改变采用决定。若无法回答，就不运行测试。
4. **一旦有符合条件的具体方法，再冻结小pilot。** 同时登记状态/trial/节点总上限、截断处理、最多一次有定位依据的实现修正；之后才谈训练及独立闭环。新门槛可允许少量案例退化，但必须报告总体净收益、不确定性和尾部风险，不能事后改旧PASS/FAIL。

本次资源预算：新增solver调用0，新增trial 0，训练0，TTF 0。没有等待中的自动任务，也没有因本协议自动获得采集许可。
