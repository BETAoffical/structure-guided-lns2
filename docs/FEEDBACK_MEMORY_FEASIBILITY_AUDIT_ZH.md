# 候选反馈记忆的作用范围审计

## 结论

本轮只读取已有轨迹，不调用求解器、不训练、不改变控制器或正式结论。
64/64条V2/Dual16轨迹、1,611个transition的SHA与状态链核验通过。
使用20个独立分析进程。正式计时报告SHA保持不变。

**发现了值得继续验证的修复条件键，但没有证明反馈控制器有效。**
不能只按agent集合累计失败，也不必先假定只有全部旧路径相同才可复用经验。

## 为什么需要补充第三种键

第一版对照了“集合+冲突边”和“集合+全部路径”。前者可能混合外部环境变化，
后者可能包含低层搜索已经不再使用的旧信息。检查InitLNS源码发现：

- `third_party/mapf_lns2/src/InitLNS.cpp` 在约377-407行计算涉及选中集合的旧冲突对，
  保存旧路径，然后把全部选中路径从PathTable删除。
- `runPPWithoutDiagnostics` 从剩余PathTable建立ConstraintTable，逐车重新搜索；
  用旧冲突对数量决定提前失败和是否接受，旧路径还用于回滚。
- 因此增加第三种**可见修复问题键**：实例/地图身份、选中agent及其起终点、
  所有外部agent的路径、涉及选中集合的旧冲突对数量、请求动作协议。
- 三种键都在每条episode内部使用，不跨实例或控制器合并。
  随机seed不进入键，用于讨论同条件下的随机尝试，不是确定性结果缓存。

此键尚未证明涵盖native内部全部影响：PathTable历史存储、搜索平局、缓存、
剩余时间和执行顺序等仍需验证。本文不把键相同写成“搜索结果必须相同”。

这些是轨迹中的尝试次数，不是独立样本数，不构成成功概率或可避免开销估计。
870次不意味着870次都可以安全跳过。未下降的尝试也可能改变后续可选动作。

如果把浮点请求PP预算也要求逐位相同，所有键的重复次数为0，因为剩余预算变化。
忽略预算的数字是机会清单，不是直接可用的反馈统计。1次截断保留，不当作普通负标签。
不能简单把所有未超时任务的不同预算称为等价，需单独检查低层截止语义。

这说明“路径一直变，所以不能复用任何反馈”过于保守；也不能反过来说问题已经可解。
以往候选机会诊断仍然成立：09/22存在一步清零候选；13已测候选没有一步清零见证。

## 与历史失败方案的边界

1. 不是重复次数触发器：次数本身不能判断状态是否不可恢复。
2. 不是禁忌表：全组仍有同条件失败后成功，不能永久屏蔽。
3. 不是按seed/rule/size记账：显式成员、外部路径和接受上限必须绑定。
4. 不是用事后标签模拟新闭环：本报告只观察原策略真正选择的动作，
   不把离线未选动作结果拼成一条虚构轨迹。
5. 不是证明等冲突路径变化无价值：即使不改变这一个集合的修复条件，
   它仍可能改变其他候选、排名及其外部约束。

## 下一步的唯一准入任务

先做有界的**修复条件等价性验证**，而不是直接运行反馈控制器。

- 在已有重复组内，固定集合、外部路径、起终点、接受上限、执行顺序、随机seed和
  足够且一致的单次预算；对比不同选中旧路径与不同历史prefix。
- 检查冻结native的路径、冲突、接受/回滚和搜索行为；分别处理正常结果与截断。
  旧路径不同意味着回滚后完整状态不同，不能以全状态指纹相同为验收条件。
- 把外部路径改变、接受上限改变作为键失效的负对照；不要求负对照一定产生不同结果。
- 若同键结果仍受未记录的native历史影响，先明确原因，不改官方平局或排序逻辑来
  强行制造等价，也不将本报告复用次数当成在线可用证据。
- 只有作用范围成立，才预注册“冻结偏好+有限反馈探索”与同预算随机探索、原策略的
  闭环对照；不永久禁用，不只探索排名前二，不按本批结果反复调整阈值。
- 准入验证失败即停止本实现扩展；不自动重训、扩大邻域或追加正式TTF。

TACKLE提供了非平稳在线反馈的设计动机，但其anytime成本优化结果和渐近理论不能
直接迁移成InitLNS保证。本轮没有复现TACKLE，也没有新增论文级正面结论。
