# 固定60+60重启核算：不宜直接用于当前SA策略

2026-09-21。固定方案登记提交 `487839a`；源结果此前已查看，因此本轮为回顾性预算核算，不是独立确认。
没有调用求解器、训练模型、执行正式计时或修改控制器。

## 1. 核算结果

8张已查看仓库地图、48个相同静态任务、seed 61/62。
每个任务都计算61先62后、62先61后两种固定顺序，等权汇总；**96个有序条件不是96个独立任务**。
首段60秒内成功即结束，否则耗满60秒后换seed，第二段TTF包含重新初始化，最多再60秒。

| 方法 | 原连续120秒完成 | 条件核算60+60完成 | 新增 / 损失 | 原封顶时间均值 | 核算封顶时间均值 |
|---|---:|---:|---:|---:|---:|
| Official Adaptive | 89/96 | 90/96 | 2 / 1 | 21.2276秒 | 21.3852秒 |
| Dual16 | 67/96 | 72/96 | 8 / 3 | 48.6081秒 | 47.0744秒 |
| Dual16+SA | 89/96 | 86/96 | 0 / 3 | 22.6728秒 | 23.6744秒 |
| Official+SA | 93/96 | 88/96 | 0 / 5 | 20.5594秒 | 22.6629秒 |

封顶时间是成功用TTF、未完成用120秒的预算统计，失败原始TTF保持null。
Official+SA来自不同批次，不用本表作同期真实速度排名；各行内都是同方法的固定日程对照。
核算假设历史前缀保持、额外切换开销为零。真实60秒deadline可能改变PP行为，本表**不是实测重启结果，也不是严格物理上界**。
主时钟为reset前到首次可行，不含冷启动/模型加载/最终路径交付；没有推断机器人整批完成时间。

## 3. 为什么没有修好当前SA尾部

Dual16+SA的7个原失败条件中：

- 4个来自两个任务的双seed都失败，另一个seed没有已观察到的成功可用。
- 另3个的伙伴seed确实能完成，但TTF分别为96.226、109.539、73.722秒，都超过重启后剩余60秒。
- 因此该固定预算下0个原失败被恢复；同时提前丢掉3个原本会在60秒后完成的条件。
- 损失集中在地图0004的一项和0006的两项，不是大量轻任务计时噪声压过了成功率收益。

这说明**另一条轨迹可能有解，不等于剩余预算足够再走到它的解**。
不能把当前问题全归于“一次随机种子不走运”；也不能反过来证明更多seed、不同预算或别种重启机制永远无效。
本轮没有证实剩余失败的唯一根因是邻域成员、路径顺序、SA温度或外部占位。

## 5. 决定与后续

1. **当前Dual16+SA不加入固定60秒重启，不启动其正式重启计时。** 已有核算无恢复且误伤晚成功，暂不值得付出运行时改造和长时间试验成本。
2. 无SA Dual16的弱正信号保留，但没有证据支持放弃当前SA、回到明显较低的完成水平；不自动投入该旁支。
3. Official多完成一项但时间账本略差，是取舍而非“什么都无效”；不用于替本项目新选择器宣称改进。
4. 不修改截止时间、不添加seed搜索、不拟合重启器。下一次算法实验须提供新动作前信息或真正不同的搜索机制；旧历史、晚期、续跑对齐、第二核和容量链的停止理由见[证据总账](RESEARCH_EVIDENCE_STATUS_ZH.md)。
5. 生产模型、PP、SA和正式结果保持不变。本轮价值是以已有证据排除一个不值得直接实装的固定方案，而不是增加一个晋级算法。
