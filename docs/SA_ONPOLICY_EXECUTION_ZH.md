# 自身轨迹策略学习：有界实现协议

2026-09-22。承接[设计](SA_ONPOLICY_DESIGN_ZH.md)，不修改设计阶段的禁止执行配置。
本文件及`configs/sa_onpolicy_execution.json`是用户继续请求下的独立实现登记，不改历史结果。

## 保持固定的内容

129维输入、小型残差actor、0.1探索、两次SGD更新、256次修复/2500万节点预算，均沿用设计。
完整候选池沿用Dual16；原V2、Dual16评分器、PP/SIPPS和SA不修改。
六张Train、两张已查看留出图，不称独立验证；不读取留出结果选择checkpoint。
最多192条训练、64条开发评价；20独立进程，所有多进程耗时不称TTF。
工作预算在修复边界检查，单次PP可越过节点阈值；记录实际值。

Official+SA保留`mode=official`，不设置逐步random_seed、不调用学习策略的proposal。
它的replica以独立SA接受流区分，不声称与显式动作有相同PP顺序。
三个显式动作方法使用配对PP/SA流；选择器流独立，生成时不消耗PP/SA流。
不同训练轮必须用新随机流；评价四方法用同一组环境流标签，标签不含方法名称。

## 实现与运行顺序

1. `prepare`封存MAPF文件、旧模型、冻结native、源码、配置与既有六/二地图划分。
2. WSL `qualify`执行32次reset。只有Train初始状态产生归一化输入；留出仅登记初始fingerprint。
3. Windows现有`build/venv-graph`执行`initialize`，仅初始化未训练actor，不使用旧标签。
4. Windows `parity --torch`与WSL `parity`核对概率误差不超过1e-12、固定draw下动作完全一致。
   这不是宣称不同BLAS逐位浮点相同。WSL `micro`验证四方法、零残差对照、重复性与安全截断。
5. WSL `collect --round 0`、`audit --round 0`；Windows `update --round 0`仅做一次更新。
6. 对actor1重做跨平台parity，完整采集并核验新一批，再进行第二次更新。
7. actor2冻结并验证后，才执行`collect --evaluation --round 2`、`audit --evaluation --round 2`、`report`。

每步入口独立，不提供会自动掩盖错误的无限重试。代码或native变化时原登记拒绝续跑。
暂停入口是`stop`，已开始的一批最多20个episode结束后停止发新任务；`--resume`明确恢复。
成功receipt与内容SHA必须匹配。不完整目录、已登记外部超时或软截断禁止静默重试或忽略。
整批有删失则不更新；先输出原因，不能补零、删掉困难任务或自动增加时限。
程序异常中断保留trace及异常记录；不得让不同代码版本的结果混算。

## 学习和审计

训练只使用当前版本自身的全轨迹，先核对行为概率，再用PyTorch Categorical/autograd求梯度。
每条episode乘其终局回报减同条件其他replica均值；对时间步求和，不除以轨迹长度。
按地图、任务和replica等权。所有候选完全平局的批次停止，不自动更换奖励。
特征从动作前状态提取；已消耗节点是过去信息，修复后路径/结果不进入该次输入。
轨迹核验重新计算特征、概率、采样动作、PP/SA种子、状态delta、合法路径和预算。
微型用例检查真实proposal和重放；完整轨迹离线审计不再执行所有PP，不能称第二次求解复现。

两次小步SGD是接口与开发信号原型，不是充分训练的RL基准。
每次参数L2变化至多0.001；若策略变化小、没有形成足够动作差异，报告学习量不足，
不能把“几乎同一策略”的平局归为所有RL失败，也不擅自加大学习率或追加更新。

## 结论边界

成功、预算未完成、资源删失分开；比较训练后与固定探索，避免把随机探索收益记作学习。
主对照是Dual16+SA与Official+SA；共同成功的节点、轮数、SOC、makespan均完整报告。
原型只提供开发信号，零冲突状态也保留。没有单workerTTF，不能声称速度或真实机器人任务时间改善。
所有错误/删失未审清、或两次更新没有完成时，不输出完整模型评价的成功结论。
