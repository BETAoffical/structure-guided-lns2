# 容量证书的外部路径放松验证

保留前轮10个有证书状态，不新增案例、不读取PP结果选车、不训练或计时。八个干预后状态相关，不能计为八张独立地图。

候选只从输入生成：为证书车辆计算完整目标条件化可达层，从每层可达位置的一步邻接转移找固定外部车辆的顶点和交换阻挡。按关键时刻前后8步的阻挡次数、全时域次数、agent ID排序，最多8辆。时域/工作上限沿用512/1000万。该提取器可能漏掉远端或必须联合解除的阻挡，不作完整性承诺。

对照为哈希固定的同数量其他外部车。分别验证8个单车、排名前4车的6种两车组合和对应随机对照，加原集合基线；每状态最多29作业，总计最多290。prepare输出准确作业数；每作业180秒安全上限、最多20独立进程，保留逐作业原子receipt、运行锁和resume。调度失败停止并保留证据，不静默替换任务。

第一层：暂时忽略候选外部路径，重新计算原证书车辆在关键时刻的可用域与Hall缺额，验证放松约束不缩小域。证书消失不代表可解。

第二层：仅对原缺额消失的动作，将所释放车辆真正加入选中集合，也要求它们到达各自目标，再检查全时间层、整个扩大集合的容量条件。报告仍不可行、未证明不可行、资源不足三种情况。“未证明不可行”绝不能写为PP成功或MAPF可解。

固定评价：按状态及单车/两车报告定向与随机的原缺额消失比例、扩大集合仍不足比例。至少两个状态存在定向扩大集合未证明不可行，且配对候选组平均此比例高于随机，才讨论下一轮原生PP机制验证；仍不晋级控制器。若只是移除障碍有效、重新加入车辆后仍不足，先报告协调复杂度，不重复宽闭包、回温或重训。没有自动PP扩展阶段。

复核原有模型、native与正式结果SHA；本轮只增加诊断模块。执行前本地Git登记，完成后保存结果与备份，不自动推送。
