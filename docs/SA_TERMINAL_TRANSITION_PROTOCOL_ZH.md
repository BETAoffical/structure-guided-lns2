# 保留OD的单档终局难度过渡

## 目标与历史区别

此前actor-1终局信用仅来自4条件/3地图；增加探索没有解开M04，严格匹配Official+SA也0/8。
本轮不重复信用盘点、一步/H32标签、探索比例或模型容量实验，而检验一档训练任务过渡能否新增完整终局差异。
对现有SA协议/报告和脚本的检索未发现同样的端点保留抽减试验；不声称对所有历史Git版本完成穷举检索。
旧d20/d25是不同OD任务；本轮保留原d25中被选车辆的起终点，并保存父ID映射。

## 冻结设计

- 六张已见Train地图M00--M05全纳入，不读M06/M07/Test/OOD，不只选容易或失败地图。
- 每图仅使用原d25的`__task_0001`，不更改地图与存活车辆OD；每车按原OD类别和是否有瓶颈约束分层。
- 全局保留人数`floor((9*N+5)/10)`，分层配额用最大余数法。层内使用seed=2026092301的稳定哈希选择，
  最终按父ID排序。不按冲突数、未来标签或求解结果挑车，不取原任务的简单agent前缀。
- 只测一个90%保留档，约等于22.5%空闲格密度。不是普通独立密度OOD，不会自动扫更多保留比例。
- 六任务、solver 233/239、每条件四replica，共12次qualification、48条冻结actor-1完整终局。
- 模型、候选池、归一化、PP、SA、native不变，不训练、不调整探索概率、不比较正式TTF。
- 每条25M修复generated nodes，无决策次数上限；256仅为冻结输入尺度。
- PP20秒、episode900秒、进程960秒保护，未知/错误不伪造失败标签，不自动重抽或补跑。
- workers=20，48条最多三波；qualification只检查合法性和完整reset，零冲突保留，不按难度过滤。

## 数据语义与归因边界

抽减车辆同时改变占用约束、初始PP顺序、native连续ID和哈希随机流。
它是固定端点子任务的开发干预，不是严格保持全部其他条件不变的密度因果实验。
保留OD类别及瓶颈约束的大致比例，不保证新初始冲突单调降低，也不把旧路径当成新初始路径。
所有新ID映射、父输入SHA、分层人数、实际密度、距离和scenario均校验并登记。
原d25数据不删不改；子任务成功绝不记作原困难任务成功或新模型成功率提升。

## 完成后怎样决定

只使用完整终局1/0、同条件其他三replica基线与完整轨迹log概率计算信用，不进行参数更新。
同时报告12条件各自成功数、混合成败条件及地图数、有效信用轨迹/步数、M04子任务成功见证。

- 至少4个混合条件且覆盖至少3图：新增终局信息达到这次数据探针的最低范围，可另行登记训练设计；不是算法晋级。
- 少量混合条件：保留局部信号，不因未满足覆盖就声称数据无用；不自动扩采或训练。
- 无混合条件：停止这一过渡档，不能用更多全成功样本伪装解决稀疏反馈。
- 只有子任务M04有成功：仅说明抽减后的任务有终局，不证明原任务可由所学模型修复。
- 任一未知/错误/缺失：保留记录并检查，不从不完整批次计算训练信用。

## 验证与交付

静态校验MovingAI场景、唯一起终点、父子OD严格对应、分层配额、父数据不变、全Train地图覆盖、确定性和无标签输入。
冻结运行器继续承担路径、动作、概率、SA/PP随机流、终止原因、原子输出、resume和进程隔离审计。
模型副本校验SHA；报告在写出前做JSON往返seal校验，避免整数键格式错误重现。
入口`scripts/probe_sa_terminal_transition.py`提供prepare/verify/dry-run/qualify/collect/audit/report/all/stop。
输出`build/sa-terminal-transition-v1`，使用curriculum_registration.json，正式求解前本地提交与备份。
保留全部结果，困难任务不删除；本轮没有自动actor-3、计时实验或任何正式控制器变更。
