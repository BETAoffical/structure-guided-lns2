# 新选择器的大小与冲突覆盖审计

## 问题与边界

目标仍是提高首次可行解的成功率、减少长尾和真实 TTF。本轮只检查：最近新模型的闭环退化，是否可以简单归因为“邻域选得太小”。

这是查看闭环结果后的描述性审计，不是预注册确认，不训练、不调用求解器、不新增标签，也不修改正式 Dual16、PP/SIPPS、SA 或候选生成器。对照 `frozen` 是 **Dual16+SA**，不是官方 Adaptive。

来源为 [bootstrap 闭环](SA_BOOTSTRAP_CLOSED_LOOP_RESULT_ZH.md) 的 8 张地图、16 个配对实例、64 条轨迹、7,414 次选择，以及旧开发集 47 个状态、188 个候选的 H32 标签。它们均为已查看的开发证据。

## 核对方法

- 对每个决策，从完整 `pool` 的 `selected_index` 取实际选中 ID；特征则按 `subset` ID 对齐。两个索引空间不能混用。
- 将新选择与**同一当前状态**下旧 Dual16 的首选比较，而不是与旧策略另一个时刻的状态比较。
- 分开统计不同 size，以及“size 相同但 agent 集合不同”的改选；额外报告第零步、0–31、32–63、64–127 阶段和每张地图。
- 内部冲突覆盖率 = 两端都在邻域内的冲突 agent 对数 / 当前全部冲突对数。关联覆盖率还包括只有一端在邻域内的边界冲突。重复时空冲突事件另外统计，不与唯一冲突对混为一谈。
- 四种方法的 16 组初始候选池、子集、特征、anchor 及状态指纹完全一致。后续状态已分岔，只做各自状态内的比较。
- 核对既有报告、开发索引及 256 个 episode 文件的 SHA；本轮复用上轮完整原生/轨迹审计的已核验字节，不重复宣称重新执行了 native 推理或完整 replay。

## 结果一：不是主要选了小邻域

| 方法 | 步数 | size16 次数 | size16 占比 |
|---|---:|---:|---:|
| 冻结 Dual16+SA | 1,528 | 1,415 | 92.60% |
| 新 GBDT | 1,995 | 1,769 | 88.67% |
| Bootstrap 概率选择 | 1,930 | 1,546 | 80.10% |
| 四候选均匀随机 | 1,961 | 925 | 47.17% |

只能排除“新模型大多选小邻域，所以退化”的简单解释，不能证明 size 完全无影响。这些是步数加权比例；不同策略的失败长轨迹贡献更多步骤。

## 结果二：同大小改选仍普遍降低冲突覆盖

仅统计改变 anchor 且实际 size 相同的步骤：

| 方法 | 同大小改选 | 内部覆盖降低 | 降低占比 | 覆盖率平均变化 |
|---|---:|---:|---:|---:|
| 新 GBDT | 1,397 | 1,310 | 93.77% | -27.95 个百分点 |
| 概率选择 | 1,064 | 987 | 92.76% | -28.04 个百分点 |
| 均匀随机 | 448 | 373 | 83.26% | -22.33 个百分点 |

这不是“93.77%的失败由覆盖不足造成”。当前没有在每个新访问状态执行未选 anchor 的反事实修复；覆盖率变化不等于实际可修复性或长期收益变化。

两个新模型在全部 8 张地图的同大小改选中，平均内部覆盖变化都为负。16 个共同初始状态中，两者各有 8 次同大小改选，其中各 7 次降低覆盖；因此现象并非只在很晚的长尾状态出现。但第零步证据只有 16 个配对实例，不能把后续数千步当作独立样本扩大置信度。

关联冲突覆盖在同大小改选中也降低：GBDT 平均 -21.79 个百分点、概率选择 -21.19 个百分点。因此不能简单解释成“放弃内部冲突，专门处理更多边界冲突”。不过，它们仍可能调整少量关键车辆；本审计不检验这一因果机制。

## 结果三：训练标签不支持直接加覆盖率硬约束

在开发标签中，逐候选与同状态 anchor 比较 H32 完成率：

| 比较范围 | 候选–anchor 对比数 | 胜 / 负 / 平 | 两个四-trial半组都严格胜 / 都严格负 |
|---|---:|---:|---:|
| 内部覆盖较低，所有 size | 126 | 27 / 25 / 74 | 5 / 7 |
| 内部覆盖较低，size 相同 | 39 | 13 / 5 / 21 | 2 / 1 |

126 个对比来自 45 个状态、8 张地图；其中 39 个同大小对比来自 39 个状态、8 张地图。它们不是 126 或 39 张独立地图。两个半组只是固定 trial 0–3 与 4–7 的事后描述，不是新的独立确认。

同大小低覆盖候选的地图等权、地图内状态等权完成率差为 +4.01 个百分点；所有 size 混合则为 +0.68 个百分点。二者是不同条件子集，不能把差值解释为 size 的因果效应，也不是某个选择策略的性能。

低覆盖候选可以有正例。不能因为本轮闭环退化，就规定模型永远选择最多冲突边或强制不低于 anchor。覆盖统计已经存在于当前输入特征中，也不能把新增同名特征当作新模型改进。

如果只保留内部覆盖不低于 anchor 的候选，在现有四候选子集中：

- GBDT 的 1,681/1,995 步（84.26%）没有任何合格的非 anchor 候选。
- 概率选择的 1,630/1,930 步（84.46%）没有任何合格的非 anchor 候选。

这只是当前已保存子集的可用性分析，不包含完整池外的候选，也没有模拟改选后的新轨迹。它说明这个硬约束大多数时候会退回旧策略，不能据此宣称训练出了更好的选择器。

开发数据的状态冲突数范围为 1–205，本次初始状态为 70–518，16 个中有 8 个超过开发最大值。新 GBDT 全轨迹仅 105/1,995 步超出该单列范围；不能因占比小而排除联合分布偏移，也不能据此认定外推就是唯一原因。

固定16家族还有 [Boundary16/Component16历史](WAREHOUSE_FIXED16_DEVELOPMENT_V2_RESULT.md)，但它与本次学习器只允许同大小的消融并不相同。针对性回查没有找到“internal coverage必须不低于当前anchor”这个确切硬约束的已执行记录；不把相近路线失败写成它已被严格否定。

本轮新增的是**在当前连续选择器上，把大小变化与集合成员变化分开，并对照现有长期标签**。不是新一轮控制器确认，也不是重新用一步下降作为学习目标。

## 当前决策与下一步

1. 保留正式 Dual16+SA；不晋级 bootstrap 选择器，不据此启动正式 TTF 或 RL。
2. 不立即添加 coverage 阈值、强制 size16 或重新训练相同47状态H32模型。已证实的现象是同大小的集合选择差异，尚未证实的因果是这些差异是否导致长尾。
3. 停止当前这组“换排序器、扩大介入、再补同类标签”的自动迭代。这不等于新模型整体不可能，而是当前数据未提供足以支持下一版的新证据。
4. 若继续新模型设计，先明确它要区分哪些低覆盖但长期有益的调整、哪些低覆盖但有害的调整，以及动作前什么可观测信息可以区分它们。必须说明与已失败的全局汇总、图特征、历史窗口、直接anchor比较和策略对齐训练有何不同。
5. 只在提出这种可检验区别后，另行登记小规模、同状态配对的机制验证。当前事后统计不自动触发新采集，不把“先挑更多冲突”退回到已经反复不够用的一步贪心目标。
