# Raw共享特征串行TTF协议

日期2026-09-26；用户已明确授权需要时开始计时。
起点c2b59b3，恢复分支codex/backup-sa-shared-before-ttf-20260926。
本轮不训练、不改模型/候选/PP/SA，不重复历史失败机制实验，不自动替换默认控制器。

## 问题和五臂

工程核验已确认96条轨迹动作等价，36状态组件均值下降37.00%。
现在只检验它能否转化为真实TTF收益，不能把组件加速直接当成结论。

为兼容已有经过验证的计时schema，内部臂名保留，但新登记、报告明确运行时含义：

| 内部名称 | 本轮含义 |
|---|---|
| raw_reference | raw-1模型 + 已优化的FastPolicy + SA |
| raw_fast | 同一个raw-1模型 + SharedFeaturePolicy + SA |
| dual16_sa | 冻结Dual16 + SA |
| official_sa | 官方Adaptive + SA |
| official | 官方Adaptive，原标准PP接受与提前终止 |

raw_reference不是最早的慢Policy。五臂同native、任务、初始fingerprint和预算。
SA各臂保持登记的配对选择/PP/接受随机流，官方标准臂不使用SA接受draw。
官方标准臂调用原 `step_with_time_limit`，不是把SA温度设零，也不是complete-greedy变体；
日志中的temperature/uniform仅兼容字段，不传入其native修复器。
保留完整原计时代码对象，只私有替换Policy，不修改全局函数或旧报告。
审计使用原独立特征提取实现，避免只用共享版自证正确。

## 固定范围

按用户追加要求扩大到原六张仓库图M00--M05，每图d20/d25两负载，solver251/257、replica0/1，
共48配对条件、240episode，是原工程12条件的四倍；不看新结果筛选，不替换失败案例。
48不是48张独立地图。官方标准臂同solver的两个replica是重复计时，
不产生新的native随机流，不能当成独立算法样本。bootstrap单位仍为6张地图。
每条件五种方法按十种Williams顺序轮换，每种出现4或5次；保留所有计时次序。
这是开发性工程确认，不新增跨地图泛化证据，也不与旧会话计时混合成同期结果。

每episode从reset前单调时钟开始，120秒首解预算；无决策数或节点执行上限。
候选生成、评分、模型推理、PP、过程中完整性检查与记录都计入。
另列最终交付时间、冷启动/模型加载、选择、PP、记录、收尾、SOC、makespan和等待步数。
无解TTF为null，单独报告成功率；共同成功子集才比较原始TTF，不把失败填零。
理想整批完成时间为交付时间加makespan乘每步0.5/1/2秒，不称为机器人实测。

计时始终一个进程、数值库一个线程，无同时运行的collector或测试。
外部进程fuse240秒只用于安全，不是额外求解预算；异常中断停止整组，保留记录不自动重试。
支持stop完成当前episode后暂停，resume显式恢复；完整结果校验后跳过，不覆盖部分结果。
前缀和事后审计最多20进程，不能把并行诊断耗时算作TTF。

## 准入和结束

1. 配置、代码、模型、native、输入轨迹及工程报告SHA登记，源码提交在正式运行之前。
2. 四个原有语义臂各做最多3步真实前缀，与冻结旧轨迹一致；
   48个官方标准臂分别检查直接官方step与有界标准step的前三步路径、邻域、顺序和低层计数一致。
   总计最多864次诊断修复，不计入TTF。
3. 串行完成240episode；实时保存运行状态，每个任务完成后可安全停止。
4. 审计全部轨迹，再对48个原/共享运行时配对检查动作与路径。
   允许PP墙钟耗尽步骤发生截止分叉；截止前动作不一致立即停止解释。
5. 新共享版分别对原快路径、Dual16+SA、Official、Official+SA做共同成功TTF、成功率、路径质量
   和地图级5000次配对bootstrap，另列Official+SA对Official的差异。
   六图及两负载完整保留，不按新结果创建子集。

主要工程结论要求动作等价、成功数不降低、共同成功TTF均值下降；
同时列置信区间和逐图胜负。区间跨零则只记为不确定正信号，不要求每例都更快，
不以事后调门槛自动晋级。对Dual16的比较与同模型工程收益分开解释。
尾部失败保留，不把多做修复、少剩冲突当成成功。
