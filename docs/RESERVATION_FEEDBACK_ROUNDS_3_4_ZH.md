# 第三、四轮：自动占用反馈失败，发现观测盲区

## 当前结论

本次有界执行已完成四轮：受控占用查询、保留外车路径的整轮消融、自动反馈规则对照、
独立路径账本及失败归因。最多20个独立进程，无正式TTF、模型训练或默认控制器修改。

前两轮有事后机制机会，第三轮输入可见的自动规则未通过，第四轮解释了一个重要限制：
**最终碰撞对象不一定是改变搜索路径选择的占用对象。**
不能把这个限制扩大为所有长尾的唯一原因，也不能说问题已经修复。

## 第四轮：为什么没有复现前两轮机会

对前两轮的11车普通PP重新生成完整反馈列表，真正有占用影响的235在8/8列表中都不存在。
其余车辆的规划可能已避开235，因此实际碰撞列表不会记录这种被避开的占用。
即使把该列表中的排序器换得更强，也不能选到列表外的235。
这是该案例的观测覆盖反例，不是普遍证明任何反馈都无效。

另一方面，直接忽略碰撞最多的外车往往正好削弱了需要保留的软惩罚：

- 定向方法29次与相同fresh seed重试相比，实际尝试路径都发生变化；不是新分支没有执行。
- 在相同长度的共同插入前缀上，24次出现与所选外车的新冲突对，只有3次移除了此类冲突对。
- 5次出现与其他车辆的新冲突对。上述计数可以重叠，不代表净新增24或5对全局冲突。
- 27次触发真实冲突上限回滚，1次接受但未改善，1次改善。
- 所有真实检查都包含被忽略外车的旧路径；不允许通过漏算它的冲突取得虚假进展。

87条新分支及8条第二轮路径通过独立账本核验；第二轮8条结果又经冻结native导入路径核验。
外车路径保持不变、逐步唯一冲突对计数、提前回滚、接受后的完整路径与回退规则均通过。

## 发现并修复的汇总问题

原v1汇总只识别`failed_long_unchanged`，遗漏历史新增状态使用的`failed_long`。
这导致随机方法在失败长尾来源的单次改善被错写成0，正确值为1。
该标签不参与车辆选择、PP搜索或随机种子生成；48项作业和87条原始分支无需重跑。
稳定状态仍为0，主NO_GO不变，但不能继续沿用“所有方法在失败长尾都无单次改善”的说法。

修复前标签 `pre-reservation-role-report-fix-20260910` 已推送。
保留原`report.json`和初版归因，不改冻结collector源码SHA。
**当前规范结果为`report-corrected.json`和`round4-review-v2.json`。**
旧collector的`analyze`仅复现原始v1；正确分类和独立核验请运行：

```bash
python scripts/audit_reservation_outcomes.py
```

修复器显式兼容两种历史失败标签，未知标签直接报错；新增测试覆盖别名和门槛行为。
另一个准备阶段问题是旧证据清单用`files.report.json`而非顶层`report_sha256`；
已在第三轮任何新搜索前修正。两项均记录，不把报告问题说成原生求解器故障。

## 第二次历史复盘与停止原因

- 没有偏离长期目标：仍在判断无效修复能否减少，保留未来成功率和真实TTF的最终门槛。
- 本轮没有把当前冲突图扩张、更多seed、更多重试或更大模型重新包装成新方法。
- 新机制改变搜索CAT而不移动外车，与历史扩邻域/内部硬约束的干预层不同。
- 但自动规则仍陷入历史共同问题：可见反馈不等于完整可修复性信息，局部路径变化不保证全局收益。
- stable4和compact-blocker已有持续性负面结果，因此不对第三轮的孤立改善直接启动闭环。

本次停止自动反馈分支，不凑满六轮、不增加忽略车辆数量、不修改旧门槛。
不是因为第三轮失败就退出：已经继续完成整批分支归因、覆盖反例、独立校验和报告修复。

下一项有区别的问题是：能否在预算内观测到搜索避开的替代路径及其占用来源，
而不是只读最终路径上的碰撞。这需要新的、明确有界的搜索内部观测方案及等价性验收。
现有结果没有证明这种信息可廉价获取，也没有证明它可用作在线选择，因此不临时拼凑新的
空间闭包或重训实验来填剩余轮次。Official/V2/Dual16保持冻结。
