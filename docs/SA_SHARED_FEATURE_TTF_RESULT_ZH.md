# Raw共享特征：五方法串行TTF结果

完成日期：2026-09-27。协议见[预登记](SA_SHARED_FEATURE_TTF_PROTOCOL_ZH.md)。
本轮没有训练、改候选、改PP/SA、修改预算或重新筛选失败任务，没有自动替换默认控制器。

## 1. 范围和结论

六张已有 station-centric 仓库地图，每图两种瓶颈任务负载，solver seeds 251/257、replicas 0/1，
共48个配对条件、五方法240条全新串行计时。不是48张地图，也不是新独立跨布局确认。
正式实验一个worker；前缀及事后校验最多20个进程。每条120秒首解预算，无决策次数或节点上限，
240秒进程保护未触发。不运行第二阶段。

结论分开表述：

- **同模型工程加速成立**：42个共同成功条件TTF均值下降4.83%，41快1慢，动作及成功路径等价。
- **对官方及官方+SA有本批正信号**：新模型成功42/48，官方42/48，官方+SA39/48；共同成功TTF明显降低。
  但当前完整记录框架对高修复次数有较大开销，不能将约49%/55%直接写成相对裸C++求解器的加速。
- **对Dual16+SA仍有取舍**：成功40→42，总体共同成功TTF下降7.52%，但地图bootstrap跨零，18快21慢。
- **长尾与路径质量未解决**：M05/d25五方法均失败；新模型相对Dual16的平均makespan略长，
  1秒/步的建模完成时间没有改善。

这里“新模型”为此前冻结的 raw-1 + SA，本轮只把重复特征提取共享，未得到新的权重。

## 2. 方法和计时口径

| 简称 | 实际方法 |
|---|---|
| Official | 官方Adaptive，标准PP接受与提前终止，无SA |
| Official+SA | 原已登记的官方Adaptive+SA |
| Dual16+SA | 冻结Dual16+SA |
| Raw reference | raw-1 + 已优化FastPolicy + SA |
| Raw shared | 同一raw-1 + SharedFeaturePolicy + SA，本轮主方法 |

所有方法同任务、初始路径、native和120秒预算。Official使用标准`step_with_time_limit`，
并不是把SA温度设为零；48个条件都验证其前三步与直接官方step一致。
SA仅为已有单轨迹机制，不代表完整CPLNS的并行协作/重启实现。

TTF从reset前开始，到首次可行状态；包括初始化、选择、PP、途中状态校验和轨迹记录。
交付时间还包括最终路径校验、写出和哈希；模型加载/环境构造与worker内冷启动另列。
worker内冷启动不包含全部操作系统启动调度时间。失败TTF为null，不填零、不折算为成功。
下面时间对比均用**该行两方法共同成功的相同条件**，因此不同对比的分母不同。

## 5. 时间收益来自哪里

同模型42个成功条件：完整选择耗时4.9573→3.7631秒，少1.1942秒；TTF少1.2105秒。
PP耗时11.2406→11.1937秒，记账6.3304→6.3772秒，主要收益确实来自共享特征，
不是偷偷改变PP或少规划一些路径。此前37.00%是局部组件基准，本轮4.83%才是包含其他成本的TTF结果。

对Official的41共同成功条件：

| 项目 | Official | Shared |
|---|---:|---:|
| 平均修复次数 | 395.9512 | 96.8293 |
| 选择耗时(s) | 0.0035 | 3.4820 |
| native PP耗时(s) | 15.2437 | 10.2629 |
| 记账耗时(s) | 23.2843 | 5.8648 |

记账包括完整状态处理和正确性检查；其17.4195秒差额约占21.4078秒TTF差额的81.4%。
这说明较少修复既减少搜索，也减少本评测框架的每步记录负担。各方法采用相同计时框架，但
**完整记录对迭代次数多的方法影响更大**，不能将当前效果外推为裸官方CLI或最小化生产运行时的同等提升。
不事后减掉这些成本来改写预登记TTF。若要提出部署速度主张，应另行冻结轻量等价记录模式做配对确认。

## 7. 失败、完整性和边界

205次成功、35次正常预算失败：18次外层deadline、17次低层PP deadline；
没有进程保护终止、非法动作、fingerprint mismatch或未解释运行错误。预算耗尽不代表不可解。

- M05/d25四个条件五方法全部失败；Shared最终仍有61--68对冲突，长尾没有解决。
- Shared其余两次失败在M01/d25，分别剩4、1对冲突；剩得少不等于保证延时能成功。
- 优化前后成功路径、SOC、makespan、低层节点及修复次数相同；失败在同样墙钟内可走不同长度，
  不要求失败终态相同，也不将截止后的不同状态误判为选择器变更。
- 48/48同模型配对核验，6725个共同决策动作/特征/概率一致；5组到达PP截止分支，
  截止前路径一致。全部240轨迹、65713个决策独立审计通过，4615次合法无状态变更不是错误。
- 240/240准入前缀通过，共864次真实非计时修复；WSL相关pytest74通过6跳过，
  Windows相关unittest23通过1跳过；CTest14/14包括两组官方parity通过。没有重跑全仓库Python测试。
- 开始时Windows电源模式为Performance；未并行运行其他项目求解器。未持续测量用户外部负载，
  不把一次电源读取写成全程硬件环境恒定证明。
