# SA 独立确认：执行监督修订 v2

## 原因与不变项

第28个正式 episode 的原始错误被通用 failure builder 的 `job["row"]` KeyError 遮蔽。
独立诊断中，原求解循环在59.20秒找到可行解，随后完整轨迹校验耗时152.41秒，
总计212.08秒，超过原来覆盖求解与校验的180秒进程 fuse。
诊断重跑不充当正式结果，不证明原中断进程具有相同求解时间。

本修订只改变监督与保存，不改变 native、模型、初始路径、候选池、排序、随机流、
退火参数、PP逻辑、60秒求解预算和不限修复轮数。TTF仍由冻结循环记录，
从reset前到第一次可行原生返回，不含离线审计与写盘。

## 修订协议

- 原始目录只读。新的原始输出、审计证明、尝试日志写入
  `build/sa-independent-confirmation-supervisor-v2`。
- 27条已由原执行器和父进程完成科学校验的记录，以中断前登记的SHA逐字节复用。
- 第28条明确重试；其诊断见证不导入。剩余101个排程位置不筛选、不改变顺序。
- 求解子进程仍用180秒外部fuse；冻结worker结束求解后，在原本开始完整校验的回调处
  原子保存待校验结果。未调用完整校验的输出不包含`validated_seconds`。
- 独立校验子进程完整调用原`validate_result`，固定1800秒审计上限，无额外规划机会。
  审计成功保存绑定原始文件SHA及监督登记SHA的证明。审计结束后才启动下一次计时。
- 审计失败保留已捕获求解结果，检查原因后仅重试审计，不重新运行求解。
  求解失败且没有原始捕获时停止整组，不自动重试。
- resume与最终分析检查文件及证明身份，不重复完整物理校验；任何字节改变即拒绝。
- 原始输出仍标记`pending_full_audit`；是否成为科学证据由独立成功证明决定，不能只看原始文件。
- 原目录和新目录同时加锁，防止旧新版collector重叠。单worker串行求解，不运行并行重负载审计。
- `stop`在当前episode求解及审计结束后安全暂停；保留原目录停止标记的兼容检查。

## 操作与证据边界

入口 `scripts/run_sa_supervised_confirmation.py`：
`register / verify / collect / resume / stop / analyze`。
执行前登记新监督代码、测试、文档和全部原科学输入。
新旧worker在冻结原生模块上验证相同候选、分数、动作、路径、修复顺序，时间不要求相等。

正式报告明确混合了27条原监督记录和101条新监督记录，但没有混合算法版本。
记录原外部中断与重试，不能宣称全组从未中断。
主门槛仍为Dual16+SA相对Dual16平均capped TTF改善至少5%、地图bootstrap上界小于0、
观察成功数不降低；不要求每张图、每个seed都胜出，不自动替换默认控制器。
有限样本成功数不降低不等于已经证明成功率非劣。
