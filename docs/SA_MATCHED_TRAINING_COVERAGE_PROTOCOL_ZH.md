# 同来源配对训练前的覆盖检查

本轮是已查看数据的描述性审计，不是新的预注册确认，不定义事后晋级阈值。
不训练、不调参、不采集、不调用求解器；不修改此前模型或结果。

## 要回答的问题

- 原 47 状态和新增 16 个匹配对实际包含多少独立根状态？不能把新标签当作 16 个全新根。
- 每个留地图训练折还有多少净结果差异、涉及哪些来源规则、多少配对 trial 真正不同？
- 最强例子所在地图被留出后，还剩多少标签差异与分半复现信号？
- 原、新采集的 trial 编号相同是否等于相同随机流？
- 拼接索引能否避免跨随机流配对、训练/验证地图混用和同一根重复加权？

## 固定统计

完整保留 16 对、10 对经验平局也不删除。按根、地图和来源规则分别报告：
净差异、A胜/B胜/同成/同败、35 个互补分半的方向一致性、全部净差异的集中程度。
复用原分半选优结果；额外报告训练半平局时均匀选择的期望，作为 ID 平局规则敏感性。
两个口径均为标签事后交叉选择，不是模型预测或真实策略收益。

逐折只从其他七张地图计算训练覆盖。描述数值上的可拟合性，不把“还有一个非零 target”
写成足够的学习证据，也不因某个手工阈值就宣称全部方法失败。

## 分组索引

旧四候选构成一个随机流组，新同来源二候选构成另一个组。
原 anchor 仅用于诊断，不将它加入新增匹配训练组；若它本来就是 pair 成员，不重复删除该成员。
保留原 collection binding、每个 trial key、候选成员与标签；只在同一组内生成比较。
审计注册生成器的 H32 PP seed/SA uniform 序列，不重新运行 native 或重放完整 rollout。
原始轨迹正确性复用之前封存的校验证据，不能把本轮称为再次验证全部原始轨迹。

安全记账示例：每个根的总预算为 1，均分到该根拥有的采集组，再均分到组内候选对；
留地图时再沿用原地图等权。反向 pair 若用于学习，要分摊原 pair 权重，不能增加根预算。
这只是未来训练输入的合同，不等于本轮执行了训练或选择了更好的损失函数。

输出独立保存在 `build/sa-matched-training-coverage-v1`：
`comparison_groups.json`、`stream_audit.json`、`report.json`；旧文件及 SHA 不改变。
准备、检查、验证入口为 `scripts/audit_sa_matched_training_coverage.py prepare|audit|verify`。
统计只有 47 根，直接计算不启动 20 个空闲 worker；后续采集的并行数不由本轮决定。

## 后续边界

覆盖审计本身不授权自动拟合或扩采。结果若仍被少数根控制，先报告局限及尚未覆盖的条件，
不在同一 16 对上反复比较不同模型。新的补采或训练必须先固定范围，不按新结果替换困难状态。
