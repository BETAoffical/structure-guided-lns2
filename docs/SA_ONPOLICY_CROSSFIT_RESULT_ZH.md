# 状态基线与有界更新：两个训练原型已生成

2026-09-22。[冻结协议](SA_ONPOLICY_CROSSFIT_PROTOCOL_ZH.md)，训练前提交`d7037bc`。
本轮已完成实际拟合与两次独立分叉更新，不再仅是设计或梯度审计。
仍未采集新MAPF轨迹、评价留出地图或执行TTF；原actor-1与正式Dual16/SA不变。

## 1. 训练了什么

两个原型都从采集96条Train轨迹的actor-0出发，各计算一次完整批梯度：

| 原型 | 回报基线 | 改动层 |
|---|---|---|
| `bounded_condition` | 原同条件其余replica完成率 | 更新尺度由预设概率偏移约束控制 |
| `bounded_state` | 四折交叉拟合的动作无关状态基线 | 回报基线及同样的有界更新 |

终局可行=1，工作预算未完成=0；actor输入、归一化、架构、候选、PP和SA都没变。
原96条轨迹确实来自actor-0，所以这是同一on-policy批次的训练消融，不是把它当成actor-1的新轨迹继续训练。
两组只有一次参数更新，不能称充分训练。第一层在零输出初始化处仍不变；不是引入新图网络或恢复静态地图上下文。

状态基线使用27项`state.*`、`sa.*`、`budget.*`特征，逐状态验证它们在所有候选之间完全相同。
四折按replica留一，每折72条拟合、24条预测，0个episode跨越训练/预测边界；包括折内标准化。
这是已见Train地图上的交叉拟合，不是新的跨地图确认。

## 2. 更新现在能实际影响选择

回溯步长只检查固定KL限制，不看回报或成功率挑参数。两个arm都从0.25依次减半到参数L2距离0.03125。
0.0625仍违反预设轨迹KL均值上限，不能四舍五入当通过。

| 指标 | 原小步actor-1 | bounded_condition | bounded_state |
|---|---:|---:|---:|
| 参数L2变化 | 0.00034802 | 0.03125 | 0.03125 |
| 相同旧状态/draw选择改变 | 6/12,180 | 466/12,180 | 512/12,180 |
| 改变比例 | 0.0493% | 3.8259% | 4.2036% |
| episode等权状态KL均值 | 未按此口径报告 | 0.00048956 | 0.00057477 |
| episode等权轨迹KL总和均值 | 未按此口径报告 | 0.0434853 | 0.0544990 |
| 已见状态最大KL | 未按此口径报告 | 0.00208370 | 0.00215242 |
| episode等权总变差均值 | 未按此口径报告 | 0.00730410 | 0.00812212 |

旧actor-1报告的总变差是决策均值，本轮是episode等权均值，不能直接计算两者的倍率。
选择改变比例使用同一批12,180个状态，分母一致；它仍只是旧状态离线回放，并不是新策略真正跑过12,180步。
KL限制仅覆盖已见Train输入，不是新地图安全保证，也不限制整条新轨迹最终会分叉多少。
动作变化更明显说明实验干预不再近乎为零，不表示这些变化有利。

## 3. 新状态基线没有显示出预期的降方差收益

| 诊断，越低越好 | 原条件基线 | 状态基线 | 变化 |
|---|---:|---:|---:|
| episode等权交叉预测Brier | 0.0462963 | 0.0802377 | +73.31% |
| 同条件episode梯度离散度代理 | 21.9714 | 29.8017 | +35.64% |

当前固定Ridge状态基线没有更准确地预测终局完成，也没有降低此离散度代理。
这不支持把它直接宣布为更好的训练基线，不能因为梯度范数更大就称为信号更多。

可能解释及边界：

- 条件基线拥有同一任务/初始seed其他三次重复的结果，已经强烈反映任务难度。
  当前状态Ridge不使用任务ID，不能假设27项状态汇总可以完整替代这些条件信息。
- 原批次21/24组全成或全败，条件基线在这些组产生零系数；状态预测通常不恰为0/1，因此产生非零系数。
  这些额外系数可能含信息，也可能只是预测误差，不能仅据数量区分。
- Ridge的表达、27项状态描述、小样本、条件差异均可能有关。本轮没有因果消融，不能锁定某一项为根因。
- 离散度计算受交叉拟合基线的共享训练数据影响，而且只有四次重复；它不是无偏真实梯度方差估计。
  因此不拿这一代理替代实际闭环，也不把本次负面推广为所有critic无效。

两个原型都保存，不根据这些Train诊断删除较差arm或宣布较好arm晋级。

## 4. 实现核验

- 提取96/96条轨迹，20个轻量NumPy进程，0新求解调用。
- 原条件基线的批量PyTorch梯度范数为0.34801956564081776，复现旧逐状态实现。
- 两个模型各238份输入，每份16个固定draw，合计7,616次跨平台动作检查一致。
- Windows PyTorch/NumPy及WSL portable概率误差均不超过4.4409e-16；WSL核对原native身份，没有替换PP。
- 原模型、归一化和结果SHA保持不变，没有安装软件。sklearn 1.5.0用既有全局Windows Python，Torch用独立环境。
- 专项回归：Windows Torch环境43通过、2环境跳过；另用全局sklearn环境运行新7项测试，4通过、3 Torch跳过。
  WSL为36通过、9 ML环境跳过。环境跳过由对应Windows后端补测，不声称跑了全仓库/CTest/正式parity。
- 69项历史保留清单缺项仍未在本轮整理，新增模块、入口和测试已登记。

这80条尚未启动，也不是本轮自动授权的正式TTF。它们回答：

1. 有界更新是否比同样探索但未训练的策略改善实际完成数，而不只是更改动作。
2. 状态基线的代理指标负面是否也表现为闭环负面，还是存在公开的收益/开销取舍。
3. 若只有探索actor-0改善，收益归探索；若只有更新改善，才有学习收益信号。

不要求每张图、每个seed都赢，报告全部配对完成/损失、未知、共同成功工作量和路径质量。
不得事后调整任务、预算或挑checkpoint；已查看的两张开发留出图不能称独立泛化证据。
