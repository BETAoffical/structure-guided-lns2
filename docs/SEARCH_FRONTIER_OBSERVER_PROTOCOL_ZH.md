# 搜索竞争节点观测预登记

## 范围与假设

前六轮结论保持不变。本轮仅检验：通过支配检查并进入队列的正碰撞转移，是否比所有区间返回提供更紧凑的占用反馈。不会把队列出现直接当作因果或恢复收益。

不修改Official/V2/Dual16、邻域、PP顺序、真实冲突接受上限或模型；不训练、不计时、不实施占用忽略。

## 独立构建

- 使用冻结SIPP源码SHA及核心archive；对派生编译单元机械插入三个观察调用：入队后、findPath出队后、路径交付时。
- 官方源文件不修改。去掉三处调用及观察头后必须与原源码逐字一致；不修改比较器、节点布局、支配逻辑或RNG。
- 比较器本身包含随机平局，不额外调用比较器用于诊断排序。
- 只记录非虚拟goal且相对父节点碰撞代价增加的转移。虚拟goal累计访问数单列；目标启发式和被支配后丢弃的节点不在本轮覆盖范围。
- 每次搜索最多32,768条12整数记录，约1.5MiB，满后只计数；不增加旧版记录容量以改变其失败结论。

## 固定特征范围

记录源/目标、父/子时刻、g、h、累计碰撞代价、父代价和节点标记。搜索结束后按本次真实固定路径映射顶点/交换占用，排除返回路径已使用的同一时空接触和内部车辆。

三个观测profile预先固定，只有第二个决定准入：

1. queued_all：所有已入队正碰撞转移，作为覆盖对照。
2. queued_envelope：已入队，且节点碰撞代价不超过最终返回值+1，g+h不超过最终路径成本。
3. popped_envelope：同一范围内已实际出队节点，仅作诊断，不替换主profile。

这是保守的、搜索后可计算的竞争范围，不是完整因果前沿，也不是证明一辆外车移除后代价必下降。多个外车可占用同一事件；仍需独立干预验证。

各profile保持此前固定排序：涉及不同规划车辆数降序、去重接触数降序、ID升序。不得围绕235调排序、代价范围或topK。

## 门槛及作业

先运行同一个历史11车状态的8个原seed/顺序条件。每个关闭/开启观测各一次，与冻结结果逐车比较路径、cost、节点、碰撞代价、PP接受/回滚和真实冲突数。

门槛同时要求：8/8完全等价，零未知/截断/无法归属正标记；主profile平均覆盖不超过25%的外车；事后见证235至少6/8进入top4。最后一项只是开发见证筛查，不能作为泛化结论。

只有全部通过才运行原24开发状态的48个条件，仍需等价、零截断/无法归属和平均外车覆盖不超过25%。不更换失败状态，不使用新确认集。

沿用20进程上限、单次PP序列30秒、单搜索5秒、外部180秒保护、原子输出、运行锁、resume和安全停止。8个见证只有8个实际worker。输出独立保存在build/initlns-search-frontier-observer-v1。

任何阶段失败后只分析已保存数据：区间可见而未入队、进入队列但范围筛除、入队后未展开、简单频次排名不足或记录完整性问题。不得将其中一种未经观测的原因写成已证事实。不能直接增加阈值、追加干预或重训。

## 验证

机械钩子可逆、别名快照、代价范围边界、顶点/交换归属、缓冲截断、异常释放、原生off/on/冻结等价；全组后检查官方parity及历史证据。预登记代码与构建SHA在新诊断前提交推送。
