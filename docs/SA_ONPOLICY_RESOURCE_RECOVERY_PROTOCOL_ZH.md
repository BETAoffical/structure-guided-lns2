# On-policy首批资源恢复与第一次更新

2026-09-22，承接[原型中止报告](SA_ONPOLICY_RUNTIME_RESULT_ZH.md)。原目录、原模型和截断记录全部保留。
本轮只补齐首批并作一次更新，不采第二批、不评价留出地图、不做TTF。

## 固定范围

- 引用原79条完整结果；只执行1条未知任务的固定seed恢复与16条未启动任务。
- 保持模型字节、129维特征、归一化、随机流、完整Dual16候选池、PP/SIPPS和SA不变。
- 256次决策、2500万节点的科学工作预算不变，仍在原子PP边界判断。
- 单PP保护仍20秒；episode保护300→900秒，进程保险360→960秒。
  这是为完成非计时数据采集提供资源，不是增加科学修复预算，也不能与原300秒作速度对比。
- 最多20个进程，此次只有17个新作业。每作业只允许本次登记的一次尝试，若仍截断则停止，不调预算、seed或标签。
- 截断任务重跑时，原238次完整修复的候选、特征、概率、动作、随机流和状态delta必须相同；
  原第239步仅要求动作前全部内容一致，原被打断的修复不得作为有效回报。
- 79条已完成轨迹仅按原路径读取，不复制大数据、不重新封存或覆盖result；引用必须匹配旧审计SHA。

## 两种身份明确分开

旧`binding`继续表示冻结模型及科学策略合同，不伪造新的模型身份。
新`registration.json`有独立资源登记binding，冻结新配置、实现、测试、协议、源审计和全部作业来源。
新作业附加`resource_receipt.json`关联资源登记和result SHA。
模型0字节原样复制到独立恢复目录；新模型1与训练receipt只写入恢复目录。
不把资源计划伪装成原`plan.json`，也不调用原入口绕过其`resume`保护。

## 执行顺序

入口：`scripts/recover_sa_onpolicy.py`。

1. `prepare/verify`核对79+1+16的范围与原始输入，登记恢复，不启动求解。
2. WSL `collect`运行17作业；支持`stop`完成当前批次后停止和显式`--resume`。
   失败/部分目录禁止静默重试，所有原始记录保留。
3. WSL `audit`重新审17条，复用79份有效审计，核对恢复prefix；合成96条只读来源清单。
4. Windows既有PyTorch环境执行`update`一次：沿用原map/condition等权、同条件其他replica基线、
   完整终局回报、固定SGD参数。仍有未知或缺失数据则拒绝更新。
5. Windows `parity --torch`和WSL `parity`检查新模型。只取Train已记录的0/32/128/255步输入，
   概率误差≤1e-12并检查固定draw动作一致；不接触留出标签。
6. `report`在旧Train状态上回放新旧概率和相同draw，统计动作变化量。
   这不是新模型真实闭环，更不能把旧轨迹成功数当成模型1的成功数。

## 归一化和同步

上轮后期隐藏单元饱和多，但所有状态仍有候选差异。为避免同时改目标、数据和表示，本轮保持归一化。
若更新几乎没有动作变化，解释为当前训练步长/表示下干预量有限，不宣布RL无效，也不擅自加学习率或重复拟合旧批次。

新入口使用遇锁即拒绝的原子互斥，不用Windows `os.kill(pid,0)`探测进程。
训练、登记和持锁测试串行执行；已有锁必须先查明来源，不能自动删除。
不改共享锁模块，避免改变冻结运行时。实验前后均本地提交、建立Git bundle备份，生成数据留在`build/`。
