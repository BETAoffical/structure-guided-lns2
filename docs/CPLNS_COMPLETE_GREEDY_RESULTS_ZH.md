# CPLNS 完整PP拆分结果：不能直接变成本项目的补丁

## 核心结论

只新增20个完整PP/贪心拒绝作业，复用并重新验证40个旧参考记录。
完整PP解释了部分平均轮数改善，SA模式仍有额外平均信号，但都不具有逐例普遍优势。
更重要的是，作者非SA的提前中止条件是 `>=`，本项目默认条件已是 `>`。
因此不能把“允许等冲突的新路径”当作本项目尚未具有的创新，也不能据此直接修改V2/Dual16。

## 额外只读定位：首次差异是什么

不新增求解，读取20对原始事件，按观测修复次序找第一处输入路径、PP顺序、输出路径或接受标记差异。

- 17对：输入路径和PP顺序相同，原模式拒绝，完整PP/贪心接受，局部冲突差为0。
- 其中16对确实变更了路径；09/seed5只改变接受标记，输出路径相同。
- 其余3对（02/seed2、13/seed3、13/seed5）在路径输入仍相同时，PP顺序已先分歧，不能作同动作接受归因。
- 两个贡献最大的原长尾（04/seed2、13/seed0）均在第一次修复出现“拒绝等冲突路径”与“接受等冲突路径”的差异。
  这是首处分歧证据，不是证明后续所有收益均由该次中性移动造成。

作者非SA在逐车PP的 `neighbor.colliding_pairs.size() >= neighbor.old_colliding_pairs.size()` 处中止，
即使冲突没有增加也可能没走到完整结果的接受分支。本项目默认原生代码则在严格 `>` 才触发同类中止。
后者已经允许继续处理等冲突情况；不应把本轮针对作者参考的修正重新作为本项目性能贡献。

## 对后续的实际帮助

本轮避免了两个误判：把完整PP的作用全归功于SA，以及把作者参考的 `>=` 行为误认为本项目默认行为。
不把完整PP补丁接入正式V2/Dual16，不把SA升级为默认，更不以少轮数声称TTF改善。

已重新查看旧 `build/nonmonotonic-repair-pilot-v1/report.json`：
旧停滞状态上standard为14/20、complete-greedy为15/20、SA为13/20，SA相对complete-greedy新增两条失败且无恢复。
因此不再重复同一组Dual16三路试验，也不追加温度扫描。
本轮用同OD重新初始化，不是原停滞路径续跑；新旧结果不能互相替代。

若继续推进，必须先明确新证据缺口：在同一个旧停滞状态上，作者高层邻域选择与Dual16选择的差异是否关键。
这需要先检查历史是否已有同条件证据，并在没有重复的前提下设计路径导入/身份验证。
当前没有完成作者路径导入，不自动启动该扩展；本轮到此收口，不继续增加分解作业。
