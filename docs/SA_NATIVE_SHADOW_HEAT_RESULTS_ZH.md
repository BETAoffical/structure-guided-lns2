# Native shadow 去冗余：组件门槛通过

## 结论与边界

本轮在保留全部完整校验的条件下，8 个案例累计选择时间从 **27.8579 秒降至 26.1672 秒，减少 6.0692%**。8/8 案例更快，792 次配对选择及 792 步完整历史路径重放一致，35 次周期 shadow 全部执行并通过。

达到预注册的“累计选择时间减少至少 5%，至少 6/8 案例更快”门槛。判定为 `retain_for_independent_ttf_confirmation`，仅保留为后续独立 TTF 确认的候选，**不替换默认运行时，不宣称端到端加速或成功率提高**。

参考实现是原 `SingleFullCheckPool`，不是上一轮已经变慢的增量版。没有降低门槛或 shadow 频率，也未修改模型、候选、排序、PP、退火接受条件或 native。

## 改了什么

独立 `NativeShadowTopology` 在 native shadow 分支中不再构造未使用的 Python `TemporalConflictIndex`。仍检查非空路径，重新进行全量 native 冲突提取，再从当前状态全量重算热度；不用待验证的增量结果作为参考答案。

Python fallback 继续构造和使用原 Python 索引。路径变化检测、增量热度更新及每 20 次更新执行一次完整 shadow 的协议保持不变。新旧选择器复用相同 code object，仅私有绑定拓扑类，未全局 monkeypatch。

## 为什么这次有净收益

|分组|调用数|原全量版秒|新版本秒|解释|
|---|---:|---:|---:|---|
|普通非初始化更新|749|26.2775|24.3349|减少 7.39%，节省 1.9426 秒|
|触发完整 shadow 的更新|35|1.2370|1.4546|仍多花 0.2176 秒|
|初始化|8|0.3434|0.3776|多花 0.0343 秒|
|总计|792|27.8579|26.1672|净节省 1.6908 秒|

完整 shadow 仍要额外重算，不能期待它完全免费。这次其开销已小于普通更新的节省，因此累计收益为正。上一轮 shadow 组的额外开销为 5.2221 秒，但那是另一次运行；不能把两轮绝对时间直接相减当成这项修改的精确收益。可靠的速度结论是本轮内部配对的 6.0692%。

5 次路径未变化调用累计略慢 0.80%，样本过少，不据此增加“回滚后跳过”的特殊分支。没有删除校验记录或排除不利调用。

组件计时包含变化检测、拓扑、proposal、特征、推理及选择器内的 fingerprint。输入 deepcopy、实验一致性对照、历史 PP 重放和结果写出在组件时钟外。因此，组件减少 6.07% 不等于 TTF 减少 6.07%；修复 PP 和其他阶段可能稀释这部分收益。
