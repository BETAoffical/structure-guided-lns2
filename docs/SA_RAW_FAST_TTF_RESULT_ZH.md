# 冻结 raw 模型快路径：串行 TTF 结果

完成日期：2026-09-26。协议见 [预登记协议](SA_RAW_FAST_TTF_PROTOCOL_ZH.md)。

## 1. 结论

工程加速确实转化成了端到端收益，但没有改变模型本身的能力边界。

- 同一个 raw-1 模型，旧运行时与快路径均成功 **10/12**。共同成功10例的平均TTF从 **28.4604秒降到24.6500秒，减少13.39%**；10例全部更快。
- 这10例的最终路径、修复次数、generated nodes、SOC、makespan、等待步数全部相同，收益不是换了PP、模型或任务。
- 同期Dual16+SA成功 **9/12**。快路径多成功一例、未丢失成功，但共同成功9例的TTF为 **21.3753秒对18.2910秒，慢16.86%**，3快6慢。
- 不要求新方法每例都更好；当前表现是一例成功增益与平均耗时增加之间的取舍。六图、单solver seed的小样本不足以宣布稳定胜过Dual16，不自动替换默认控制器。
- 仍有两个任务三种方法都失败。没有解决长尾，不恢复静态上下文或跨OOD迁移主张。

## 2. 实验与完整性

复用原六张station_centric地图，每图d20/d25两个任务，solver seed 251、replica 0。12条件、三方法、36次串行首解计时。没有重抽任务、训练、二阶段优化或重试失败。

raw_reference与raw_fast都是相同的raw-1权重；前者不是raw-0父模型。Dual16+SA保持原控制器。
三个方法共用冻结native、PP/SIPPS、SA和对应随机流。快路径仅省掉dynamic profile本来就删除的history.*计算，保留阶段特征和History.observe。

- 单worker，首解预算120秒，进程fuse240秒，无决策数或节点执行上限。
- 主TTF从reset前到首个可行env返回；模型加载、环境构造单列。此前迭代的校验、记录等开销仍进入TTF，不事后扣除。
- 交付时间再包含最终校验、路径保存及哈希。所有成功案例都按时交付。
- 计时前36条×3步native前缀通过；相关WSL测试61通过、8项因无Torch跳过。Windows新增10项unittest通过。
- 36/36完整轨迹审计通过，共5,888次决策/PP修复，无合法空决策。
- 12/12运行时配对通过，共1,779个重叠动作一致；两个截止步骤允许因剩余预算不同而分叉，其余修复后状态一致。
- 共29次成功、7次正常预算失败，零安全fuse、非法动作、身份错误或未解释异常。计时期间没有暂停或重跑。
- 计时启动与结束电源方案均为Performance，启动前接电。采集约30分钟；非计时审计另计，不能完全排除外部系统波动。
- 原native及1,624项登记输入保持不变。未重跑全库测试或CTest，未修改C++。

预登记提交为`357285cae207240dd11ef9a9b079868543771324`。准备时发现旧case通用density字段为null，改为核验既有bottleneck_d20/d25标识；该修正发生在注册和任何计时之前，不改变任务或筛选规则。

## 4. 加速来自哪里

在同模型共同成功10例中：

| 项目 | 旧运行时 | 快路径 | 变化 |
|---|---:|---:|---:|
| 平均TTF | 28.4604秒 | 24.6500秒 | -13.39% |
| 完整选择开销，含proposal | 8.7054秒 | 4.9069秒 | -43.63% |
| 原生PP耗时 | 10.9746秒 | 11.0216秒 | +0.43%，区间跨零 |
| 校验/状态记录等bookkeeping | 6.2344秒 | 6.2020秒 | 基本不变 |
| 修复次数 | 106.8 | 106.8 | 完全相同 |
| generated nodes | 7,485,526.5 | 7,485,526.5 | 完全相同 |

平均TTF少3.8104秒，选择开销少3.7985秒，与此次删去未使用计算的机制一致。
之前68.62%的结果只测候选生成之后的选择组件；本次完整选择还含proposal，总TTF又含初始规划、PP、校验等，因此不能要求整个求解也加速68.62%。native_pp是step_wall的子项，不能重复相加。

对Dual16共同成功9例，快路径仍多1.7568秒选择开销、多0.6270秒原生PP、多0.5091秒bookkeeping。修复次数93.8889对84.2222，generated nodes 6,408,058.2对5,990,969.0。
因此本小样本的剩余差距不全是未使用特征计算；实际搜索工作量也不同。不能把上一轮48条件中的节点优势直接移植到这个9例条件子集，更不能据此推断特定邻域评分缺陷。

## 5. 路径与整批任务完成时间

同模型10例的makespan均值均为151.2步，SOC均为35,537.5，等待均为5,669.2步，最终路径完全一致。工程改动没有改善或损害路径质量。
按每步1秒的理想执行模型，交付加makespan从179.8383秒变为176.0339秒，改善2.12%；这只是提前交付了同一组路径。
