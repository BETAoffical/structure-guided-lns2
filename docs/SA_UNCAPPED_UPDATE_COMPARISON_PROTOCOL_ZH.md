# 无次数上限新模型的冻结闭环比较

## 范围

本轮只评价已冻结的 `uncapped_condition`，不训练、不调参、不改变候选、特征、PP或SA，不做正式TTF。
模型来自无次数上限Train终局补齐后的单次更新。其训练集80/96仅是actor-0采样结果，不能当作新模型成绩。

沿用上一轮两张已查看的开发留出地图M06/M07、8个任务/solver条件、每条件2个replica。
只新增16条新模型轨迹，原样引用已审计的80条Official+SA、Dual16+SA、未训练探索、旧条件模型和旧状态模型轨迹。
不重跑正常基线，不筛选任务，不更换seed。原五方法全部展示，主要增量比较为新模型对旧条件模型，另看相对探索、Dual16和Official的结果。

这是复用开发集的诊断，既不是新地图确认，也不是重复16条独立地图。训练6图与评价2图隔离，评价结果不得用于本轮拟合。

## 执行合同

- `max_decisions=null`，原生修复轮数上限0，不用大整数伪装无上限。
- 保留2500万修复generated nodes预算，以及单PP 20秒、episode 900秒、外部fuse 960秒安全保护。
- 零冲突为成功；节点预算耗尽为预算内未完成，不是无解证明。安全中断记未知，不丢掉后继续报告完整成功率。
- 冻结原256特征归一化参考，超过后该输入为0，但不控制停止。
- 新模型执行原 `trained_actor` 路径；仅输出身份为 `uncapped_condition`。保留原phase/pair/replica随机流，不能因新模型名字改变PP与SA随机数。
- 初始fingerprint、任务、map ID、split及RNG stream与所有基线逐项配对。
- 配置workers=20，但只有16个新作业。并行工作量与节点只用于机制比较，不把并行wall-clock写成TTF。
- 所有输出在 `build/sa-uncapped-update-comparison-v1`，模型、实现和源结果SHA在采集前登记。历史文件不修改。
- 整组运行锁、每作业原子结果与显式resume；已完成结果校验引用，部分结果或异常不自动重试。stop在当前批次结束后停下。

## 预设分析

完整结果及轨迹审计后，报告各方法成功数、净新增/净损失、逐地图与逐条件结果。
路径质量、修复次数与节点在同一共同成功集合配对，失败时间不记零，也不混用不同方法的成功子集。
报告新模型对旧条件模型及探索策略的第一次动作分歧；在分歧前检查同状态、同候选、同特征、同抽样随机数及同动作后状态，排除更换随机流造成的假差异。

解释规则不要求所有案例更好：

1. 对旧条件模型和未训练探索均净增成功，且不低于Dual16：开发集正信号，仅允许建议新随机流复核，不晋级正式控制器。
2. 对旧条件模型及Dual16均净损失：开发集退化，保留逐例互补结果，不晋级。
3. 其他情况：混合或无净增，逐项报告，不将门槛附近或局部改善写成整体成功。

两张已查看地图不足以支持确认性地图bootstrap或独立泛化结论。本轮不新增统计阈值要求每图全胜，也不根据中间结果加replica、换模型、调SA温度或延长预算。

## 验证与后续

测试新旧随机流一致、16/80覆盖、无决策上限、模型身份、原型与训练来源、配对完整性、未知拒绝、resume和中断保护。
新16条完整审计复算路径、冲突、特征、模型概率及选择；80条旧结果引用已登记审计并检查原文件SHA。
代码与协议在采集前提交备份，结果另行提交；正式native和模型保持原SHA。

有正信号时先冻结并在新随机流上复核；无稳定收益时分析新增/损失，不再次重拟合同一批actor-0轨迹。本轮不自动追加训练或正式计时。
