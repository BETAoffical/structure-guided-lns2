# 退火数据重训准备度：只读审计

本轮不调用求解器、不训练、不改控制器、不计时。只读取冻结的96条120秒SA轨迹与11条300秒失败并集轨迹，分开报告，不能把重复来源合成107个独立任务。

## 与历史的区别

HistoryRank已经否定简单新颖度/单特征替代；Feedback Exploration已经测试过失败记忆、随机探索和后继状态救援，不能改名重跑。
旧精确条件正反馈难以复用的推理依赖冲突单调下降。SA允许冲突回升，理论上可能重新访问曾经成功的条件。本轮只核实它在现有数据中实际出现多少，不预设反馈方法会有效。

## 统计边界

- 每条轨迹独立记账，严禁跨task、seed、控制器或120/300秒来源复用历史。
- 分别统计agent集合键、可见PP问题键、问题加温度/预算键。
- 可见PP问题包含实例、地图、所选车辆起终点、全部外部路径、所选集涉及的旧冲突对数和动作协议；不含已移除的所选旧路径。
- 外部路径用带agent ID的逐路径SHA组成结构化键，不改变正式fingerprint或RNG。
- 问题键忽略PP随机顺序、截止时间和隐藏native历史；只是可观测经验复用上限，不证明搜索结果同分布或可直接缓存。温度/预算严格键也不补足全部隐藏状态。
- 原温度随轮次变化，严格温度键的零重复可能由定义直接决定，不将它当成学习无法跨温度泛化的证据。
- 每一步先查询所有候选此前的完整观测，再读取当前结果并更新。截断保留为censored，不记成失败标签；未来完成与否不进入前置特征。
- 正反馈只指完整尝试的一步冲突下降，不等于长期成功。退火接受不等于正标签。
- 原轨迹只知道实际执行动作，未选候选没有新标签；有历史观测也不能虚构离线替代闭环。

## 候选标签盘点

复用三个已查看地图0006状态、57个候选、228个四trial结果。重新统计相对原选项的四trial均值、两半均值改善、逐trial改善和一步可行。
这不是新的稳定性确认，不追加trial，不选择新阈值。尤其不能将228个trial当作228个独立状态。旧H4和本轮回温分支不能拼成这些候选的后续标签。

## 执行与停止

20个独立只读分析进程，单episode分析安全上限600秒；使用已有原子输出、运行锁和显式resume。源SHA、初始/终态fingerprint和接受规则必须一致。错误停止，不自动重跑求解器。
使用已保存的路径delta重建状态；不再次执行逐路径物理搜索验收，该验收已由冻结源报告完成。本轮验证源文件SHA及状态链。
输出 `build/sa-training-readiness-v1` 的plan、逐episode统计和总报告。入口 `python scripts/audit_sa_training_readiness.py prepare|run [--resume]`。

无论历史正反馈多少，本轮不能直接发放训练许可：已执行动作数据不足以给未执行候选提供监督真值。若存在新的SA条件复用现象，保留为机制设计依据；若仍无稳定可选择机会，停止以“多加退火数据”作为充分重训方案，不重复反馈探索实验。
