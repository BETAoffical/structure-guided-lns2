# Dual16 非单调接受：从作者初始路径开始的移植验证

## 新问题与旧失败的区别

恢复标签 `post-cplns-complete-greedy-20260912`；新分支 `codex/dual16-sa-initial-state-transfer`。
以前的SA移植在Dual16已经访问的5个末期状态（1--3对冲突）才开始，standard/完整贪心/SA分别14/15/13成功，不能忽略。
这次使用作者参考中已保存的20个初始化完整路径（9--35对冲突），从第一个修复动作开始使用同一个冻结Dual16。
检验较早启用非单调接受是否避免进入困难状态，不重跑旧末期60条，不证明一步目标就是唯一根因。

## 三路和固定实现

- 冻结Dual16选择器、候选、GBDT、特征、PP随机种子策略；不重新训练，不改正式V2/Dual16。
- standard：本项目原来的严格 `>` 提前中止与单调接受，不采用作者的 `>=`。
- complete_greedy：已有隔离原生扩展的完整PP＋只接受冲突不增加。
- annealed：同一隔离扩展完整PP＋指数退火接受，不新写或重新编译SA实现。
- 三路从相同的导入路径开始；每个状态共同的PP seed与独立接受随机数不包含臂名称。
- T=1000，每次修复后乘0.99，不在中途重新升温。使用现有 Python 独立连续均匀随机数，
  不复现作者的 `rand()%10000` 共用随机流；属于机制移植，不称逐位复现CPLNS。
- 完整状态fingerprint和低层历史仍参与原Dual16候选生成：后续路径/低层计数变化会改变候选，
  因此实验比较现有完整控制器，不声称纯粹隔离某次接受概率。
- 本轮不重启、不计正式TTF、不改变地图、动作空间或第二阶段。

## 导入、smoke、采集

1. 精确使用前轮5任务、seeds 0/2/3/5的20个作者初始化事件，不重新生成初始路径。
2. 用本项目 `reset_paths` 导入：agent ID、栅格、每条路径、起终点、冲突对数、SOC逐项一致；
   native内部计数和元数据重新初始化，不能声称与作者内部完整状态相同。
3. 20个准入作业登记初始状态、第一候选池/成员/分数/选择；无效导入立即停止，不修正式native来迁就样本。
4. 每地图seed0，两步smoke，三臂加冻结旧native，共20作业。
   旧native与隔离扩展默认模式的路径、fingerprint、候选与分数必须完全一致，且无删失。
5. 通过后20来源×三臂=60个诊断，20进程。每条最多256次修复，单PP5秒，控制循环资源120秒，
   进程fuse180秒，整轮阶段预算1800秒；步数只是诊断资源上限，不恢复正式控制器的100步限制。
6. 独立作业、原子结果、运行锁、SHA与resume，创建 `STOP` 文件可在当前批结束后暂停。
   未解释错误、非法路径、回滚或身份不一致即停止；超限标记删失/未知，不当作无解。

## 指标与判定

继续沿用旧移植pilot的成功恢复门槛，而不是看结果后降低要求：SA相对两种对照均新增至少2个成功配对、
覆盖至少2个不同来源状态、没有配对成功损失、总generated不超过各自1.25倍、无资源删失，才记开发性恢复信号。
来源是20个不同初始化状态，不将其声称为20张地图。
另独立报告共同成功样本上的修复次数胜负和合计、冲突AUC、generated、最终冲突及接受变差次数。
若恢复门槛没通过但轮数有优势，仅记描述性信号，不能默认晋级；删失时先报告证据不足。
少调用不等于TTF更快，失败不能凭调用少算胜；不把共同成功子集代替完整成功率。

原来一步监督标签与长尾可能相关，但不是通过本实验预设的结论。
SA有效也只支持接受/探索层存在机会；SA失败也不能证明所有长期控制无效。
本轮通过后仍需另立独立状态/串行TTF确认，不自动启动正式计时、RL或大规模扩采。
