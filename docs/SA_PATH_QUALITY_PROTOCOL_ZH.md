# Dual16＋退火：复用路径质量任务的串行计时

用户明确不采用栈邻接PP工程优化，直接比较当前方法。三种方法共用原冻结native：`build/linux/sa-wall-clock-v1/lns2_env.cpython-310-x86_64-linux-gnu.so`，SHA `5b1b2af1a8a388e76567c3f1e874674ef8c2701775c3706d0a1e4d9678d1925d`。不使用或续跑PP组件计时数据。

## 固定范围

复用旧路径质量实验的14任务、11地图、seed 51/52。8仓库、2Room、1Maze32；原2项Maze128继续隔离。只复用任务字节，不复用旧时间或依表现筛选任务。这是开发性复测，不是独立泛化确认。

对比 Official Adaptive、Dual16、Dual16＋退火。学习方法共用冻结模型和SingleFullCheckPool；两者使用相同显式动作seed派生规则。退火保留已有 `T=1000×0.99^iteration` 及独立接受随机流，不调参。Official 使用原标准接受与官方随机流。

三组各84个episode，共252个：首解即交付（上限120秒）；第一阶段＋官方第二阶段总60秒；两阶段总120秒。串行单worker，方法顺序六种排列轮换，无修复轮数上限，硬超时为规划预算＋120秒。

第二阶段对全部方法使用同一官方 Adaptive anytime LNS、PP＋SIPPS、邻域8，直接接收首解并使用共同独立stage2 seed。预算是从reset前开始的总预算，不是额外60/120秒。

## 时钟与完整性

复用PathJournal、官方handoff、supervisor和路径重新审计。主时钟reset前至校验后有效路径写出交付，TTF另记第一次可行状态返回。模型加载及环境构造在常驻规划器口径外，冷启动另列。首解后路径保存及收尾不从时间中扣除。

首解/末解都保存，终点永久占位、顶点/交换冲突、SOC、makespan、等待步数重新从路径检查。每步保存候选池、选中候选、实际动作、接受温度/随机值、路径delta、PP计数及时间；完整trace审计在episode结束后进行，不占下一episode规划预算。临近截止的合法proposal耗尽只记超时，不能冒充非法动作。

先做56个任务/seed/预算专属reset核验，再功能smoke验证两阶段与三方法。正式排程不接受smoke修改后的预算。任何native/模型/输入身份变化、非法动作、路径损坏或未解释错误停组；正常无解超时保留继续。

结果文件原子写入、SHA manifest逐episode落盘。STOP_AFTER_EPISODE请求在当前episode完成后生效。已完成作业可校验续跑，不完整作业与异常不自动重试。原数据及结果不覆盖，保存于`build/sa-path-quality-evaluation-v1`。

## 分析

成功率用全组分母。TTF、交付耗时、SOC、makespan、等待与建模完成时间在每对方法共同成功条件上比较，非共同成功项完整列出，失败不填零。所有三对方法按协议、地图、地图族报告均值、中位数、胜负数及5000次地图级bootstrap。

建模完成时间为 `交付耗时＋makespan×步长`，主步长1秒，另报0.5/2秒，不称为真实机器人实测。SOC改善不保证makespan改善；不以TTF单独替代整批完成结论。本轮不因结果自动晋级默认控制器。

代码、配置及测试在计时前本地提交并备份。用户已授权全部三组串行计时；不推送远端。预计正式计时约5–6小时，随困难任务及主机环境变化，不含前期适配验证。
