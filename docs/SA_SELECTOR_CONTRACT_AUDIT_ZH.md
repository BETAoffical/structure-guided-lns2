# 新选择器退化：历史、实现与训练合同复核

## 结论

本轮没有修改生产控制器、模型、候选生成、PP/SIPPS或SA，没有训练或新增求解。
复核47个开发状态、96个闭环episode、18,466次保存决策后，没有发现新的已执行动作计算错误。
这不是全仓库无bug证明，也没有消除20个资源截尾。

当前更值得整改的是训练与连续控制之间的合同，而不是再换一个回归器：

- 监督标签回答的是“此处换一个动作，之后让旧Dual16+SA继续，32步内能否完成”。
- 实际部署却让新模型在每一步继续换动作，还会进入训练未覆盖的候选比较。
- 新模型在旧续跑下的早期完成率也略好，却在连续接管时恶化，不能只怪H32窗口太长。
- 不要求全部地图都赢；本轮拒绝替换是因为已观察净成功数和共同成功工作量都更差。

保留冻结Dual16+SA。线性模型优于本轮新GBDT是相对改进，不是超过现有控制器。

## 查了哪些错误

| 检查 | 当前证据与边界 |
|---|---|
| 数据或模型混用 | 原闭环注册输入、模型receipt、384个输出及本轮共1,618项登记输入哈希通过 |
| 初始状态与候选不配对 | 32组的三方法第一步fingerprint、完整候选池、四候选子集、特征完全一致 |
| 模型分数/选择算错 | 前轮全轨迹重算通过；本轮相关Windows/WSL推理、训练矩阵与微型闭环测试继续通过 |
| 训练与部署用不同特征 | 两端都使用`profile_features(..., "dynamic")`，不是一端有历史、一端没有 |
| 把未知当失败标签 | 训练无截尾；闭环仍单列资源截尾，没有补成失败后重训 |
| 前次启动错误 | `status`缺失和错误回调`row`假设已在前轮修复；失败的v1没有策略结果，不与v1a混算 |

温度与PP/SA随机流使用绝对decision；正式续跑与标签的策略身份不同是已登记的设计差异，
不是偷偷改了官方修复器。没有发现支持回退native或重跑96个episode的新证据。

## 新增数据复核

### 1. 短窗口也有离线优势，不能直接改训H8

使用原47状态的留图预测，不重新挑动作、不拟合、不选择最有利窗口。
从已有trial的首次完成步数读取固定8/16/32步完成率，按地图等权：

| 选择规则，后续均为旧策略 | 8步内 | 16步内 | 32步内 |
|---|---:|---:|---:|
| 冻结选择 | 24.27% | 36.30% | 50.10% |
| 线性选择 | 25.31% | 37.86% | 52.71% |
| GBDT选择 | 25.99% | 41.09% | 54.53% |
| 四候选均匀随机期望 | 25.30% | 38.20% | 50.89% |

H32逐项复现原正式离线报告。这些是已经反复查看的开发数据，不是新确认结果。
但它排除了一个过于简单的解释：“模型只是选了32步能完成、前期必然更慢的动作”。
新模型在8/16步也略好，而新的持续闭环更差，不能据此直接换短窗口再训练。

### 2. H32标签确实遗漏速度，但这不足以单独解释退化

47状态共有282个候选对，其中167对H32经验完成率相同。
这167对中91对的1至32步完成曲线不同。
9个全部候选8/8完成的状态，H32标签没有排序差异，但平均完成步数存在差异。
例如一个状态不同候选为1.125至4.25步，另一个为3.875至10.25步。

这些是同样本描述，不是可靠的真实动作差异或新的训练目标。
步数也不是时间或低层节点数。不能改成预测剩余修复轮数，就宣称对齐TTF。
本轮不生成Cost-to-Go或剩余轮数监督标签，不按这些事后差异挑新赢家。

### 3. 单变量范围不等于候选比较覆盖

新增检查选中候选与anchor的特征差值，是否超过训练中任意候选对的最大绝对差值。
这比仅检查一个特征值是否落在训练最小/最大值内更贴近当前排序输入。

| 连续策略 | 改选次数 | 改选中至少一列差值越界 | 比例 | 第一决策越界/32 |
|---|---:|---:|---:|---:|
| 线性 | 5,205 | 990 | 19.02% | 9 |
| GBDT | 7,140 | 1,283 | 17.97% | 13 |

越界包括来源统计、冲突覆盖、路径拓扑等。它不只发生在很晚的状态。
两种新模型分别有39、33次决策涉及训练中从未变化过的特征差值。

注意：这是坐标范围诊断，不是联合分布检验，更不是越界导致失败的因果证明。
本轮没有未选动作的结果，不能计算越界后“回退就会更好”。
冻结策略与自己比较的差值恒为零，不能把它的0越界当作训练充分的证据。
不得直接把这些范围改成在线回退门槛。

### 4. 当前线性模型不是完整的历史条件化策略

127列输入中没有`history.*`；这是前期历史增量实验未获支持后固定的消融配置。
36列在训练的同一候选池内从未变化，其中包括温度、全局状态量和部分未出现的size类别。
它们的线性系数都接近浮点零，绝对值不足3e-16。

纯线性差分无法表达“同样的候选差异，在不同温度或不同冲突负载下改变偏好”。
这在原协议中已明确，不是本轮新发现的编码bug。
GBDT保留共享量且允许非线性交互，但仍退化，所以不能断言补一个交互项就能修好。

## 历史排除项

| 已尝试 | 不能再作为直接修复方案的原因 |
|---|---|
| 容量、图模型、时空网络 | 没有闭环优势；新网络训练拟合好不等于留图有效 |
| 改短期目标为H32完成 | 本轮模型已经如此，不能再归为“一步贪心” |
| 降低介入频率 | 历史单次介入18/32、连续15/32、冻结20/32，未证明频率门控有效 |
| 只用新策略续跑重贴标签 | 历史续跑变差成立，但候选相对排序翻转不稳定，未证明换标签足够 |
| 直接anchor比较或矛盾否决 | 旧成对一致性审计仅有弱、噪声信号，没有确认救回连续闭环 |
| 更多样性、禁止重复集合 | 新模型重复更少，但工作量更大，不能靠重复率单项解释 |
| 更便宜的一步、节点分配 | 既往结果不能支持它们代替任务完成目标 |

## 下一步应该改什么

建议把下一轮问题固定为“训练过程是否能学会自己的连续决策”，而不是再次挑最好的静态排序器。
这仍是InitLNS高层选择，PP/SIPPS和SA不动，不是重写整个求解器。

1. 先登记一个有界的迭代训练原型，旧Dual16+SA继续作为不可覆盖的基线。
2. 训练状态必须包括当前学习策略实际访问的状态；状态来源策略和标签续跑策略分别登记。
3. 同一候选分别保留参考策略、当前策略的续跑结果。预算从同一来源episode的剩余预算定义，不能每步无声重置一个新的H32窗口。
4. 使用完成事件和固定预算结果，未知仍保留未知；不能把一步下降、便宜修复或剩余轮数改名成任务完成。
5. 每次更新后先做小型完整闭环对照。允许部分地图退化，考察净成功数与共同成功工作量，而非要求所有指标全胜；不以离线分数自动授权下一轮。
6. 第一轮没有净收益时，区分候选无机会、标签不可区分、学习失败和资源截尾。没有新的可检验信号就不追加参数版本。

这与以前仅聚合旧状态、只换H1/H4/H32标签、只测一次新策略续跑不同；
但不能声称类似思想从未尝试，更不能承诺本轮诊断已证明它会成功。
它需要独立协议决定准确预算、状态数及最多更新次数，本次没有启动该采集或训练。

论文方面重新核对了[DAgger](https://proceedings.mlr.press/v15/ross11a.html)与
[LOLS](https://proceedings.mlr.press/v37/changb15.pdf)。
前者强调策略改变会改变后续观测分布；后者在算法1中使用学习策略到达训练状态，
并在每个完整续跑分支选择参考或学习策略评价动作。
这为训练与部署对齐提供设计依据，不是MAPF实验，也不保证对PP随机修复和本项目有限标签适用。
LOLS的续跑混合不是在部署时每步随机切换控制器，更不等于已有SA接受机制。
