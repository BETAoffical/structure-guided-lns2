## 3. 更新是否改变了选择

Windows PyTorch与WSL NumPy portable在238份Train输入上的概率最大误差为2.2204460e-16。
每份输入检查16个固定draw，共3,808次动作完全一致。这里没有新增C++神经网络推理器。

在全部12,180个已记录Train状态上，用actor-1重新计算概率并使用原draw：

| 诊断 | 结果 |
|---|---:|
| 相同输入及draw下选择改变 | 6 / 12,180，约0.04926% |
| 平均概率分布总变差距离 | 0.0000608682 |
| 任一候选概率最大绝对变化 | 0.0002043626，约0.02044个百分点 |

这是**旧状态上的离线动作敏感性检查**，不是actor-1闭环轨迹；一次不同动作也可能改变后续路径，不能从6次直接推出真实闭环只有6处变化。
76/96属于未训练actor-0的采集结果，不能写成actor-1的完成率，更不能与历史不同预算/随机流的Official结果直接比较。

## 4. 结论与下一步

正式机器结论为`first_on_policy_update_verified_not_closed_loop_evidence`。

- 已验证：资源恢复保留科学合同、行为轨迹可重放、完整回报可产生非零策略梯度、一次更新及跨平台推理可复现。
- 尚未验证：新策略的完成率、尾部恢复、节点效率、TTF或跨地图泛化。正式Dual16/SA及冻结模型不替换。
- 当前限制：组内成败差异稀疏、固定小步更新量很小；仅初始状态归一化的后期饱和风险仍在，本轮没有同时修改它。
- 不能下的结论：既不能说新模型已经更好，也不能据此否定RL或断言归一化是全部问题。

下一轮先明确可检验的策略变化与训练预算，不因一次小步几乎未改变动作就花费数小时做正式TTF。
若完成原先的两步原型，第二批必须由actor-1自身重新采集并单独登记，不能重复利用actor-0旧轨迹假装on-policy，也不能自动扩大本轮范围。
若要更改归一化、学习率或更新次数，须另立训练合同；保留本次固定结果，不在看到留出表现后调参。
两个小步本身也只验证流程，不能被包装成充分训练或对RL可行性的最终测试。
