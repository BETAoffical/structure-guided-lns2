# actor-2冻结开发闭环比较

## 单一问题与边界

检验第二次终局更新相对actor-1是否增加完成数，而不是再训练或寻找更好的离线代理。
固定actor-2、actor-1、未训练锚点探索和Dual16+SA四种方法，每种16条，共64条。
复用两张已查看开发地图的八个任务/初始solver条件，不筛选困难或简单任务，不改变初始路径。
随机流使用未登记的replica 4/5，phase与原科学stream seed不变；扫描历史登记拒绝复用。
这是已查看开发图上的新随机流诊断，不是独立地图泛化，不合并旧分母来挽救本轮结果。

actor-2输入、父子谱系、update、portable parity与文件SHA须通过完整链式校验。
评价地图不属于两批Train地图；评价标签不得回流到本轮冻结训练。
不重训、不新增模型、不改候选池、特征、PP或SA。没有Official新运行，此轮比较目标是隔离新增训练效果，
不能用缺席Official的本轮数据宣称超过官方。

## 执行协议

- 无决策次数上限，native max_repair_iterations=0；256只作冻结特征参考。
- 每episode修复generated nodes预算2500万，PP安全上限20秒，episode安全上限900秒，外部fuse960秒。
- 正常终局为可行或节点预算耗尽；PP中断和保护超时为未知，发生后暂停检查，不自动补成失败或重跑。
- 20个进程，最多4批；每批结束检查安全停止标记。逐episode原子结果、随机流与模型身份独立，支持显式resume。
- 全量校验初始fingerprint与配对随机流、逐步候选/特征/动作、接受规则、路径与终局计数。
- 比较父子第一次动作分歧，要求此前状态一致、分歧时候选/特征/抽样数一致。
- prepare与dry-run不运行求解。先测试、提交代码配置与门槛，再登记并启动采集。
- 4批外部fuse的预算合计约64分钟，不含登记和审计；不是耗时预测，也不是TTF结果。

## 结果与解释

逐方法列出成功数、停止原因、决策数、节点数、SOC、makespan、等待步数、逐地图及每个配对位置。
所有配对位置用于成功数；计算量和路径质量仅在各自共同成功位置比较，明确分母。
本轮多进程耗时不作为真实TTF，失败不补零时间，未求解路径的SOC不作为可行解质量。

主解释固定为：
1. actor-2相对actor-1、探索均净增成功，并且不低于Dual16：开发正信号，需要独立重复确认，不自动晋级。
2. 同时比actor-1和Dual16少完成：开发退化，保留模型与负面证据。
3. 其余为混合或无净增，分开说明相对各对照的收益，不等于模型绝无价值。

允许个别案例损失，不要求每张图或每条随机流都获胜；没有新增全胜门槛。
未通过时先审查干预是否生效、失败冲突及工作量，再决定信息来源或探索是否需要改变。
不自动追加replica到显著，不再对同一批Train反复更新，不恢复一步/H32目标。

入口：`scripts/compare_sa_second_update.py prepare|verify|dry-run|collect|audit|report|stop`。
采集必须使用已登记native的WSL Python，后续resume显式提供 `--resume`。
源码和协议本地提交，数据保存在 `build/sa-second-update-comparison-v1`，旧报告保持不变。
