# 非零父策略的一次终局续训

## 边界

仅使用已审计的第二批当前策略96条Train轨迹，报告SHA固定为
`869ae98b2fbbd3b7d9f1aa014f46576a11b8e9599fd118d91b206d4cbea628c1`。
探索对照、旧actor-0轨迹与开发留出标签不进入梯度。本轮不新增求解、正式TTF或闭环评价。
仍无决策次数上限；2500万节点预算仅用于验证已采集终局。256仍只是冻结特征参考。

父模型为现有actor-1 `uncapped_condition`，子模型iteration为2、名称为`second_condition`。
保留129维输入、32单元残差网络、原归一化、候选生成、Dual16锚点、PP和SA，不删除或覆盖旧模型。
本轮是学习系统原型的续训，不能直接替代正式控制器。

## 唯一更新

固定先验为q=0.9倍锚点one-hot加0.1倍均匀分布，策略为softmax(log(q)+2*tanh(network(x)))。
行为概率只用于回放与父子KL比较，不能当作q后再叠加完整残差。
历史actor-0更新器的限制及结果保留，新增独立模块，不修改已登记源码。

终局可行回报1、节点预算未完成回报0；安全删失不补成0。
条件内其他三个replica作基线，地图/条件/episode等权，乘整条轨迹log概率之和，不除以轨迹长度。
按固定job顺序累加一次完整梯度，不重复epoch、不重估归一化、不更换基线或奖励。
原步长保护保持不变：起始参数L2距离0.25，最多12次二分回退；平均状态KL上限0.002、
平均轨迹KL之和上限0.1、最大状态KL上限0.02。回退只判断概率偏移，不运行MAPF挑选步长。
所有96条父策略轨迹都参与KL检查，包括终局系数为零的轨迹。
零梯度或没有合规步长时记录不更新，不自动扩采、放宽阈值或尝试其他参数。

## 验证与执行

1. 先提交代码、配置、测试与协议，再冻结输入、源码和父模型SHA。
2. 20进程提取96条缓存，重算完整终局系数并与上一批报告逐项核对；不读取探索trace。
3. 非零父模型下验证批量概率与NumPy及逐状态Torch一致；批量与逐状态梯度一致。
4. 使用六张Train地图中按job排序首尾各一条轨迹的首尾状态，另含存在时的第256步，进行真实输入数值检查。
   有限差分检查各参数张量最大绝对梯度位置。合成测试另覆盖负系数、不同候选数量与单候选。
5. 单线程、固定顺序执行唯一参数更新，保存完整回退记录、父模型SHA、cache及数值检查SHA。
6. 从每条轨迹抽取决策0/32/128/255/256及最后一步进行新模型Torch/NumPy/WSL portable对齐，
   每状态16个固定draw检查选择一致。不创建求解episode。

CLI：`scripts/train_sa_parent_update.py prepare|verify|extract|check|train|parity`，Torch侧parity增加`--torch`。
Windows现有Torch环境训练，WSL仅做portable校验，不安装依赖。
部分提取、重复更新或输入变化均拒绝继续，需要先检查；阶段状态原子写入，所有结果留在新忽略目录
`build/sa-nonzero-parent-update-v1`。训练前后保存本地Git bundle及紧凑证据备份。

## 结果解释

概率和动作发生变化仅说明干预生效，不等于新增成功。训练完成也不代表通过闭环门槛。
完成后单独登记父模型、子模型、探索和Dual16的开发配对比较；本轮不自动启动该比较。
第二批有效信用仍只来自4条件、3地图；一次续训不能被描述为已经解决稀疏反馈或高负载长尾。
