# 配对完成差模型：有界动作数据修正Pilot

2026-09-17。只研究新选择模型，不修改初始化、候选生成、PP、SA、冻结模型或正式控制器。
本协议在新反事实标签产生前登记。没有TTF、RL、正式模型部署或自动扩采。

## 为什么还值得做这一次

原204观察点只有旧策略已选动作的后果，不能充分监督同状态替代动作。上次8根桥接只测旧动作及两个历史模型首选，
候选支持不完整；目标交叉对照发现完成目标有局部信号，但没有可靠超过旧选择器。
本轮只修正一个可识别的问题：挑战候选的采样不读模型分数，再用相同干预数据比较直接完成率与同状态配对完成差。
因此可以区别“干预数据帮助了所有模型”与“配对训练本身有增量”；不是只给新模型更多数据后归功于架构。

这不构成新长期价值理论，也不能保证解决噪声。H仍32、trial仍8，不继续增加树、历史特征、窗口或重复次数。
旧H4/H32稳定性FAIL不变。本轮完整报告重复trial的分歧；不通过挑经验赢家或丢弃平局使其看起来稳定。
即使有信号也只是开发证据，不能恢复静态迁移主张或直接接入控制器。

## 固定范围与盲采样

- 复用高压力来源中的Dual16+SA轨迹，8张已有仓库地图，不使用Test/OOD、旧Validation或新地图。
- 排除上一轮8个桥接根所在的全部episode；这些排除项在标签产生前固定。
- 只检查decision 4、16、32、64、128的决策前状态。每图选一项early(4)、一项continuing(其余)，不同episode。
- 先从较稀少的continuing层按固定哈希选取，再从其他episode选early。不会按未来成功、冲突下降或最终超时筛选。
- 必须8图各2根，共16根；缺额就停止，不用其他地图或阶段填补，也不事后换seed。
- 每根保留冻结旧动作作为必要对照；其他候选按固定哈希在实际大小1--4、5--8、9以上三组取样，余位按哈希补齐。
- 原在线池和对照动作仍来自冻结机制。“盲”指挑战者采样不读分数，不是宣称整个候选生成不依赖旧策略。
- 每根最多4个候选，原池不足4时保留真实数量，不能捏造或重复集合。无可选替代动作的状态不产生排序标签。
- H1旧诊断和来源轨迹可能已经看过；这里的前瞻性只针对尚未运行的新分支标签，不是全新独立数据确认。

## 采集合同

最多`16*4*8=512`分支、16384次续跑修复，另计16个原动作控制和前缀重放。
每根独立reset并重放全部显式prefix，核验路径、冲突、低层计数、历史、完整候选池及原动作控制。
候选第一步强制执行，之后最多31步冻结Dual16+SA；温度按原episode绝对decision继续。
PP与接受随机化按root/trial/absolute decision配对，不含candidate ID。不同agent集合仍可能得到不同相对PP顺序。
复用已验证的分支执行和逐步校验函数，不另改底层搜索。

- 最多20个活跃分支进程，每次只重放一个根，不产生20乘20嵌套并发。
- 单PP最多5秒；分支安全上限120秒、2500万generated nodes，独立进程fuse180秒；根fuse900秒。
- 这些是并行非计时诊断资源限制，不是TTF。任何资源截断记未知，不补零，不静默删难例。
- 每作业原子文件、根receipt、整组运行锁与进度。只复用完整通过SHA校验的根；中断半根先审计，不自动重跑。
- `request-stop`在当前根完成后停止。resume不绕过停止标记。
- 原动作或prefix不一致、非法动作或未知运行错误停止整组，不更换来源。

## 训练与比较

只用新配对数据，不把旧204个观察点或旧24个模型筛选候选混入拟合。
先聚合8trial。未知标签或任一训练折没有完成差异时，报告数据不足，不把未训练写成模型失败。
保持上轮原型的固定HGB参数，不调参、不导出部署权重；8折留一地图，每折完整隔离两个根及其候选和trial。

比较冻结旧动作、均匀随机的精确期望、直接完成率回归器、配对完成差回归器，以及有乐观偏差的经验oracle。
直接回归器与配对模型使用相同决策前127维特征、完成事件和等状态权重，只有目标编码/训练方式不同。
paired使用254维差/均值编码，必须注明不能把编码差异与目标效果完全分离。
只报告共同已采候选池结果，不当作完整19/20候选在线策略表现。

主要量为留图选择后的32步完成率，地图级paired bootstrap 5000次，另列逐根、分阶段、原模型受损案例和split-half稳定性。
有限离线信号需paired相对冻结动作至少提高5个百分点、CI下界不小于0、至少5/8图严格提高，且优于随机、不差于直接回归器。
这是进入下一次设计讨论的信号，不是控制器晋级；全部结果均`promotion_allowed=false`。
若只直接回归改善，不能归功于配对架构；若均无改善，则停止本pilot，不自动扩充根、H、trial或再换参数。
没有过当前样本不代表所有新模型不可能，只否定或限制本次数据/表示/目标组合。

## 执行顺序

1. 单元测试、提交协议及实现，保存本地恢复标签和ZIP。
2. `prepare`读取已有轨迹；`dry-run`给出准确根、分支、reset和修复次数上限。它们不调用solver。
3. 覆盖通过才`collect --limit 2`，审计原动作和完整续跑；同一冻结版本继续`collect --resume`。
4. `analyze`逐分支校验并生成训练索引。数据合格才在Windows执行`fit-evaluate`，最多8个折进程、16次小型拟合。
5. 根据结果解释失败或有限正信号，保留原正式方法；不运行TTF、不继续第二轮参数试验。

入口：`scripts/run_sa_paired_completion_pilot.py`。WSL使用冻结`build/linux/sa-wall-clock-v1`，不安装sklearn；训练用Windows现有1.5.0。
输出只进入`build/sa-paired-completion-pilot-v1`。源码检查点与结果ZIP分开保存，不把分支轨迹提交Git。
备份标签`pre-sa-paired-completion-pilot-20260917`指向修改前原型。保留全部旧负面结果及其哈希。
