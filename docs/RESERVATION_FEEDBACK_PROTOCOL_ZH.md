# 第三、四轮：自动反馈车辆与失败归因

## 新问题与旧实验区别

前两轮仅证明事后选定235的占用引导有影响。本轮不使用235、成功路径或最终控制器成败来选择车辆。
沿用24个已查看开发状态、4张地图、每状态两个固定seed，不作为独立验证。
借用普通PP的已尝试前缀提取反馈，不扩大邻域、不改变规划顺序、不添加硬约束。
这是搜索CAT的单条占用消融，不是历史的blocker重规划扩张或compact-blocker。

## 冻结方法

先验证48项普通PP与旧结果的完整路径和逐车搜索签名一致。
普通PP回滚或接受但全部路径不变时才触发；其余状态保留并标记不触发。
从普通PP全部实际插入记录提取selected-to-external冲突事件，按以下顺序选择一辆外车：
涉及的不同选中车辆数降序、事件数降序、最早事件时间升序、agent ID升序。
没有外部反馈时明确不适用，不改用成功见证或扩大搜索。

四个对照：

1. 冻结普通PP，复现后保留结果。
2. 一次fresh-seed普通PP重试。
3. 忽略反馈最高分外车的搜索CAT，但其真实旧路径仍进入每次接受账本。
4. 从同一反馈列表确定性均匀选一辆外车，作随机反馈对照。

三个新增分支使用相同fresh seed、相同30秒整轮与5秒单搜索预算。外车不能移动。
反馈列表只有一辆时，定向与随机相同，不记为结构选择器独有收益。
每个分支最后只在严格少于普通PP的冲突数时采用，否则精确保留普通结果，额外工作仍完整记录。
原生reset_paths只用于最终路径验证，不声称重放了闭环全部计数和Adaptive历史。

## 门槛

- 48/48普通结果复现，0未知/非法路径/未解释错误，24个状态全部保留。
- 在两个seed均触发且均可用的状态中，主方法相对普通PP两次均有新增严格改善：至少3个状态、
  至少2张地图、至少1个失败长尾来源。
- 至少2个这样的状态相对fresh retry及随机反馈也均严格更好。
- 单seed改善、只在快速对照改善、相同反馈列表导致的平局，都不能替代上述门槛。
- expanded/generated与总调用完整计入，不能将机制通过称为TTF或上线许可。

## 第四轮归因及停止边界

无论第三轮是否通过，使用全部已保存分支做一次只读归因：反馈覆盖、路径是否改变、目标冲突是否
仍存在、是否转移到其他冲突、在哪个真实冲突上限检查回滚。不得只查看获胜案例。
固定复盘前缀反馈、整对路径、RepairDependency、compact-blocker、stable4结果。
如果新规则不能恢复失败长尾且与简单重试无增量，不追加更多忽略车辆或seed，不启动闭环。
只有归因提供明确的新可检验原因才允许另立第五轮；无依据时结束本次有界执行。

## 预算和恢复

48个独立状态-seed作业，最多20个进程；每作业原普通复现加最多3条新分支，外部fuse180秒。
理论新分支上限144，未触发或无反馈明确记账；不得把分支数写成独立地图样本数。
最坏串行fuse2.4小时，20进程理想下界不是实际耗时承诺。
输入/原生/代码/result SHA固定，原子结果、独占锁、STOP_AFTER_JOB、完整结果resume。
失败或超时不自动重跑；修复新版本，不混数据。无正式TTF、训练、生产代码改动。
