# 独立计时任务生成修订

## 原因和边界

原登记提交 `7242335` 的12张地图全部生成，24个任务中22个完成。
M07、M10的d25任务在分别分配203/206、193/195个受约束车辆后，
贪心拒绝采样耗尽可用端点。此时没有运行 qualification 或计时，不能称为模型失败。
瓶颈端点最大匹配分别为206、196；这只说明局部端点容量，不证明全任务或MAPF可行性。

原 `build/sa-completion-independent-ttf-v1` 完整保留。
修订输出为 `build/sa-completion-independent-ttf-v2`，只修复两项未完成任务；
12张地图、全部map/task/solver seed、22项已完成任务文件均保持不变。
不修改共享生成器、native、冻结模型、候选生成、退火、预算和计时逻辑。

## 匹配方法

1. 从原静态地图、OD区域和8至100步距离限制枚举合法端点边。
2. 标记存在经过原最高先验瓶颈之一的最短路径的边。
3. 使用现有SciPy最大二分匹配分配受约束车辆，再匹配其余车辆。
4. 固定原task seed控制匹配平局及顺序；最多16种确定性平局序列。
   不重新抽任务seed，不降低车辆数或40%配额。
5. 对完整任务独立重算距离、起终点唯一性、OD归属与每个瓶颈义务。
   匹配重试耗尽记为未知；不能称为MAPF无解。

这不是原拒绝采样分布的等价实现。两项任务保留原OD合法方向，但匹配会改变端点和
实际OD频率分布。报告必须额外列出排除这两项任务、排除其两张地图的敏感性结果，
不得用它们替换主分析。修订完全基于生成失败，没有查看控制器效果。

## 执行

Windows既有Python执行 `scripts/run_sa_completion_amended_ttf.py prepare` 和 `generate`。
WSL既有冻结native执行 `qualify`、`register`、`preflight` 后，执行 `all`。
`stop` 在当前episode结束后停止；`resume`继续未运行episode，之后执行`audit`和`report`。
非计时准入及离线审计最多20进程，正式计时单进程，不把准入或审计算入TTF。

仍为12地图、24任务、48条件、144个episode；比较parent、A和Official+SA。
规划预算120秒，进程保险240秒，无决策数或节点数上限。共同成功TTF与成功数分开报告。
准入有错误则停止，不移除困难任务。
