## 唯一失败的诊断

失败位置为M04子任务、solver239、replica2，episode ID `1c27232ad2c4a9120e7d4583`。

- 初始177对冲突；第84次修复后到达过1对，最终为12对。
- 完成341次修复，generated nodes为25,110,411；最后一个原子修复越过25M边界后正常停止。
- 不是墙钟超时、PP保护中断或决策次数截断；同条件另外三次均成功。
- 最后50个保存的冲突数在2--22之间变化；全程接受113次冲突增加。
- 341次选择包含295个不同的实际agent集合，出现次数最多的集合为10次。
- 从delta重建342个路径状态，按排序后的`(agent ID, path)`计，337个不同，最大重复次数2。
  五次相邻路径未变化，对应五次`acceptance_rejected`；其余336次PP失败原因字段为`none`。

路径内容计数明确排除了iteration、runtime和低层累计计数；不能使用必然随迭代变化的完整fingerprint证明没有循环。
重建终态的科学fingerprint与保存终态一致；delta按设计不保留外部context和runtime字段。

因此，这条失败不能简化为恒定重复同一邻域、SA未生效或PP调用未完成。
较合理的现象描述是：搜索已能接近可行，但仍在多个近可行状态间游走，未在预算内完成最后协调。
路径不同不排除更粗粒度的冲突结构反复出现；当前记录不能进一步证明是排序器、SA日程或PP路径选择的单独因果责任。
更不能因为到过1对冲突就推断延时必然成功。
