# 第五、六轮：搜索候选区间的占用观测

## 范围

恢复点 `pre-search-occupancy-observer-20260910` 指向 `1533a30`。
仍为非计时开发诊断，不改Official/V2/Dual16、不训练、不自动忽略新车辆或扩展邻域。
上轮自动碰撞反馈NO_GO保持不变。

新增独立`lns2_search_observer_native`。通过C++局部编译facade重用冻结SIPP.cpp和probe源码，
仅包装ReservationTable的三个公开返回接口；不手抄搜索器、不改节点布局、比较器、RNG或区间结果。
冻结核心archive、lns2_env和旧probe不重编译、不覆盖。

观测语义是“返回给搜索的带软碰撞标记的区间”。其中可能包括随后被成本边界排除、
dominance处理或未展开的候选，不能说每项都曾展开或因碰撞而被拒绝。
不覆盖未被调用的格子、未返回区间或goal启发式的全部影响，不能据此证明完整搜索因果。

## 有界记录与所有者映射

- 每次单车搜索最多65536个十整数记录，约2.5MiB原生缓冲；满后只计丢弃数量，不改变搜索。
- 记录接口类型、from/to、请求时间区间、候选到达时间、generation/expansion上界及v/e标记。
- 不在搜索内部解析agent，搜索结束后用当次真实fixed paths映射顶点/交换边/终点持续占用。
- 外部与已规划内部车辆分开；仅报告最终返回路径未使用的同一时空转换上的外部接触。
- 所有者去重按(规划车辆、外车、类型、from、to、arrival)，不把重复展开当独立证据。
- 固定排序：涉及不同规划车辆数降序、去重非最终路径接触数降序、agent ID升序。
  top4/top8只是观测紧凑性诊断，本轮不据此执行修复动作。

同时与上一轮冻结probe/native结果比较。顺序中的全部单车调用必须相同；不是只看最终回滚路径。

准入门槛：8/8上述一致、零未知/截断/无归属的正标记、单元测试通过。
此后检查此前8/8缺失的已知事后车辆235是否被新观测捕获：至少6/8才能进入第六轮。
记录top4/top8排名，但不调整排序争取235上榜；不把目标可见性写成在线选择有效。
若门槛失败，分析缺失来自观测范围、所有者解析还是实现，不能只增加缓冲/预算重跑。
