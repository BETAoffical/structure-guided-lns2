# STRIDE Repairability Opportunity V1 报告

## 目的

本阶段回答一个严格限定的问题：在已经记录的候选池中，是否存在相对冻结 V2 锚点 **不牺牲一步修复质量、但 PP 更容易产生真实路径变化** 的候选；如果不存在，V2 锚点本身是否已经是可修复的安全动作。

审计复用 78 个状态、90 个逻辑检查点、2,502 个候选和 40,032 个严格配对 PP 试验。没有新求解、模型训练、未来轨迹或运行时间输入。

## 判定规则

V2 锚点使用冻结检查点中的 `original_pool_anchor_candidate_id`。挑战者必须同时满足：

1. 16-seed mean、lower-half mean、固定 trial 0–7 mean 和 trial 8–15 mean 均不低于 V2；
2. no-progress rate 不高于 V2；
3. `replan_success_rate` 严格高于 V2；
4. 严格配对的 PP 成功 wins 多于 losses；
5. 两个固定 8-seed 半组分别满足 wins 不少于 losses。

其中 `replan_success` 只表示 PP 至少改变一条 agent 路径。它由离线多 seed 试验生成，不是运行时先试 PP。

V2 锚点始终是可接受的回退动作。审计初版曾错误地把“没有挑战者严格胜过 V2”视为候选池缺陷；观察汇总后发现，无挑战机会的状态中 V2 本身往往有 0.9375–1.0 的可修复率。因此已透明修正规则：只有 V2 可修复率为 0 且没有合格正可修复率替代时，才算已观察到候选覆盖缺口。配对、质量约束、cohort 和 claim boundary 均未改变。

## 关键结果：17 个 adverse 重复平台入口

- 冻结结构选择的平均 PP 可修复率：0.3015；
- V2 锚点平均可修复率：0.7132；
- V2 或合格挑战者组成的最佳可接受动作：平均 0.9926；
- 当前选择到最佳可接受动作的平均可修复率差：0.6912；
- 当前结构选择只有 1/17 是可接受挑战者；
- 9/17 状态存在严格胜过 V2 的挑战者，其中 base 候选覆盖 7/17，structural 候选覆盖 9/17；
- 唯一 V2 可修复率为 0 的状态已有一个保持质量的正可修复率 base 候选，因此零成功率覆盖缺口为 0；
- 9 个最佳挑战者尺寸分布为 4、8、16、24 各 2 个，32 为 1 个；6 个 structural、3 个 base；
- 9 个有机会状态中，7 个存在不大于 V2 锚点的候选，全部 9 个都存在不大于当前结构选择的候选。

这不是“邻域越大越好”或“越小越安全”。机会横跨 4–32，且多数不需要增大当前邻域。

## 其他切片

在全部 45 个 `first_repeat_stall` 检查点：

- 当前选择平均可修复率 0.3583，V2 为 0.7056，最佳可接受动作 0.9736；
- 当前选择仅 4/45 可接受；
- mixed pool 在 28/45 有严格优于 V2 的挑战者；
- 45/45 都有 V2 或合格挑战者提供非零机制覆盖。

在首个结构动作检查点，当前选择平均可修复率为 0.875，明显高于重复平台入口的 0.358。这与平台审计一致：结构动作最初经常有效，但排序器在进入残余状态后继续偏好已经变得难修的结构邻域。

## 结论

对当前冻结长尾 cohort，主要缺陷是 **排序目标**，不是已证明的候选覆盖缺失：

- V2 锚点在没有更好挑战者时通常已经高度可修复；
- 有更好挑战者时，当前排序器也几乎从不选中；
- 当前排序器只看一步质量，无法识别同一结构候选在残余状态中 PP 成功概率已经崩塌；
- 现有池已经足以构造“V2 锚点 + 受质量约束的 repairability 挑战者”选择问题。

这不等于候选池设计已经最终完成。数据只覆盖 3 张 Maze 图和历史困难状态，也没有解决 StructPool 固定尺寸的可解释性；但在训练新排序器前，没有证据要求继续无边界扩张候选池。

## 下一步

1. 先审计 repairability 标签的两个 8-seed 半组稳定性、候选相对 V2 方向一致性和逐地图表现；不稳定则不得训练。
2. 稳定后只训练 anchor-relative gate：预测挑战者能否在保持一步质量的同时提高 PP 可修复分布；无合格挑战者时精确回退 V2。
3. 模型不得直接最大化可修复率，也不得偏好小邻域；一步质量约束先于 repairability 比较。
4. 首次验证使用冻结首动作的 bounded continuation，检验从入口是否减少平台形成；随后才允许完整 paired TTF。

本阶段没有候选池推广、运行时接入、长尾避免或 TTF 改善声明。
