# 非单调 PP 接受机制：首轮结果

## 结论与范围

2026-09-11，预注册实现提交 `2c0f633`。结论为 `no_go_this_pilot`，不启用为默认控制器，不启动正式 TTF。
这不是官方 Adaptive 与学习算法的端到端比较：三组都沿用冻结 Dual16 的候选生成与排序，仅改变 PP 完成及接受规则。
5 个已查看的 discovery 状态，每状态 4 trials；共 60 作业、1515 次新修复，另有 444 次前缀重放。
Horizon 64 是本次有界诊断预算，不是恢复正式求解器的修复次数限制。
20 进程采集耗时约 122.8 秒，不是单 worker TTF；20 个两步 smoke 作业另耗时约 26.4 秒。
所有作业完整，资源删失、非法动作、前缀及候选源不匹配、未解释运行错误均为 0。

## 原因分析：观察与推断分开

1. **接受规则不能覆盖所有停滞类型。** 状态 13 每个分支 64 步都选同一候选 ID，冲突始终为 3。
   修复返回成功且不变差，退火没有遇到需要改变的拒绝决定。源路径与最终路径并非完全相同，不能称为严格路径自环。
   这是候选选择/重规划形成的平台，单改接受规则没有作用；不据此证明更大的邻域一定有效。
2. **允许变差不保证进入更好状态。** 状态 22 的退火轨迹出现 1→4→1 和多次回到 1 对冲突，仍有 3/4 未解。
   状态 09 有相反的局部正信号，说明机制是状态相关的；不能事后筛掉状态 22 或据此部署按案例分流。
3. **温度尺度可能过于宽松，但尚未验证因果。** 本轮沿用论文温度 1000、衰减 0.99，并从来源 iteration 继续降温。
   实际 14 次正 delta 的接受概率为 0.99648–0.99894，全部被接受。在这些低冲突末期状态上，它接近无条件接受增加。
   这支持检查尺度的必要性，不证明降低温度就能修好。没有事后增加温度档位。
4. **完整贪心多成功一次不能当作确定改进。** 冲突 pair 集在一次 PP 内累积，已经超过旧界限不会靠规划剩余 agent 自行减少。
   同时，现有冻结控制器用包含低层计数的 state fingerprint 派生 proposal 随机种子。
   状态 22 trial 0 的标准与完整贪心第一步都回滚，却产生不同后继 fingerprint，第三步选中邻域已不同。
   因此多做被拒绝的规划也可能改变后续随机候选；这轮测量的是保留现有控制器时的整体交互，不是完全排除了候选随机性的纯接受效应。
5. **模型适配是未验证解释。** 冻结排序器在原单调流程数据上开发，尚未证明适用于退火访问状态；本轮不能直接归因于模型，也不因此立即重训。

## 下一步边界

暂不部署退火，不追加温度调参、重启、训练或端到端计时。
优先处理已明确的实验解释问题：在独立协议中将“审计用完整 fingerprint”和“候选随机流键”分开，
用同路径、同候选、同 PP order 的分支确认接受机制，不改变当前冻结算法或旧结论。
先查历史是否已有相同隔离；仅在能排除搜索计数引发的随机扰动后，才讨论有界回滚的非单调探索。
状态 13 的候选平台与状态 22 的接受后再停滞必须分开，不再次叠加全量阻挡闭包、随机重试和 RL 来混合解释。
