# 长尾入口与自然恢复：六条已有轨迹的只读检查

## 范围和结论

复用已经登记的两个失败、两个长尾后成功和两个快速对照，读取3776个transition；不新增求解、训练、计时或在线干预。六条轨迹并行解码，最多六个进程，额外启动至20个不会增加有效并行工作。

本轮没有发现可以直接上线的修复规则。找到的进一步线索是：两个长尾后成功案例打破最长停滞时，采用了此前该停滞段候选池中没有出现过的具体agent集合。不能把这解释为“模型曾经看到了成功动作却没选”；也不能从新集合出现与恢复同时发生，断言增加候选数量必然有效。

## 新线索和不能得出的结论

### 1. 候选池一直变化，但选择可能高度集中

Dual16失败例1008轮累计出现11410个不同候选ID，却只实际选择两个集合，分别987次和21次。V2失败例602轮累计出现7653个不同候选ID，却始终选择同一个集合。

这些是跨轮累计的不同集合，不是单轮候选池，也不是11410或7653次已知修复结果。绝大多数未选集合的PP结果未知，不能把它们当成错失的有效动作。

两个长尾后成功案例的退出集合，在此前806或192轮的所有候选池中均未出现。V2失败例的退出集合也此前未出现，且退出后仍未可行。故“选择集中”“有新集合”和“路径改变”都不是充分的救援条件。

### 2. 不能把等冲突接受统一视为坏动作

Dual16失败入口第44步SOC减少83，移除4条冲突边、新增4条边，其中新增边均涉及agent157；随后进入最长重复段。它是值得定位的实际入口，但并未证明拒绝这一步就会更好：进入前在40对冲突上也已停滞。

反过来，V2成功例第829步SOC不变、冲突仍为1对，只将冲突从(46,254)转移至(46,89)，随后第834步才可行。它说明只看冲突数量会把一次有后续进展的路径变化误记为无效；同样，这只是一条已观察序列，不证明该变化在所有PP顺序下都有益。

### 3. 成功和失败seed不能当作同状态反事实

Dual16两个长尾案例是同一任务的seed61与62，但初始完整fingerprint不同，后续路径也不同。成功seed的动作不能直接作为失败seed的正确答案。

因此不重做“第三次就切换”“一律禁止重复”“禁止等冲突动作”或“先消除一个简单冲突再恢复原策略”等已缺乏支持的方案。

## 后续边界

现阶段应保持Official、V2和Dual16不变，不重训或开始RL。本轮没有形成新的在线阈值，也没有用这六个事后案例作泛化验收。

若继续投入，只考虑一个尚未回答的窄问题：自然恢复时新出现的具体邻域，能否在相同路径状态下由低成本、输入可见的生成机制更早产生，并在新的PP顺序下仍改善困难冲突，而不是只消除无关的小分量。首先复查现有生成来源；不能硬编码成功见证、不断扩大候选池，或直接把成功轨迹动作变成训练标签。没有可实现且未重复历史失败方案的机制，就停止新增求解实验。
