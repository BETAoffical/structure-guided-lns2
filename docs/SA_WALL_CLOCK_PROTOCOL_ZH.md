# 退火四路开发性墙钟试验

## 固定问题与边界

本轮验证已有非计时退火信号能否转化为真实首次可行时间，不训练、不调温度、
不改候选或模型，不运行 Component16 或双轨。旧门槛及结果保持不变。
本轮是使用已查看开发任务的计时筛查，不是独立泛化确认，不自动晋级。

比较 Official Adaptive、Official Adaptive + SA、冻结 Dual16、冻结 Dual16 + SA。
SA 使用完整 PP，T=1000 * 0.99^decision，独立 Python 接受随机流；不重启、不加权 SIPPS。
因此 SA 对原方法的差值是完整 PP 与退火组合效果，不是接受概率的纯因果效应。
已完成的完整 PP 消融保留，不为本轮再追加两臂。

## 数据与预算

固定复用 uniform-runtime-official-probe-v1 中全部16个任务-seed（8张 station_centric
仓库地图、每图一个任务、seed19/23），不按结果筛选或补换。每个episode从原始PP
reset开始，不导入canonical路径、不注入等待。初始路径与原记录必须完全一致。
四方法共64个episode，单worker，四阶Williams顺序按任务轮换，每方法每位置各4次。
统一60秒墙钟预算，无修复次数上限；单次PP使用剩余预算，不沿用诊断的5秒PP限制。
外部180秒仅为启动及审计fuse，不提供额外搜索预算。最长求解预算64分钟，外部极端
上限192分钟；不把该预算当作预计实际运行时间。

## 时间定义与公平性

主TTF为常驻规划器口径：模型加载和环境构造结束后，从reset前到首次可行的native
调用返回，包含PP初始化、候选、特征、推理、正常状态处理、前序轨迹delta编码。
首次可行时间不包含该次成功后的完整路径审计和落盘；所有方法同一边界。
另报setup、reset、PP、选择、校验完成时间及worker总时间。不是路径交付计时，不能
与之前含最终交付或checkpoint导入的实验绝对时间混算。
逐步路径/冲突重建统一在计时循环结束后，使用保存的初始状态和delta完整重建。
结构及静态缓存沿用现有生产实现，需验证候选、分数、选择与冻结FrozenPool一致。

Official不执行proposal、不reseed C RNG、不改变Adaptive权重更新。仅在独立实验API
允许官方action使用已有接受实现。默认step和默认CLI不改变；新native另存，不覆盖旧版。

## 完整性与执行

先核验登记源码、模型、地图/native SHA，16次reset准入，前两个任务四臂三步smoke。
旧/新native普通Official与Dual16三步路径、节点、FP一致；优化缓存候选/分数一致。
两组官方parity必须通过。准入错误停止，不删案例。测试/编译不得与正式计时重叠。
准备、smoke属于非正式测量，不纳入64个结果。

每episode独立进程、完整审计后原子保存；配置/源码变化拒绝resume。
`python scripts/run_sa_wall_clock.py stop` 写安全停止标记，当前episode结束后不再调度。
`resume` 仅移除停止标记并复核已完成记录；不从半条轨迹恢复。
外部超时/异常保存原始错误并停止整组，不自动重试。模型/路径错误不允许回退Official。
源码检查点及恢复ZIP在计时前完成；数据仅在build下。

## 分析

主要量是固定60秒窗口内的受限平均求解时间：已找到解取min(TTF,60)，未找到解取60。
这是时间窗内等待量，不宣称失败真实TTF等于60，也不施加2倍失败惩罚。
同时报告全组成功数、共同成功原始TTF、逐任务/地图差值、搜索量、选择/PP开销。
独立性以地图为组，5000次配对bootstrap，seed20260912。节点/轮数不设性能否决条件。
主要对比Dual16+SA vs Dual16；Official+SA vs Official检验通用收益；两种SA互比检验选择器增量。
这些比较属开发性描述，不按最漂亮一对宣布确认性发现。

- 平均改善且成功数不降低、时间差区间完全小于0：开发性计时信号。
- 平均改善但区间跨0：正点估计、证据不确定。
- 平均改善但成功数减少：速度可靠性取舍，不能静默晋级。
- 平均未改善：本pilot无平均计时收益；仍报告各任务与成功变化。

成功差区间单独报告，不把点估计不降低当作已证明统计非劣。
不要求每个seed/地图都赢，不追求节点、AUC、时间全部改善。任何结果都不自动改默认，
下一次独立确认须在新任务上冻结方案；不围绕此次失败状态追加温度或救援链。
